Given an integer array nums of length n and an integer target, choose three different elements of nums so that their sum is closest to target. Return that sum.

You may assume that every input has exactly one best answer.

2 💡 Examples and Constraints

Example 1

Input: nums = [-1,2,1,-4], target = 1
Output: 2
Explanation: The sum closest to 1 is 2, from (-1) + 2 + 1. Its distance to the target is only 1.

Example 2

Input: nums = [0,0,0], target = 1
Output: 0
Explanation: There is only one possible triple, 0 + 0 + 0 = 0.

📖 Example breakdown (Example 1), step by step
  • The numbers are [-1,2,1,-4] and the target is 1. There are only four possible triples.
  • (-1, 2, 1) = 2, distance |2 - 1| = 1. (-1, 2, -4) = -3, distance 4. (-1, 1, -4) = -4, distance 5. (2, 1, -4) = -1, distance 2.
  • The smallest distance is 1, from the sum 2. That sum is the answer.
  • Result: 2 ✅ (the expected output of Example 1)

⚠️ Constraints

  • 3 <= nums.length <= 500
  • -1000 <= nums[i] <= 1000
  • -104 <= target <= 104

3 🧠 How to Think About It (in Easy Words)

This is 3Sum with a twist: instead of asking for a sum of exactly zero, we keep the sum that is nearest to the target. The sorted two-finger walk of 3Sum still works: if the current sum is below the target, only moving the left finger right can raise it; if it is above, only moving the right finger left can lower it. Along the way we remember the best sum seen so far, and if we hit the target exactly we can stop at once.

Below you will find 2 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 🚀 Approach 1: Brute Force: Try Every Triple

Brute force

💡 Intuition

Try every triple of positions, compute the sum, and remember the sum whose distance |sum - target| is smallest.

Weigh every possible trio of apples and keep the trio whose weight is nearest to a kilo.

🪜 Algorithm, Step by Step

  1. Start with best = the sum of the first three numbers.
  2. Try every triple of positions and compute its sum.
  3. If |sum - target| is smaller than |best - target|, the new sum becomes best.
  4. Return best.

⏱️ Complexity

CostWhy
TimeO(n3)three nested loops look at about n3 / 6 triples (20,708,500 for n = 500)
SpaceO(1)only a few number variables
Good sideWeak side
Simple and obviously right.For n = 500 that is about 20 million triples: slow but possible; for larger n it is hopeless.

💻 Code

class Solution {
public:
    int threeSumClosest(vector<int>& nums, int target) {
        int n = nums.size();
        int best = nums[0] + nums[1] + nums[2];                // start with any valid sum
        for (int i = 0; i < n; i++)
            for (int j = i + 1; j < n; j++)
                for (int k = j + 1; k < n; k++) {
                    int sum = nums[i] + nums[j] + nums[k];
                    if (abs(sum - target) < abs(best - target)) best = sum;   // nearer to the target than the best so far
                }
        return best;
    }
};

5 🚀 Approach 2: Sort, Then Two Pointers (Most Optimized)

Most optimized

💡 Intuition

Sort the array. For each first number nums[i], put left just after it and right at the end. Compute the sum; if it is nearer to the target than the best so far, remember it. A sum below the target moves left right, a sum above the target moves right left, and an exact hit returns immediately.

Like 3Sum, but instead of looking for an exact match you keep a note of the nearest miss.

🪜 Algorithm, Step by Step

  1. Sort the array and set best to the sum of the first three numbers.
  2. For each position i put left = i + 1 and right = n - 1.
  3. Compute the sum, update best if it is nearer to the target.
  4. If the sum is below the target move left, if above move right, if equal return it at once.

⏱️ Complexity

CostWhy
TimeO(n2)sorting O(n log n), then n times a pointer walk of O(n) steps
SpaceO(1) extraa few variables (the sort may use O(log n) extra)
Good sideWeak side
Fast, with the same pointer logic as 3Sum.You must update the best sum before moving a pointer, or you may lose the nearest one.

💻 Code

class Solution {
public:
    int threeSumClosest(vector<int>& nums, int target) {
        sort(nums.begin(), nums.end());
        int n = nums.size();
        int best = nums[0] + nums[1] + nums[2];
        for (int i = 0; i + 2 < n; i++) {
            int left = i + 1, right = n - 1;
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                if (abs(sum - target) < abs(best - target)) best = sum;   // remember the nearest sum
                if (sum < target) left++;                      // too small: raise it
                else if (sum > target) right--;                // too big: lower it
                else return sum;                               // exact hit: nothing can be closer
            }
        }
        return best;
    }
};

class Solution:
    def threeSumClosest(self, nums: List[int], target: int) -> int:
        nums.sort()
        n = len(nums)
        best = nums[0] + nums[1] + nums[2]
        for i in range(n - 2):
            left, right = i + 1, n - 1
            while left < right:
                total = nums[i] + nums[left] + nums[right]
                if abs(total - target) < abs(best - target):    # remember the nearest sum
                    best = total
                if total < target:
                    left += 1                           # too small: raise it
                elif total > target:
                    right -= 1                          # too big: lower it
                else:
                    return total                        # exact hit: nothing can be closer
        return best

7 🔑 Key Insights

  • It is 3Sum with a different question: keep the sum nearest to the target instead of the sums equal to it.
  • Moving left right can only raise the sum and moving right left can only lower it, which is why the pointer walk never misses a better sum.
  • An exact hit can stop the whole search at once (nothing is closer than distance 0).
  • Initialize best with a real sum, not with 0 or a magic number, because 0 may be farther from the target than any real sum.

9 ⚠️ Common Mistakes

  • Starting with best = 0 or a huge number: 0 may be farther from the target than any real sum, so start with a real sum such as the first three numbers.
  • Comparing sums to the target without taking the absolute value of the difference.
  • Moving a pointer before updating the best sum, so the nearest sum is lost.
  • Using the same element twice: left must stay to the right of i and always smaller than right.
  • Trying to skip duplicates in a way that skips a needed number: for this problem duplicates are harmless, so you can leave the skipping out.

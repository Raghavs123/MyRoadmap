You are given a signed 32-bit integer x. Return x with its digits reversed. The minus sign (if any) stays in front.

If reversing the digits makes the value go outside the signed 32-bit range [-231, 231 - 1], return 0 instead.

Assume the environment does not let you store 64-bit integers (signed or unsigned).

2 💡 Examples and Constraints

Example 1

Input: x = 123
Output: 321
Explanation: The digits 1, 2, 3 become 3, 2, 1.

Example 2

Input: x = -123
Output: -321
Explanation: The sign stays in front: -123 becomes -321.

Example 3

Input: x = 120
Output: 21
Explanation: The reversed digits are 021, which is just 21 (leading zeros disappear).

📖 Example breakdown (Example 2), step by step
  • Remember the sign: the number is negative.
  • Work with 123: pop 3 (result 3), pop 2 (result 32), pop 1 (result 321).
  • Put the sign back: −321.
  • −321 is inside the 32-bit range [−2147483648, 2147483647], so it is returned.
  • (If the reversed number did not fit, for example 1534236469 → 9646324351, the answer would be 0.)
  • Result: -321 ✅ (the expected output of Example 2)

⚠️ Constraints

  • -231 <= x <= 231 - 1

3 🧠 How to Think About It (in Easy Words)

Think of a train of digit carriages. You unhook the last carriage of the old train (that is the digit x % 10) and hook it to the back of a new train (result * 10 + digit). After the old train is empty, the new train is the reversed number. The only danger is that the new train may get too long for the station (more than the biggest 32-bit number), so we must check before we hook the next carriage.

Below you will find 3 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 🚀 Approach 1: Brute Force: Turn It into Text and Flip It

Brute force

💡 Intuition

Write the number as text, remember the sign, reverse the digit text, turn it back into a number and check whether it fits in 32 bits.

Like writing the number on a strip of paper, turning the strip around, and reading it again.

🪜 Algorithm, Step by Step

  1. Note whether x is negative.
  2. Reverse the digit text of |x| and turn it back into a number (leading zeros disappear).
  3. Put the sign back.
  4. If the value is outside [−231, 231 − 1], return 0; otherwise return it.

⏱️ Complexity

CostWhy
TimeO(d), d = number of digits (at most 10)x has at most 10 digits and each step touches each digit once: O(d).
SpaceO(d)The digit text of length d.
Good sideWeak side
Easy to write and to understand.Uses text and a wider (64-bit) number for the final range check, which the problem says we may not rely on.

💻 Code

class Solution {
public:
    int reverse(int x) {
        bool negative = x < 0;
        string digits = to_string(x);                          // for example "-123" or "123"
        if (negative) digits.erase(digits.begin());            // drop the minus sign: "123"
        std::reverse(digits.begin(), digits.end());            // flip the text: "321"
        long long value = stoll(digits);                       // at most 10 digits, so it fits in 64 bits
        if (negative) value = -value;
        if (value < INT_MIN || value > INT_MAX) return 0;      // does not fit in 32 bits
        return (int)value;
    }
};
class Solution {
    public int reverse(int x) {
        boolean negative = x < 0;
        String digits = Long.toString(Math.abs((long) x));     // for example "123" (long, because abs(Integer.MIN_VALUE) does not fit in int)
        String flipped = new StringBuilder(digits).reverse().toString();   // "321"
        long value = Long.parseLong(flipped);                  // at most 10 digits, so it fits in 64 bits
        if (negative) value = -value;
        if (value < Integer.MIN_VALUE || value > Integer.MAX_VALUE) return 0;   // does not fit in 32 bits
        return (int) value;
    }
}
class Solution:
    def reverse(self, x: int) -> int:
        negative = x < 0
        flipped = int(str(abs(x))[::-1])                # "123" -> "321" -> 321
        value = -flipped if negative else flipped

            return 0

5 🚀 Approach 2: Pop and Push Digits with a 64-bit Result

Optimized

💡 Intuition

Repeat: pop the last digit with x % 10, cut it off with x / 10, and push it onto the result with result * 10 + digit. A reversed 10-digit number is below 1010, which fits easily in a 64-bit box, so we simply check the range at the end.

Moving carriages one by one from the back of the old train to the back of the new train, and measuring the new train only at the end.

🪜 Algorithm, Step by Step

  1. Remember the sign and work with |x|.
  2. While x ≠ 0: digit = x % 10, x = x / 10, result = result × 10 + digit (a 64-bit variable).
  3. Apply the sign; return 0 if the result is outside the 32-bit range, otherwise the result.

⏱️ Complexity

CostWhy
TimeO(d)One loop round per digit: O(d).
SpaceO(1)A few number variables.
Good sideWeak side
No text, no extra memory, very short.Needs a 64-bit variable, which the original statement says to avoid (in Python this is not a concern: its integers never overflow).

💻 Code

class Solution {
public:
    int reverse(int x) {
        long long result = 0;                                  // a 64-bit box: a reversed 10-digit number always fits
        while (x != 0) {
            int digit = x % 10;                                // pop the last digit (it is negative when x is negative)
            x /= 10;                                           // cut it off
            result = result * 10 + digit;                      // push it onto the result
        }
        if (result < INT_MIN || result > INT_MAX) return 0;    // check the 32-bit range once, at the end
        return (int)result;
    }
};

class Solution:
    def reverse(self, x: int) -> int:
        sign = -1 if x < 0 else 1
        x = abs(x)                                      # work with a positive number (Python's % and // act differently for negatives)
        result = 0
        while x != 0:
            digit = x % 10                              # pop the last digit
            x //= 10                                    # cut it off
            result = result * 10 + digit                # push it onto the result (Python never overflows)
        result *= sign
        if result < -2**31 or result > 2**31 - 1:       # check the 32-bit range once, at the end
            return 0
        return result

6 🚀 Approach 3: Pop and Push with an Overflow Check Before Each Push (Most Optimized)

Most optimized

💡 Intuition

Do the same pop and push, but use only a 32-bit result. Before pushing a digit, ask: would result * 10 + digit go above 2147483647 or below -2147483648? That happens when result is already bigger than 214748364, or equal to it with a last digit above 7 (for negatives: below -214748364, or equal with a digit below -8). If so, stop and return 0.

Before hooking a carriage you measure whether the station platform still has room for it, instead of building the train and finding out afterwards.

🪜 Algorithm, Step by Step

  1. Start with a 32-bit result = 0.
  2. While x ≠ 0: pop the last digit (it is negative when x is negative, as in C++ and Java).
  3. Before pushing: if result > 214748364, or it equals 214748364 and digit > 7, return 0; if result < −214748364, or it equals −214748364 and digit < −8, return 0.
  4. Push: result = result × 10 + digit.
  5. Return result.

⏱️ Complexity

CostWhy
TimeO(d)One loop round per digit: O(d).
SpaceO(1)A few number variables, and no 64-bit helper.
Good sideWeak side
Follows the rule of the problem exactly: never needs more than 32 bits.The two limit checks are easy to get wrong (the 7 and the -8 come from the last digits of 2147483647 and -2147483648).

💻 Code

class Solution {
public:
    int reverse(int x) {
        int result = 0;                                        // only 32-bit numbers are used here
        while (x != 0) {
            int digit = x % 10;                                // pop the last digit
            x /= 10;
            // would result * 10 + digit be above INT_MAX = 2147483647 ?
            if (result > INT_MAX / 10 || (result == INT_MAX / 10 && digit > 7)) return 0;
            // ... or below INT_MIN = -2147483648 ?
            if (result < INT_MIN / 10 || (result == INT_MIN / 10 && digit < -8)) return 0;
            result = result * 10 + digit;                      // now it is safe to push the digit
        }
        return result;
    }
};

    public int reverse(int x) {
        int result = 0;                                        // only 32-bit numbers are used here
        while (x != 0) {
            int digit = x % 10;                                // pop the last digit
            x /= 10;

            if (result > Integer.MAX_VALUE / 10 || (result == Integer.MAX_VALUE / 10 && digit > 7)) return 0;
            // ... or below Integer.MIN_VALUE = -2147483648 ?
            if (result < Integer.MIN_VALUE / 10 || (result == Integer.MIN_VALUE / 10 && digit < -8)) return 0;

        }
        return result;
    }
}
class Solution:
    def reverse(self, x: int) -> int:
        # Python never overflows, so we imitate a 32-bit machine by hand.
        MAX_TENTH, MAX_LAST = 214748364, 7              # 2147483647 = 214748364 * 10 + 7
        MIN_TENTH, MIN_LAST = -214748364, -8            # -2147483648 = -214748364 * 10 - 8
        negative = x < 0
        x = abs(x)
        result = 0
        while x != 0:
            digit = x % 10                              # pop the last digit
            x //= 10
            if negative:
                digit = -digit                          # a negative number pops negative digits (like C++ and Java)
            if result > MAX_TENTH or (result == MAX_TENTH and digit > MAX_LAST):
                return 0                                # the next push would go above 2147483647
            if result < MIN_TENTH or (result == MIN_TENTH and digit < MIN_LAST):
                return 0                                # the next push would go below -2147483648
            result = result * 10 + digit                # now it is safe to push the digit
        return result

8 🔑 Key Insights

  • Pop with % 10, push with × 10 + digit: the core move of many digit problems (also used in Palindrome Number).
  • Check for overflow before the multiplication: afterwards the value has already broken a 32-bit variable.
  • 2147483647 = 214748364 × 10 + 7 and −2147483648 = −214748364 × 10 − 8: that is where the 7 and the −8 in the checks come from.
  • In C++ and Java % keeps the sign of x (−123 % 10 = −3); Python's % does not, so the Python code works with |x|.

10 ⚠️ Common Mistakes

  • Checking for overflow after the multiplication in a language where integers wrap around (C++ signed overflow is undefined behaviour; Java silently wraps).
  • Forgetting the negative side: -2147483648 has a bigger size than 2147483647, so its limit digit is 8, not 7.
  • Calling abs(x) on -2147483648 in a 32-bit int: the result does not fit (use a wider type or avoid abs).
  • Expecting % and / to behave the same for negative numbers in every language: C++ and Java truncate toward zero, Python rounds down.
  • Returning the reversed value with its sign lost, or forgetting that trailing zeros (120) simply vanish.

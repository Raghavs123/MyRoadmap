Given an integer array nums, return all triplets [nums[i], nums[j], nums[k]] such that i, j and k are three different positions and nums[i] + nums[j] + nums[k] == 0.

The answer must not contain the same triplet twice (two triplets are the same if they have the same numbers, whatever the order). You may return the triplets in any order.

2 💡 Examples and Constraints

Example 1

Input: nums = [-1,0,1,2,-1,-4]
Output: [[-1,-1,2],[-1,0,1]]
Explanation: Two different triplets add up to 0: (-1) + 0 + 1 and (-1) + (-1) + 2. Although there are two -1 values, the triplet [-1,0,1] is listed only once.

Example 2

Input: nums = [0,1,1]
Output: []
Explanation: The only possible triplet is 0 + 1 + 1 = 2, which is not 0.

Example 3

Input: nums = [0,0,0]
Output: [[0,0,0]]
Explanation: 0 + 0 + 0 = 0.

📖 Example breakdown (Example 1), step by step
  • Sort the numbers: [-4,-1,-1,0,1,2].
  • First number -4: the rest would have to add up to 4, but the biggest pair is 1 + 2 = 3. No triple.
  • First number -1 (the first copy): left finger on -1, right finger on 2: -1 + -1 + 2 = 0. Save [-1,-1,2]. Move both fingers. Now 0 and 1: -1 + 0 + 1 = 0. Save [-1,0,1].
  • First number -1 again (the second copy): it equals the previous first number, so skip it; otherwise we would find the same triples again.
  • First number 0: only 1 and 2 are left to its right and 0 + 1 + 2 = 3, not 0, so there are no more triples. The answer is the two saved triples.
  • Result: [[-1,-1,2],[-1,0,1]] ✅ (the expected output of Example 1)

⚠️ Constraints

  • 3 <= nums.length <= 3000
  • -105 <= nums[i] <= 105

3 🧠 How to Think About It (in Easy Words)

The hard part is not finding triples that add to zero but not repeating them. Sorting the numbers solves both problems. Fix the smallest number a of the triple; then you only need two other numbers that add up to -a, and in a sorted list you can find such a pair by walking two fingers inwards (too small: move the left finger right, too big: move the right finger left). Equal neighbours are skipped so the same triple is never produced twice.

Below you will find 3 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 🚀 Approach 1: Brute Force: Three Loops and a Set to Remove Repeats

Brute force

💡 Intuition

Sort the array, try every triple of positions i < j < k, and put every triple that sums to 0 into a set. Because the array is sorted, equal triples look exactly the same and the set throws the repeats away.

Try every possible trio of friends and write the lucky ones in a notebook that refuses duplicate lines.

🪜 Algorithm, Step by Step

  1. Sort the array (so equal triples look identical).
  2. Try every triple of positions i < j < k.
  3. If the three numbers add up to 0, insert the triple into a set.
  4. Return the contents of the set.

⏱️ Complexity

CostWhy
TimeO(n3)three nested loops look at about n3 / 6 triples (4,495,501,000 for n = 3000)
SpaceO(number of answers)the set holds the answers
Good sideWeak side
Obviously correct.For n = 3000 that is about 4.5 billion triples: much too slow.

💻 Code

class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());                        // sorted triples make equal triples look identical
        int n = nums.size();
        set<vector<int>> found;                                // a set keeps every triple only once
        for (int i = 0; i < n; i++)
            for (int j = i + 1; j < n; j++)
                for (int k = j + 1; k < n; k++)
                    if (nums[i] + nums[j] + nums[k] == 0)
                        found.insert({nums[i], nums[j], nums[k]});
        return vector<vector<int>>(found.begin(), found.end());
    }
};

5 🚀 Approach 2: Sort, Then Two Pointers (Most Optimized)

Most optimized

💡 Intuition

Sort the array. For each position i (skipping a value equal to the previous one) look for two numbers to the right of it that add up to -nums[i] with two pointers left and right. When the sum is too small move left; when it is too big move right; when it is 0 save the triple and move both pointers past all equal values.

Pick the smallest friend of the trio, then let two other friends walk towards each other from the ends of the sorted line until their total is just right.

🪜 Algorithm, Step by Step

  1. Sort the array.
  2. For each position i (stop when nums[i] > 0, skip a value equal to the previous one) put left = i + 1 and right = n - 1.
  3. While left < right: if the sum is below 0 move left, if above 0 move right.
  4. On a hit save the triple, move both pointers, and skip over equal numbers on both sides.

⏱️ Complexity

CostWhy
TimeO(n2)sorting costs O(n log n) and the two-pointer walk for each of the n first numbers costs O(n)
SpaceO(1) extra (O(log n) for the sort)the output list aside, only a few variables (the sort may use O(log n) extra)
Good sideWeak side
No set and no repeats by construction; only about n * n / 2 steps.The three 'skip duplicates' rules are easy to get wrong.

💻 Code

class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int n = nums.size();
        vector<vector<int>> out;
        for (int i = 0; i + 2 < n; i++) {
            if (nums[i] > 0) break;                            // the smallest number is positive: no more zero sums
            if (i > 0 && nums[i] == nums[i - 1]) continue;     // same first number as before: would repeat triples
            int left = i + 1, right = n - 1;
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                if (sum < 0) left++;                           // too small: need a bigger number
                else if (sum > 0) right--;                     // too big: need a smaller number
                else {
                    out.push_back({nums[i], nums[left], nums[right]});
                    left++; right--;
                    while (left < right && nums[left] == nums[left - 1]) left++;      // skip equal numbers
                    while (left < right && nums[right] == nums[right + 1]) right--;
                }
            }
        }
        return out;
    }
};

                else:

                    right -= 1
                    while left < right and nums[left] == nums[left - 1]:      # skip equal numbers
                        left += 1
                    while left < right and nums[right] == nums[right + 1]:
                        right -= 1
        return out

6 🚀 Approach 3: Sort, Then a Hash Set Instead of Two Pointers

Optimized (alternative)

💡 Intuition

Sort the array. For each first number nums[i] walk j to the right and keep a set of the numbers already passed. The number that completes the sum is need = -nums[i] - nums[j]; if it is in the set, you found a triple. After a hit, skip equal numbers at j so the triple is not repeated.

Instead of two walkers meeting in the middle, keep a list of everyone you have already met and ask: is the friend I need on that list?

🪜 Algorithm, Step by Step

  1. Sort the array.
  2. For each i (skip repeated first numbers) start with an empty set seen.
  3. For each j to the right compute need = -nums[i] - nums[j]; if need is in seen save [nums[i], need, nums[j]] and skip equal numbers at j.
  4. Add nums[j] to seen and continue.

⏱️ Complexity

CostWhy
TimeO(n2)sorting plus, for each first number, one pass with O(1) set operations
SpaceO(n)the set can hold up to n numbers
Good sideWeak side
A good alternative that shows the 'Two Sum with a hash set' idea inside 3Sum.Uses extra memory for the set, and is usually a little slower than two pointers.

💻 Code

class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int n = nums.size();
        vector<vector<int>> out;
        for (int i = 0; i + 2 < n && nums[i] <= 0; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;     // same first number as before: would repeat triples
            unordered_set<int> seen;                           // numbers already passed to the right of i
            for (int j = i + 1; j < n; j++) {
                int need = -nums[i] - nums[j];
                if (seen.count(need)) {
                    out.push_back({nums[i], need, nums[j]});   // need <= nums[j] because the array is sorted
                    while (j + 1 < n && nums[j] == nums[j + 1]) j++;   // skip equal numbers
                }
                seen.insert(nums[j]);
            }
        }
        return out;
    }
};

8 🔑 Key Insights

  • Sorting does two jobs: it lets two pointers walk inwards, and it puts equal numbers next to each other so they are easy to skip.
  • For nums = [-1,0,1,2,-1,-4] the brute force finds 3 position triples that add up to 0 but only 2 different triplets, because the number -1 appears twice: this is why de-duplication matters.
  • For n = 3000 the brute force needs 4,495,501,000 triple checks (about 4.5 billion); the two-pointer method needs about n2 / 2 = 4.5 million steps.
  • Skipping duplicates must happen after using a value once, never before, or the triple [-1,-1,2] would be lost.
  • 3Sum is the same as 2Sum with one more loop around it, and 4Sum adds yet another loop.

10 ⚠️ Common Mistakes

  • Returning the same triple more than once because equal numbers were not skipped (the classic wrong answer on [-1,-1,0,1,1] or [0,0,0,0]).
  • Skipping duplicates before using them: the first copy must be used, only the following equal numbers are skipped (so [-1,-1,2] is still found).
  • Using the same position twice: i, left and right must be three different positions.
  • Forgetting to move both pointers after finding a triple.
  • Stopping the loop for i too early or not at all: once nums[i] > 0 no triple can sum to 0 (this stop is only an optimization).

Easy   Topics: Array, Hash Table

You are given a list of whole numbers nums and one whole number target. Find two different positions i and j in the list such that nums[i] + nums[j] == target, and return those two positions (the indices, counting from 0).

  • You may assume that every input has exactly one valid answer.
  • You may not use the same element twice (positions i and j must be different).
  • You may return the two indices in any order.

2 💡 Examples and Constraints

Example 1

Input: nums = [2,7,11,15], target = 9
Output: [0,1]
Explanation: nums[0] + nums[1] = 2 + 7 = 9, so the answer is [0, 1].

Example 2

Input: nums = [3,2,4], target = 6
Output: [1,2]
Explanation: nums[1] + nums[2] = 2 + 4 = 6.

Example 3

Input: nums = [3,3], target = 6
Output: [0,1]
Explanation: The same value may appear twice, but at two different positions.

📖 Example breakdown (Example 1), step by step
  • Goal: find two different positions whose numbers add up to 9.
  • Position 0 holds 2, so its partner must be 9 - 2 = 7.
  • 7 sits at position 1, which is a different position.
  • Check: 2 + 7 = 9. Found it.
  • Result: [0,1] ✅ (the expected output of Example 1)

⚠️ Constraints

  • 2 <= nums.length <= 104
  • -109 <= nums[i] <= 109
  • -109 <= target <= 109
  • Only one valid answer exists.
Follow-up: Can you come up with an algorithm that is faster than O(n²)?

3 🧠 How to Think About It (in Easy Words)

Imagine a shelf of price tags and you must pick two that cost exactly your target amount. The slow way is to try every pair. The fast way is to remember what you have already seen, so for each new tag you only have to ask: 'did I already see the tag that completes this one?'

Below you will find 4 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 🚀 Approach 1: Brute Force: Try Every Pair

Brute force

💡 Intuition

Take the first number, then check it with every number after it. Then take the second number and do the same, and so on. The first pair that adds up to the target is the answer.

Like asking every pair of children in a class 'do your ages add up to 20?' until you find the pair.

🪜 Algorithm, Step by Step

  1. Pick the first number at position i (from the start to the end).
  2. Pick a second number at every later position j (j > i).
  3. If nums[i] + nums[j] == target, return [i, j].
  4. The problem promises exactly one answer, so the loops always find it.

⏱️ Complexity

CostWhy
TimeO(n²)Up to n·(n − 1)/2 pairs are checked, which grows like n².
SpaceO(1)Only the two loop counters are stored.
Good sideWeak side
Very easy to write and to trust.For 10,000 numbers this checks about 50 million pairs; it is the slowest option.

💻 Code

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        int n = nums.size();
        for (int i = 0; i < n; i++) {               // choose the first number
            for (int j = i + 1; j < n; j++) {       // choose a second number that comes AFTER it
                if (nums[i] + nums[j] == target) {  // do they add up to the target?
                    return {i, j};                  // yes: report their positions
                }
            }
        }
        return {};                                  // never happens: an answer always exists
    }
};

5 🚀 Approach 2: Sort and Use Two Pointers

Optimized (sorting)

💡 Intuition

If the numbers are in order, we can stand one finger on the smallest and one on the biggest. If their sum is too big, move the right finger left (a smaller number). If it is too small, move the left finger right (a bigger number). Because sorting loses the original positions, we sort pairs of (value, original index).

Two people walking towards each other along a number line, adjusting until their numbers meet the target.

🪜 Algorithm, Step by Step

  1. Make pairs (value, original index) for every number.
  2. Sort the pairs by value (the original index travels with its value).
  3. Put one finger left on the first pair and one finger right on the last pair.
  4. While left < right: add the two values. Equal to target: return both original indexes. Too small: move left one step right. Too big: move right one step left.

⏱️ Complexity

CostWhy
TimeO(n log n)Sorting the n pairs costs O(n log n); the two-finger walk adds only O(n).
SpaceO(n)The list of n (value, index) pairs.
Good sideWeak side
No hash map needed; shows the two-pointer trick used in many problems.Sorting costs O(n log n) and we must remember the old indices.

💻 Code

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        int n = nums.size();
        vector<pair<int, int>> a;                   // pairs of (value, original index)
        for (int i = 0; i < n; i++) a.push_back({nums[i], i});
        sort(a.begin(), a.end());                   // sort by value; the index travels with it
        int left = 0, right = n - 1;                // one finger at each end
        while (left < right) {
            int sum = a[left].first + a[right].first;
            if (sum == target) {
                return {a[left].second, a[right].second};
            } else if (sum < target) {
                left++;                             // too small: we need a bigger number
            } else {
                right--;                            // too big: we need a smaller number
            }
        }
        return {};
    }
};

6 🚀 Approach 3: Two-Pass Hash Map

Optimized (hashing)

💡 Intuition

A hash map answers 'have I seen this number, and where?' almost instantly. Pass 1: write every number and its position into the map. Pass 2: for each number, look up target - number; if it is in the map (and is not the same position), we are done.

Write every price tag in a notebook with its shelf number first; then for each tag, look in the notebook for the tag that completes it.

🪜 Algorithm, Step by Step

  1. Pass 1: write every value and its index into a hash map (a later copy of the same value overwrites the earlier one).
  2. Pass 2: for each index i, compute need = target - nums[i].
  3. If need is in the map and its stored index is not i, return [i, map[need]].

⏱️ Complexity

CostWhy
TimeO(n)Two passes over n numbers; each hash-map insert or lookup takes O(1) on average.
SpaceO(n)The map can hold up to n entries.
Good sideWeak side
Linear time; very clear in two simple steps.Uses extra memory and walks the list twice.

💻 Code

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> position;           // value -> index
        for (int i = 0; i < (int)nums.size(); i++) {
            position[nums[i]] = i;                  // pass 1: remember where each number is
        }
        for (int i = 0; i < (int)nums.size(); i++) {
            int need = target - nums[i];            // pass 2: which number completes nums[i]?
            auto it = position.find(need);
            if (it != position.end() && it->second != i) {   // found, and not the same element
                return {i, it->second};
            }
        }
        return {};
    }
};
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> position = new HashMap<>();   // value -> index
        for (int i = 0; i < nums.length; i++) {
            position.put(nums[i], i);                       // pass 1: remember where each number is

            int need = target - nums[i];                    // pass 2: which number completes nums[i]?
            Integer j = position.get(need);

                return new int[]{i, j};

7 🚀 Approach 4: One-Pass Hash Map (Most Optimized)

Most optimized

💡 Intuition

Do both jobs in a single walk. For each number, first ask the map 'is target - number already here?'. If yes, the answer is that older position and the current one. If not, write the current number into the map and move on. A number can never match itself, because it is only added after we have looked.

Walking along the shelf with a notebook: at each tag you check the notebook for its partner, then add the tag to the notebook.

🪜 Algorithm, Step by Step

  1. Start with an empty hash map seen (value → index).
  2. For each index i, compute need = target - nums[i].
  3. If need is already in seen, return [seen[need], i].
  4. Otherwise store seen[nums[i]] = i and move on.

⏱️ Complexity

CostWhy
TimeO(n)One pass; each step does one average-O(1) lookup and at most one insert.
SpaceO(n)In the worst case almost every number is stored before the pair is found.
Good sideWeak side
Fastest in practice, only one loop, handles equal values like [3, 3] naturally.Needs a hash map (extra memory).

💻 Code

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> seen;               // value -> index, for numbers we already visited
        for (int i = 0; i < (int)nums.size(); i++) {
            int need = target - nums[i];            // the partner this number is looking for
            auto it = seen.find(need);
            if (it != seen.end()) {                 // the partner was seen earlier
                return {it->second, i};
            }
            seen[nums[i]] = i;                      // otherwise remember this number
        }
        return {};
    }
};
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();       // value -> index, for numbers we already visited
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];                    // the partner this number is looking for
            if (seen.containsKey(need)) {                   // the partner was seen earlier
                return new int[]{seen.get(need), i};
            }
            seen.put(nums[i], i);                           // otherwise remember this number
        }
        return new int[0];
    }
}

9 🔑 Key Insights

  • Turn 'which pair?' into 'have I already seen the partner?': the partner of x is target - x.
  • A hash map trades memory for speed: O(n) extra space buys O(n) time instead of O(n²).
  • Looking up the partner before inserting the current number (one pass) automatically stops a number from pairing with itself.
  • Sorting destroys positions, so when indexes are the answer, carry each value's original index with it.

11 ⚠️ Common Mistakes

  • Using the same element twice: nums[i] + nums[i]. Always make sure the two positions are different (in the one-pass version this is automatic).
  • Returning the values instead of the indices.
  • After sorting, returning the sorted positions instead of the original ones (store the original index with each value).
  • In the two-pass hash map, forgetting the != i check: for nums = [3,2,4], target = 6 the number 3 would pair with itself and return [0,0].

Easy   Topics: Math

Given an integer x, return true if x is a palindrome (it reads the same from left to right and from right to left), and false otherwise.

2 Examples and Constraints

Example 1

Input: x = 121
Output: true
Explanation: 121 reads 121 from left to right and 121 from right to left.

Example 2

Input: x = -121
Output: false
Explanation: From left to right it reads -121. From right to left it reads 121-. So it is not a palindrome.

Example 3

Input: x = 10
Output: false
Explanation: From right to left it reads 01, which is not the same as 10.

Constraints

  • -231 <= x <= 231 - 1
Follow-up: Could you solve it without converting the integer to a string?

3 How to Think About It (in Easy Words)

Hold a number up to a mirror. A palindrome looks the same in the mirror. You can check it in two ways: write it on paper and read it backwards (text), or build the mirror image digit by digit with % 10 and / 10 (maths). The cleverest way builds the mirror image of only the second half: if the two halves match, the whole number is a palindrome, and you never risk building a number that is too big.

Below you will find 3 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 Approach 1: Brute Force: Compare the Text with Its Reverse

Brute force

Idea: Turn the number into text, make a reversed copy of the text, and compare. A negative number starts with '-', so its reversed text ends with '-' and never matches.

Write the number on a strip of paper, flip the strip over, and see if it still reads the same.
TimeSpaceGood sideWeak side
O(d), d = number of digitsO(d)One line of real logic, almost impossible to get wrong.Uses extra memory for the text, and the follow-up asks to avoid strings.

Code

class Solution {
public:
    bool isPalindrome(int x) {
        string text = to_string(x);                            // for example "121" (a negative number starts with '-')
        string backwards(text.rbegin(), text.rend());          // the same text read from the end
        return text == backwards;
    }
};
class Solution {
    public boolean isPalindrome(int x) {
        String text = Integer.toString(x);                     // for example "121" (a negative number starts with '-')
        String backwards = new StringBuilder(text).reverse().toString();   // the same text read from the end
        return text.equals(backwards);
    }
}
class Solution:
    def isPalindrome(self, x: int) -> bool:
        text = str(x)                                   # for example "121" (a negative number starts with '-')
        return text == text[::-1]                       # compare with the same text read from the end

5 Approach 2: Reverse the Whole Number with Maths

Optimized (no strings)

Idea: A negative number can never be a palindrome. For the others, build the reversed number digit by digit (reversed = reversed * 10 + x % 10, then x = x / 10) and compare it with the original.

Peel the digits off the end of the number one at a time and stack them into a new number.
TimeSpaceGood sideWeak side
O(d)O(1)No strings, so it answers the follow-up question.The reversed number can be too big for a 32-bit int (for example 2147483647 reversed is 7463847412), so a 64-bit variable is needed in C++ and Java.

Code

class Solution {
public:
    bool isPalindrome(int x) {
        if (x < 0) return false;                               // a minus sign can never match at the other end
        long long original = x, reversed = 0;                  // 64-bit: the reversed number may not fit in 32 bits
        while (x > 0) {
            reversed = reversed * 10 + x % 10;                 // push the last digit of x onto 'reversed'
            x /= 10;                                           // cut the last digit off x
        }
        return reversed == original;
    }
};

class Solution:
    def isPalindrome(self, x: int) -> bool:
        if x < 0:
            return False                                # a minus sign can never match at the other end
        original, reversed_number = x, 0
        while x > 0:
            reversed_number = reversed_number * 10 + x % 10     # push the last digit of x onto the new number
            x //= 10                                    # cut the last digit off x
        return reversed_number == original

6 Approach 3: Reverse Only Half of the Number (Most Optimized)

Most optimized

Idea: Move digits from the end of x onto a new number, but stop as soon as the new number is as big as what is left of x: that is the middle. Now compare the two halves. For an odd number of digits, drop the middle digit of the reversed half with / 10. Numbers ending in 0 (except 0 itself) can never be palindromes, because a number cannot start with 0.

Two friends walk towards each other from both ends of a corridor. When they meet in the middle they only have to compare what each of them saw.
TimeSpaceGood sideWeak side
O(d), half as many stepsO(1)The reversed half is always small, so a 32-bit int is enough and overflow can never happen.The stopping rule and the odd-length case need careful thinking.

Code

class Solution {
public:
    bool isPalindrome(int x) {
        if (x < 0 || (x % 10 == 0 && x != 0)) return false;    // negative, or ends with 0 (but is not 0): never a palindrome
        int reversedHalf = 0;
        while (x > reversedHalf) {                             // stop when we reach the middle
            reversedHalf = reversedHalf * 10 + x % 10;         // move the last digit of x to the reversed half
            x /= 10;
        }
        // even number of digits: x == reversedHalf; odd: the middle digit sits at the end of reversedHalf, so drop it
        return x == reversedHalf || x == reversedHalf / 10;
    }
};

class Solution:
    def isPalindrome(self, x: int) -> bool:
        if x < 0 or (x % 10 == 0 and x != 0):

        while x > reversed_half:                        # stop when we reach the middle
            reversed_half = reversed_half * 10 + x % 10     # move the last digit of x to the reversed half
            x //= 10
        # even number of digits: x == reversed_half; odd: the middle digit sits at the end of reversed_half, so drop it
        return x == reversed_half or x == reversed_half // 10

9 Common Mistakes

  • Treating negative numbers as palindromes because their digits look symmetric: the minus sign breaks it.
  • Reversing the whole number in a 32-bit int: a palindrome-looking input like 2147483647 reverses to a number that overflows.
  • Forgetting the trailing-zero rule in the half-reverse method: for 10 the loop ends with x = 0 and reversedHalf = 1, and the odd-length shortcut 1 / 10 = 0 makes them look equal, so 10 would wrongly be called a palindrome.
  • Forgetting that 0 is a palindrome (it ends with 0 but is allowed).
  • Dropping the middle digit in the even-length case too, or forgetting to drop it in the odd-length case.

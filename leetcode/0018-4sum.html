Medium   Topics: Array, Two Pointers, Sorting

Given an integer array nums of length n and an integer target, return all different quadruplets [nums[a], nums[b], nums[c], nums[d]] such that:

  • 0 <= a, b, c, d < n, and a, b, c, d are four different positions,
  • nums[a] + nums[b] + nums[c] + nums[d] == target.

Two quadruplets with the same four numbers count as the same. You may return the answer in any order.

2 💡 Examples and Constraints

Example 1

Input: nums = [1,0,-1,0,-2,2], target = 0
Output: [[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]]
Explanation: Three different groups of four numbers add up to 0.

Example 2

Input: nums = [2,2,2,2,2], target = 8
Output: [[2,2,2,2]]
Explanation: Every group of four 2s adds up to 8, but they are all the same quadruplet, so it is listed once.

📖 Example breakdown (Example 1), step by step
  • Sort [1,0,-1,0,-2,2] to [-2,-1,0,0,1,2]; the target is 0.
  • First number -2: the other three must add up to 2. With second number -1 the last two must add to 3: fingers on 1 and 2 give 1 + 2 = 3, so [-2,-1,1,2]. With second number 0 the last two must add to 2: 0 and 2 give 2, so [-2,0,0,2].
  • First number -1: second number 0, the last two must add to 1: the fingers find 0 and 1, so [-1,0,0,1].
  • First number 0 and later ones cannot give more groups. Three different groups are returned.
  • Result: [[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]] ✅ (the expected output of Example 1)

⚠️ Constraints

  • 1 <= nums.length <= 200
  • -109 <= nums[i] <= 109
  • -109 <= target <= 109

3 🧠 How to Think About It (in Easy Words)

4Sum is 3Sum with one more loop, and 3Sum was 2Sum with one more loop. The pattern: sort the numbers, fix the first numbers with loops (skipping equal neighbours so you never repeat a group), and let two fingers walk inwards for the last two. One more thing is new: the numbers can be as large as a billion, so the sum of four of them does not fit in a 32-bit integer. Add them in a 64-bit variable.

Below you will find 3 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 🚀 Approach 1: Brute Force: Four Loops and a Set

Brute force

💡 Intuition

Sort the array, try every group of four positions, and insert each group that adds up to target into a set that removes repeats. Use a 64-bit sum.

Try every possible team of four and write down the winners in a notebook that refuses repeated lines.

🪜 Algorithm, Step by Step

  1. Sort the array.
  2. Try every group of four positions a < b < c < d and add the numbers in a 64-bit variable.
  3. If the sum equals the target, insert the group into a set.
  4. Return the contents of the set.

⏱️ Complexity

CostWhy
TimeO(n4)four nested loops look at about n4 / 24 groups (64,684,950 for n = 200)
SpaceO(number of answers)the set holds the answers
Good sideWeak side
Almost impossible to get wrong.For n = 200 there are about 64 million groups to test (and a set insertion for each match).

💻 Code

class Solution {
public:
    vector<vector<int>> fourSum(vector<int>& nums, int target) {
        sort(nums.begin(), nums.end());                        // sorted quadruplets make equal ones look identical
        int n = nums.size();
        set<vector<int>> found;                                // keeps every quadruplet only once
        for (int a = 0; a < n; a++)
            for (int b = a + 1; b < n; b++)
                for (int c = b + 1; c < n; c++)
                    for (int d = c + 1; d < n; d++) {
                        long long sum = (long long)nums[a] + nums[b] + nums[c] + nums[d];   // 64-bit: no overflow
                        if (sum == target) found.insert({nums[a], nums[b], nums[c], nums[d]});
                    }
        return vector<vector<int>>(found.begin(), found.end());
    }
};

5 🚀 Approach 2: Sort, Two Loops, Then Two Pointers

Optimized

💡 Intuition

Sort the array. Fix the first two numbers with two loops (skipping a number equal to the previous one at each loop). For the last two numbers, walk left and right inwards, exactly as in 3Sum, comparing a 64-bit sum with the target.

Choose the first two team members, then let the last two walk towards each other along the sorted line until the total is right.

🪜 Algorithm, Step by Step

  1. Sort the array.
  2. Loop over the first number i and the second number j to its right; skip a number equal to the one before it.
  3. Put left = j + 1, right = n - 1 and walk them inwards comparing the 64-bit sum with the target.
  4. On a hit save the group, move both pointers and skip equal numbers.

⏱️ Complexity

CostWhy
TimeO(n3)two loops over n numbers and an O(n) pointer walk inside: O(n3)
SpaceO(1) extraonly a few variables besides the output
Good sideWeak side
Fast enough (about 1.3 million steps for n = 200) and no set is needed.Four places where duplicates must be skipped correctly.

💻 Code

class Solution {
public:
    vector<vector<int>> fourSum(vector<int>& nums, int target) {
        sort(nums.begin(), nums.end());
        int n = nums.size();
        vector<vector<int>> out;
        for (int i = 0; i + 3 < n; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;             // same first number as before
            for (int j = i + 1; j + 2 < n; j++) {
                if (j > i + 1 && nums[j] == nums[j - 1]) continue;     // same second number as before
                int left = j + 1, right = n - 1;
                while (left < right) {
                    long long sum = (long long)nums[i] + nums[j] + nums[left] + nums[right];
                    if (sum < target) left++;
                    else if (sum > target) right--;
                    else {
                        out.push_back({nums[i], nums[j], nums[left], nums[right]});
                        left++; right--;
                        while (left < right && nums[left] == nums[left - 1]) left++;      // skip equal numbers
                        while (left < right && nums[right] == nums[right + 1]) right--;
                    }
                }
            }
        }
        return out;
    }
};

        return out

6 🚀 Approach 3: General kSum: Recursion Down to Two Sum (Most Optimized)

Most optimized (generalizes to any k)

💡 Intuition

Write one function kSum(start, k, target) on the sorted array. For k > 2 it loops over the first number (skipping repeats) and calls itself with k - 1 and the reduced target. For k == 2 it runs the two-pointer walk. Two cheap checks stop early when the smallest or the largest possible sum already misses the target.

A team captain picks one player and hands the rest of the job to a smaller team captain, until only two players are left to pick.

🪜 Algorithm, Step by Step

  1. Sort the array and call kSum(start = 0, k = 4, target).
  2. If k == 2 do the two-pointer walk and save groups.
  3. Otherwise loop over the next number (skip repeats), stop early if even the smallest or the largest possible sum misses the target, and call kSum with k - 1 and the reduced target.
  4. Return all saved groups.

⏱️ Complexity

CostWhy
TimeO(nk - 1) = O(n3) for k = 4k - 2 = 2 levels of loops and an O(n) pointer walk: O(nk - 1) = O(n3)
SpaceO(k) for the recursionthe recursion is only k levels deep
Good sideWeak side
The same code solves 2Sum, 3Sum, 4Sum ... and the early stops make it fast in practice.More abstract: you must keep the 64-bit target and the duplicate skipping correct at every level.

💻 Code

class Solution {
    void kSum(vector<int>& nums, long long target, int start, int k, vector<int>& current, vector<vector<int>>& out) {
        int n = nums.size();
        if (k == 2) {                                          // base case: two pointers
            int left = start, right = n - 1;
            while (left < right) {
                long long sum = (long long)nums[left] + nums[right];
                if (sum < target) left++;
                else if (sum > target) right--;
                else {
                    current.push_back(nums[left]); current.push_back(nums[right]);
                    out.push_back(current);
                    current.pop_back(); current.pop_back();
                    left++; right--;
                    while (left < right && nums[left] == nums[left - 1]) left++;
                    while (left < right && nums[right] == nums[right + 1]) right--;
                }
            }
            return;
        }
        for (int i = start; i + k <= n; i++) {
            if ((long long)nums[i] * k > target) break;                // even the smallest choices are too big
            if ((long long)nums[n - 1] * k < target) break;            // even the biggest choices are too small
            if (i > start && nums[i] == nums[i - 1]) continue;         // skip repeats at this level
            current.push_back(nums[i]);
            kSum(nums, target - nums[i], i + 1, k - 1, current, out);  // pick k - 1 more numbers
            current.pop_back();
        }
    }
public:
    vector<vector<int>> fourSum(vector<int>& nums, int target) {
        sort(nums.begin(), nums.end());
        vector<vector<int>> out;
        vector<int> current;
        kSum(nums, target, 0, 4, current, out);
        return out;
    }
};
class Solution {
    private void kSum(int[] nums, long target, int start, int k, List<Integer> current, List<List<Integer>> out) {
        int n = nums.length;
        if (k == 2) {                                          // base case: two pointers
            int left = start, right = n - 1;
            while (left < right) {
                long sum = (long) nums[left] + nums[right];
                if (sum < target) left++;
                else if (sum > target) right--;
                else {
                    List<Integer> quad = new ArrayList<>(current);
                    quad.add(nums[left]); quad.add(nums[right]);
                    out.add(quad);
                    left++; right--;
                    while (left < right && nums[left] == nums[left - 1]) left++;
                    while (left < right && nums[right] == nums[right + 1]) right--;
                }
            }
            return;
        }
        for (int i = start; i + k <= n; i++) {
            if ((long) nums[i] * k > target) break;                    // even the smallest choices are too big
            if ((long) nums[n - 1] * k < target) break;                // even the biggest choices are too small
            if (i > start && nums[i] == nums[i - 1]) continue;         // skip repeats at this level
            current.add(nums[i]);
            kSum(nums, target - nums[i], i + 1, k - 1, current, out);  // pick k - 1 more numbers
            current.remove(current.size() - 1);
        }
    }

    public List<List<Integer>> fourSum(int[] nums, int target) {
        Arrays.sort(nums);
        List<List<Integer>> out = new ArrayList<>();
        kSum(nums, target, 0, 4, new ArrayList<>(), out);
        return out;
    }
}
class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:
        nums.sort()
        n = len(nums)
        out = []

        def k_sum(start, k, goal, current):
            if k == 2:                                  # base case: two pointers
                left, right = start, n - 1
                while left < right:
                    total = nums[left] + nums[right]
                    if total < goal:
                        left += 1
                    elif total > goal:
                        right -= 1
                    else:
                        out.append(current + [nums[left], nums[right]])
                        left += 1
                        right -= 1
                        while left < right and nums[left] == nums[left - 1]:
                            left += 1
                        while left < right and nums[right] == nums[right + 1]:
                            right -= 1
                return
            for i in range(start, n - k + 1):
                if nums[i] * k > goal:
                    break                               # even the smallest choices are too big
                if nums[-1] * k < goal:
                    break                               # even the biggest choices are too small
                if i > start and nums[i] == nums[i - 1]:
                    continue                            # skip repeats at this level
                k_sum(i + 1, k - 1, goal - nums[i], current + [nums[i]])   # pick k - 1 more numbers

        k_sum(0, 4, target, [])
        return out

8 🔑 Key Insights

  • Four numbers of size 109 add up to 4,000,000,000, which is more than the biggest 32-bit int (2,147,483,647). Always sum in a 64-bit type.
  • For n = 200 the brute force looks at 64,684,950 groups; the sorted pointer methods make only about 1.3 million steps.
  • The kSum idea solves 2Sum, 3Sum, 4Sum and any bigger k with the same code; only the base case is special.
  • The numbers in all three languages come out the same: the tests include groups made of the extreme values -109 and 109.

10 ⚠️ Common Mistakes

  • Adding four numbers of size 109 in a 32-bit int: the sum overflows. Use long long / long in C++ and Java.
  • Skipping duplicates with the wrong condition: compare with the previous element, and for the second loop only when j > i + 1 (not j > 0).
  • Returning the same quadruplet twice because the pointers were not moved past equal numbers after a hit.
  • Using an unsorted array with two pointers: the walk only works on sorted data.
  • In kSum, forgetting that target - nums[i] can also overflow a 32-bit int: keep the target in 64 bits.

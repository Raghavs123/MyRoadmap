Medium   Topics: Hash Table, String, Backtracking

On an old phone keypad every digit from 2 to 9 carries some letters: 2 = abc, 3 = def, 4 = ghi, 5 = jkl, 6 = mno, 7 = pqrs, 8 = tuv and 9 = wxyz. (The digit 1 has no letters.)

You are given a string digits that contains only the digits 2 to 9. Return all letter combinations the number could stand for, by choosing one letter for each digit. You may return the answers in any order.

2 💡 Examples and Constraints

Example 1

Input: digits = "23"
Output: ["ad","ae","af","bd","be","bf","cd","ce","cf"]
Explanation: 2 can be a, b or c and 3 can be d, e or f: 3 * 3 = 9 combinations.

Example 2

Input: digits = ""
Output: []
Explanation: With no digits there is nothing to spell, so the answer is an empty list (not a list holding an empty word).

Example 3

Input: digits = "2"
Output: ["a","b","c"]
Explanation: Just the three letters of the digit 2.

📖 Example breakdown (Example 1), step by step
  • The digit 2 has the letters abc and the digit 3 has def.
  • Choose a for the digit 2, then each of d, e, f for the digit 3: ad, ae, af.
  • Go back and choose b: bd, be, bf. Then c: cd, ce, cf.
  • 3 letters times 3 letters gives 9 words.
  • Result: ["ad","ae","af","bd","be","bf","cd","ce","cf"] ✅ (the expected output of Example 1)

⚠️ Constraints

  • 0 <= digits.length <= 4
  • digits[i] is a digit in the range ['2', '9'].

3 🧠 How to Think About It (in Easy Words)

For every digit you must choose one of its letters, and the choices for different digits do not depend on each other. That is a tree: the first digit splits into 3 or 4 branches, each branch splits again for the second digit, and so on. Every path from the top to the bottom of the tree is one answer. You can walk the tree by calling yourself (backtracking), or build the answers digit by digit (extend every word you already have by every letter of the next digit).

Below you will find 3 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 🚀 Approach 1: Backtracking: Walk the Tree of Choices

Standard approach

💡 Intuition

Write a helper that knows the current position in digits and the word built so far. If the word is complete, save it. Otherwise try every letter of the current digit: add the letter, call the helper for the next position, then remove the letter again (undo the choice).

Walking through a maze of three-way crossroads and writing down the route every time you reach an exit, then stepping back to try the next turn.

🪜 Algorithm, Step by Step

  1. If the digit string is empty, return an empty list.
  2. Write a helper build(position, current); when position equals the number of digits, save current.
  3. Otherwise loop over the letters of the current digit: append a letter, call build(position + 1), then remove the letter again.
  4. Call build(0, empty word) and return the saved words.

⏱️ Complexity

CostWhy
TimeO(4n * n)the tree has up to 4n leaves and every leaf word costs O(n) to write
SpaceO(n) for the recursion (plus the answer)recursion depth n plus the current word (the answer list is extra)
Good sideWeak side
The classic way to generate all combinations; easy to extend to other problems.Recursion with an 'undo' step is a little harder for beginners.

class Solution {
    const vector<string> letters = {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};
    void build(const string& digits, size_t position, string& current, vector<string>& out) {
        if (position == digits.size()) {                       // one letter chosen for every digit: a finished word
            out.push_back(current);
            return;
        }
        for (char c : letters[digits[position] - '0']) {       // try each letter of this digit
            current.push_back(c);                              // choose it
            build(digits, position + 1, current, out);         // fill the next positions
            current.pop_back();                                // undo the choice
        }
    }
public:
    vector<string> letterCombinations(string digits) {
        vector<string> out;
        if (digits.empty()) return out;                        // no digits: no words
        string current;
        build(digits, 0, current, out);
        return out;
    }
};
class Solution {
    private static final String[] LETTERS = {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};

    private void build(String digits, int position, StringBuilder current, List<String> out) {
        if (position == digits.length()) {                     // one letter chosen for every digit: a finished word
            out.add(current.toString());
            return;
        }
        for (char c : LETTERS[digits.charAt(position) - '0'].toCharArray()) {   // try each letter of this digit
            current.append(c);                                 // choose it
            build(digits, position + 1, current, out);         // fill the next positions
            current.deleteCharAt(current.length() - 1);        // undo the choice
        }
    }

    public List<String> letterCombinations(String digits) {
        List<String> out = new ArrayList<>();
        if (digits.isEmpty()) return out;                      // no digits: no words
        build(digits, 0, new StringBuilder(), out);
        return out;
    }
}
class Solution:
    def letterCombinations(self, digits: str) -> List[str]:
        letters = ["", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"]
        out = []

        def build(position, current):
            if position == len(digits):                 # one letter chosen for every digit: a finished word
                out.append("".join(current))
                return
            for c in letters[int(digits[position])]:    # try each letter of this digit
                current.append(c)                       # choose it
                build(position + 1, current)            # fill the next positions
                current.pop()                           # undo the choice

        if digits:                                      # no digits: no words
            build(0, [])
        return out

5 🚀 Approach 2: Iterative: Extend Every Word by Every Letter

Optimized (no recursion)

💡 Intuition

Start with a list that holds one empty word. For each digit, make a new list: for every word in the old list and every letter of the digit, add word + letter. After the last digit the list contains all answers.

Building a family tree level by level: each person gets a child for every letter of the next digit.

🪜 Algorithm, Step by Step

  1. If the digit string is empty, return an empty list.
  2. Start with the list [""] (one empty word).
  3. For every digit, build a new list holding word + letter for every word in the old list and every letter of the digit.
  4. After the last digit return the list.

⏱️ Complexity

CostWhy
TimeO(4n * n)every level builds all words of that length, so the total work is about 4n * n
SpaceO(4n * n) for the liststhe old and the new list exist at the same time
Good sideWeak side
No recursion and no undo step: just two loops.Creates a whole new list for every digit.

💻 Code

class Solution {
public:
    vector<string> letterCombinations(string digits) {
        if (digits.empty()) return {};                         // no digits: no words
        const vector<string> letters = {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};
        vector<string> words = {""};                           // start with one empty word
        for (char digit : digits) {
            vector<string> longer;
            for (const string& word : words)
                for (char c : letters[digit - '0'])
                    longer.push_back(word + c);                // extend every word by every letter
            words = longer;
        }
        return words;
    }
};

6 🚀 Approach 3: Breadth-First with a Queue

Optimized (alternative)

💡 Intuition

Put the empty word in a queue. Repeatedly take the word at the front; if it is already as long as digits, everything left in the queue is an answer. Otherwise add every letter of the next digit to it and push the longer words at the back.

People stand in a line at a ticket window; each person leaves and sends three or four children to the back of the line, until everyone in the line is fully grown.

🪜 Algorithm, Step by Step

  1. If the digit string is empty, return an empty list.
  2. Put the empty word in a queue.
  3. While the word at the front is shorter than the digit string: take it out and push it back once for every letter of the next digit.
  4. The queue now holds all finished words: return it.

⏱️ Complexity

CostWhy
TimeO(4n * n)every word is pushed once and every pushed word costs O(n) to build
SpaceO(4n * n)the queue holds up to 4n words of length n
Good sideWeak side
Shows the same idea as breadth-first search and keeps the answers in alphabetical order.Needs a queue, and a little thought to know when to stop.

💻 Code

class Solution {
public:
    vector<string> letterCombinations(string digits) {
        vector<string> out;
        if (digits.empty()) return out;                        // no digits: no words
        const vector<string> letters = {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};
        queue<string> line;
        line.push("");
        while (line.front().size() < digits.size()) {          // the front word is still too short
            string word = line.front();
            line.pop();
            for (char c : letters[digits[word.size()] - '0'])  // next digit = digit at position word.size()
                line.push(word + c);
        }
        while (!line.empty()) { out.push_back(line.front()); line.pop(); }
        return out;
    }
};
class Solution {
    public List<String> letterCombinations(String digits) {
        List<String> out = new ArrayList<>();
        if (digits.isEmpty()) return out;                      // no digits: no words
        String[] letters = {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};
        Deque<String> line = new ArrayDeque<>();
        line.add("");
        while (line.peekFirst().length() < digits.length()) {  // the front word is still too short
            String word = line.pollFirst();
            for (char c : letters[digits.charAt(word.length()) - '0'].toCharArray())   // next digit = digit at position word.length()
                line.addLast(word + c);
        }
        out.addAll(line);
        return out;
    }
}
class Solution:
    def letterCombinations(self, digits: str) -> List[str]:
        if not digits:
            return []                                   # no digits: no words
        letters = ["", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"]
        line = deque([""])
        while len(line[0]) < len(digits):               # the front word is still too short
            word = line.popleft()
            for c in letters[int(digits[len(word)])]:   # next digit = digit at position len(word)
                line.append(word + c)
        return list(line)

8 🔑 Key Insights

  • Every answer is one path in a tree with one level per digit and 3 or 4 branches per level.
  • The number of answers is the product of the letter counts: 3 * 3 * 3 * 3 = 81 for "2345" and 4 * 4 * 4 * 4 = 256 for "7979" (7 and 9 have four letters).
  • The empty string is a special case: it has no combinations, so the answer is [], not [""].
  • All 4,681 digit strings of length 0 to 4 over the digits 2 to 9 were tested, so every possible input of this problem was covered.

10 ⚠️ Common Mistakes

  • Returning [""] instead of [] for empty input: the empty digit string has no combinations.
  • Forgetting to undo the choice in backtracking (pop_back / deleteCharAt / pop): the words grow longer and longer.
  • Using the wrong letters for 7 (pqrs) or 9 (wxyz): these are the two digits with four letters.
  • Mapping a digit character to an index without subtracting '0' (digits[i] - '0').
  • Looking for a clever formula: the number of answers really is exponential, so the work is spent writing them out.

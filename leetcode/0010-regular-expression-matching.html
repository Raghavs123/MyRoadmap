1 Problem Statement

Open on LeetCode ↗

Hard   Topics: String, Dynamic Programming, Recursion

You are given a text s and a pattern p. Implement regular expression matching with support for two special characters:

  • '.' matches any single character.
  • '*' matches zero or more copies of the character just before it (so a* can mean "", "a", "aa", "aaa", ...).

The match must cover the entire string s, not just a part of it. Return true if it does, otherwise false.

2 Examples and Constraints

Example 1

Input: s = "aa", p = "a"
Output: false
Explanation: The pattern "a" matches only one "a", but the text has two, so the whole text is not covered.

Example 2

Input: s = "aa", p = "a*"
Output: true
Explanation: "a*" means zero or more "a". Using it twice gives "aa".

Example 3

Input: s = "ab", p = ".*"
Output: true
Explanation: ".*" means zero or more of any character, so it can match "ab".

Constraints

  • 1 <= s.length <= 20
  • 1 <= p.length <= 20
  • s contains only lowercase English letters.
  • p contains only lowercase English letters, '.', and '*'.
  • It is guaranteed that for each appearance of '*', there will be a previous valid character to match.

3 How to Think About It (in Easy Words)

Look at the pattern one piece at a time. A piece is either a single symbol (a or .) or a symbol followed by a star (a* or .*). A plain piece must eat exactly one matching letter from the text. A starred piece has two choices: skip it (it matches zero letters) or eat one matching letter and stay on the same piece to maybe eat more. The question 'does the rest of the text match the rest of the pattern?' repeats with smaller and smaller leftovers, which is why recursion and dynamic programming fit so well.

Below you will find 4 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 Approach 1: Brute Force: Plain Recursion

Brute force

Idea: Ask: does s[i..] match p[j..]? If the pattern is used up, the text must be used up too. Otherwise check whether the first letters match (equal, or the pattern has '.'). If the next pattern symbol is '*', try the two choices: skip the starred piece (j + 2), or use it once (i + 1, same j). If there is no star, both indexes move on by one.

Like walking through a maze and at every fork trying both paths one after the other, even if you have already explored the same room before.
TimeSpaceGood sideWeak side
Exponential in the worst caseO(n + m) call stackIt is the rule of the problem written as code: the easiest to understand.The same (i, j) pairs are solved again and again, so patterns like "a*a*a*a*b" on a text of a's take very long.

Code

class Solution {
    // does s[i..] match p[j..] ?
    bool match(const string& s, const string& p, int i, int j) {
        int m = s.size(), n = p.size();
        if (j == n) return i == m;                             // pattern used up: the text must be used up too
        bool firstMatches = i < m && (p[j] == s[i] || p[j] == '.');   // can the first letters match?
        if (j + 1 < n && p[j + 1] == '*') {
            // 'x*': skip it (use it zero times), or use it once and stay on it
            return match(s, p, i, j + 2) || (firstMatches && match(s, p, i + 1, j));
        }
        return firstMatches && match(s, p, i + 1, j + 1);      // a plain symbol eats exactly one letter
    }
public:
    bool isMatch(string s, string p) {
        return match(s, p, 0, 0);
    }
};

5 Approach 2: Recursion with a Memory (Top-Down DP)

Optimized

Idea: It is the same recursion, but the answer for every pair (i, j) is written in a table the first time it is computed. When the same pair comes again, the saved answer is returned at once. There are only (n + 1) × (m + 1) pairs, so the work becomes small.

Like writing the result of every maze room on a sticky note and sticking it on the door, so you never explore the same room twice.
TimeSpaceGood sideWeak side
O(n × m)O(n × m)Tiny change from the brute force; the speed-up is huge.Still uses recursion, so the call stack grows with the text and pattern length.

Code

class Solution {
    // memo[i][j]: -1 = not known yet, 0 = false, 1 = true
    bool match(const string& s, const string& p, int i, int j, vector<vector<int>>& memo) {
        int m = s.size(), n = p.size();
        if (memo[i][j] != -1) return memo[i][j] == 1;          // already solved: use the saved answer
        bool answer;
        if (j == n) {
            answer = (i == m);                                 // pattern used up: the text must be used up too
        } else {
            bool firstMatches = i < m && (p[j] == s[i] || p[j] == '.');
            if (j + 1 < n && p[j + 1] == '*')
                answer = match(s, p, i, j + 2, memo) || (firstMatches && match(s, p, i + 1, j, memo));
            else
                answer = firstMatches && match(s, p, i + 1, j + 1, memo);
        }
        memo[i][j] = answer ? 1 : 0;                           // save the answer for next time
        return answer;
    }
public:
    bool isMatch(string s, string p) {
        vector<vector<int>> memo(s.size() + 1, vector<int>(p.size() + 1, -1));
        return match(s, p, 0, 0, memo);
    }
};

6 Approach 3: Bottom-Up Dynamic Programming Table

Optimized (table)

Idea: Fill a table dp[i][j] = 'does s[i..] match p[j..]?' starting from the ends of the strings and going backwards, so every cell only looks at cells that are already filled. The answer is dp[0][0]. The rule for each cell is exactly the recursion's rule.

Instead of asking the questions from the top and waiting for answers, you answer the easiest questions first (the short leftovers) and build up to the full question.
TimeSpaceGood sideWeak side
O(n × m)O(n × m)No recursion, no stack problems, and the table makes the idea visible.Stores the whole table although each row only needs the next row.

Code

class Solution {
public:
    bool isMatch(string s, string p) {
        int m = s.size(), n = p.size();
        // dp[i][j] is true when s[i..] matches p[j..]
        vector<vector<bool>> dp(m + 1, vector<bool>(n + 1, false));
        dp[m][n] = true;                                       // an empty text matches an empty pattern
        for (int i = m; i >= 0; i--) {                         // go backwards so the cells we need are already filled
            for (int j = n - 1; j >= 0; j--) {
                bool first = i < m && (p[j] == s[i] || p[j] == '.');
                if (j + 1 < n && p[j + 1] == '*')
                    dp[i][j] = dp[i][j + 2] || (first && dp[i + 1][j]);   // skip 'x*', or eat one letter and stay
                else
                    dp[i][j] = first && dp[i + 1][j + 1];      // a plain symbol eats exactly one letter
            }
        }
        return dp[0][0];
    }
};

7 Approach 4: Table with Only Two Rows (Most Optimized Memory)

Most optimized

Idea: Cell dp[i][j] only looks at its own row (dp[i][j+2]) and at the next row (dp[i+1][j], dp[i+1][j+1]). So keep just two rows: next (row i + 1) and cur (row i). After finishing a row, swap them.

Like a teacher who only keeps the last two pages of a long calculation on the desk and throws away the older pages.
TimeSpaceGood sideWeak side
O(n × m)O(m), m = pattern lengthThe same speed as the full table with a tiny amount of memory.A little harder to read: you must remember which row is which after each swap.

Code

class Solution {
public:
    bool isMatch(string s, string p) {
        int m = s.size(), n = p.size();
        vector<bool> next(n + 1, false), cur(n + 1, false);    // next = row i + 1, cur = row i
        for (int i = m; i >= 0; i--) {
            cur[n] = (i == m);                                 // only the empty text matches the empty pattern
            for (int j = n - 1; j >= 0; j--) {
                bool first = i < m && (p[j] == s[i] || p[j] == '.');
                if (j + 1 < n && p[j + 1] == '*')
                    cur[j] = cur[j + 2] || (first && next[j]); // skip 'x*', or eat one letter and stay
                else
                    cur[j] = first && next[j + 1];             // a plain symbol eats exactly one letter
            }
            swap(next, cur);                                   // row i becomes 'next' for row i - 1
        }
        return next[0];                                        // after the last swap, row 0 is in 'next'
    }
};

    public boolean isMatch(String s, String p) {

            for (int j = n - 1; j >= 0; j--) {

10 Common Mistakes

  • Treating '*' as 'zero or more of anything' (like a shell wildcard). Here it repeats only the character just before it.
  • Forgetting the 'zero times' choice: "aab" matches "c*a*b" only because c* is used zero times.
  • Checking the first letters when the text is already empty (reading past the end): always test i < s.length() first.
  • Moving to j + 1 instead of j + 2 when skipping a starred piece: the star belongs to the piece.
  • Matching only a part of the text: the pattern has to be used up and the text has to be used up at the same time.
  • Filling the table in the wrong order: cell (i, j) needs (i, j + 2) and row i + 1, so go from the end backwards.

Easy   Topics: String, Stack

You are given a string s that contains only the six characters '(', ')', '{', '}', '[' and ']'. Decide whether the string is valid. A string is valid when:

  1. every opening bracket is closed by a bracket of the same type,
  2. the brackets are closed in the correct order (the most recently opened bracket must be closed first), and
  3. every closing bracket has an opening bracket of the same type to match.

2 💡 Examples and Constraints

Example 1

Input: s = "()"
Output: true
Explanation: One opening and one closing round bracket.

Example 2

Input: s = "()[]{}"
Output: true
Explanation: Three pairs, one after the other.

Example 3

Input: s = "(]"
Output: false
Explanation: The round bracket is closed by a square bracket: the types do not match.

Example 4

Input: s = "([])"
Output: true
Explanation: The square brackets are opened and closed inside the round brackets, so the order is correct.

📖 Example breakdown (Example 4), step by step
  • The string is ([]).
  • ( is an opening bracket: put it on the pile (we now expect a )). [ opens too: the pile is now (, [ with [ on top.
  • ] is a closing bracket and it matches the top ([): take the top away. ) closes and matches the new top (: take it away.
  • The pile is empty at the end, so every bracket was closed in the right order: true.
  • Result: true ✅ (the expected output of Example 4)

⚠️ Constraints

  • 1 <= s.length <= 104
  • s consists only of the characters '()[]{}'.

3 🧠 How to Think About It (in Easy Words)

Think of a stack of plates. Every time you meet an opening bracket you put a plate on the pile. Every time you meet a closing bracket it must match the plate on top of the pile (the most recent opening); if it does, take that plate away, otherwise the string is wrong. At the end the pile must be empty. A different idea: keep deleting neighbouring pairs (), [], {}; a valid string disappears completely.

Below you will find 3 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 🚀 Approach 1: Keep Deleting Matching Pairs

Brute force

💡 Intuition

Repeat: remove every occurrence of (), [] and {} from the string. If nothing is left in the end the string was valid; if the string stops changing while still not empty, it is invalid.

Cancel out neighbours that cancel each other, like +1 and -1 side by side, until nothing is left (or something that cannot cancel remains).

🪜 Algorithm, Step by Step

  1. Remove every (), [] and {} from the string.
  2. If the string became shorter, repeat from step 1.
  3. When a whole round removes nothing, stop.
  4. Return true only if the string is empty now.

⏱️ Complexity

CostWhy
TimeO(n2)every round scans the string and each round removes at least one pair, so up to n / 2 rounds are needed
SpaceO(n)a shorter copy of the string
Good sideWeak side
Very short and easy to believe.Each round scans the whole string and there can be n / 2 rounds, so it is slow for 10,000 characters.

💻 Code

class Solution {
    void eraseAll(string& text, const string& pair) {
        size_t pos;
        while ((pos = text.find(pair)) != string::npos) text.erase(pos, 2);   // remove one matching pair
    }
public:
    bool isValid(string s) {
        size_t before;
        do {
            before = s.size();
            eraseAll(s, "()");
            eraseAll(s, "[]");
            eraseAll(s, "{}");
        } while (s.size() != before);                          // stop when a whole round removes nothing
        return s.empty();                                      // valid only if everything cancelled out
    }
};
class Solution {
    public boolean isValid(String s) {
        int before;
        do {
            before = s.length();
            s = s.replace("()", "").replace("[]", "").replace("{}", "");     // remove every matching pair
        } while (s.length() != before);                        // stop when a whole round removes nothing
        return s.isEmpty();                                    // valid only if everything cancelled out
    }
}
class Solution:
    def isValid(self, s: str) -> bool:
        while True:
            shorter = s.replace("()", "").replace("[]", "").replace("{}", "")    # remove every matching pair
            if len(shorter) == len(s):                  # a whole round removed nothing
                break
            s = shorter
        return s == ""                                  # valid only if everything cancelled out

5 🚀 Approach 2: Stack of the Closing Brackets We Still Expect (Most Optimized)

Most optimized

💡 Intuition

Go through the string once with a stack. When you see an opening bracket, push the closing bracket it needs. When you see a closing bracket, the stack must not be empty and its top must be exactly this bracket; then pop. At the end the stack must be empty.

A to-do list on a sticky note: every opening bracket adds a promise ('I must close with ]'); every closing bracket must fulfil the newest promise.

🪜 Algorithm, Step by Step

  1. Make an empty stack for the closing brackets that are still expected.
  2. For an opening bracket push the closing bracket it needs.
  3. For a closing bracket: if the stack is empty or the top is a different bracket return false; otherwise pop.
  4. After the last character return whether the stack is empty.

⏱️ Complexity

CostWhy
TimeO(n)each character is pushed or popped at most once
SpaceO(n)the stack can hold up to n characters
Good sideWeak side
One pass and the code is very short: no lookup table needed.You must remember to check 'is the stack empty?' both when closing and at the end.

💻 Code

class Solution {
public:
    bool isValid(string s) {
        stack<char> expected;                                  // the closing brackets we still owe
        for (char c : s) {
            if (c == '(') expected.push(')');
            else if (c == '[') expected.push(']');
            else if (c == '{') expected.push('}');
            else {                                             // a closing bracket: it must be the newest promise
                if (expected.empty() || expected.top() != c) return false;
                expected.pop();
            }
        }
        return expected.empty();                               // no promise may be left over
    }
};

}

6 🚀 Approach 3: Stack of Opening Brackets with a Lookup Table

Optimized (alternative)

💡 Intuition

Push every opening bracket on the stack. For a closing bracket, look up which opening bracket it needs in a small table () -> (, ] -> [, } -> {) and compare it with the top of the stack.

The same pile of plates, but now the plates are the open brackets themselves and the table tells you which closing bracket fits which plate.

🪜 Algorithm, Step by Step

  1. Make a table that maps each closing bracket to its opening partner and an empty stack.
  2. Push every opening bracket.
  3. For a closing bracket compare the top of the stack with the table entry; on a mismatch (or an empty stack) return false, otherwise pop.
  4. After the last character return whether the stack is empty.

⏱️ Complexity

CostWhy
TimeO(n)each character is pushed or popped at most once
SpaceO(n)the stack can hold up to n characters
Good sideWeak side
Mirrors the textbook explanation of bracket matching and is easy to extend with more bracket types.A little longer than the 'expected closer' version.

💻 Code

class Solution {
public:
    bool isValid(string s) {
        unordered_map<char, char> partner = {{')', '('}, {']', '['}, {'}', '{'}};
        stack<char> opened;                                    // the opening brackets that are still open
        for (char c : s) {
            if (partner.count(c)) {                            // a closing bracket
                if (opened.empty() || opened.top() != partner[c]) return false;
                opened.pop();
            } else {
                opened.push(c);                                // an opening bracket
            }
        }
        return opened.empty();                                 // nothing may be left open
    }
};
class Solution {
    public boolean isValid(String s) {
        Map<Character, Character> partner = new HashMap<>();
        partner.put(')', '(');
        partner.put(']', '[');
        partner.put('}', '{');
        Deque<Character> opened = new ArrayDeque<>();          // the opening brackets that are still open
        for (char c : s.toCharArray()) {
            if (partner.containsKey(c)) {                      // a closing bracket
                if (opened.isEmpty() || !opened.pop().equals(partner.get(c))) return false;
            } else {
                opened.push(c);                                // an opening bracket
            }
        }
        return opened.isEmpty();                               // nothing may be left open
    }
}
class Solution:
    def isValid(self, s: str) -> bool:
        partner = {")": "(", "]": "[", "}": "{"}
        opened = []                                     # the opening brackets that are still open
        for c in s:
            if c in partner:                            # a closing bracket
                if not opened or opened.pop() != partner[c]:
                    return False
            else:
                opened.append(c)                        # an opening bracket
        return not opened                               # nothing may be left open

8 🔑 Key Insights

  • The most recently opened bracket must be closed first: that is exactly what a stack (last in, first out) is for.
  • Counting the brackets of each type is not enough: "([)]" has the right counts but the wrong order.
  • A string such as "(((" never meets a wrong closing bracket, so you must also check that the stack is empty at the end.
  • On the same 10,000-character inputs the stack versions take a few milliseconds while repeated deletion is much slower (see the test report).

10 ⚠️ Common Mistakes

  • Popping from an empty stack when the string starts with a closing bracket like ): check isEmpty() first.
  • Returning true when the loop ends without checking that the stack is empty (the string "(((" has no wrong closing bracket but is invalid).
  • Only counting brackets of each type: "([)]" has matching counts but the wrong order.
  • Comparing with the wrong bracket: the stack of expected closers stores ), the stack of openers stores (: do not mix the two styles.
  • Having an odd length: such a string can never be valid, which is a quick early answer (not required).

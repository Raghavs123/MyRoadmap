Hard   Topics: Array, Binary Search, Divide and Conquer

You are given two sorted arrays nums1 (size m) and nums2 (size n), each in ascending order. Return the median of the two arrays combined.

The median is the middle value of the combined sorted list: if the total count is odd it is the single middle element; if it is even it is the average of the two middle elements.

The overall running time should be O(log (m+n)).

2 💡 Examples and Constraints

Example 1

Input: nums1 = [1,3], nums2 = [2]
Output: 2.00000
Explanation: Merged array = [1,2,3] and the median is 2.

Example 2

Input: nums1 = [1,2], nums2 = [3,4]
Output: 2.50000
Explanation: Merged array = [1,2,3,4] and the median is (2 + 3) / 2 = 2.5.

📖 Example breakdown (Example 2), step by step
  • Together there are 2 + 2 = 4 numbers: an even count, so the median is the average of the 2nd and 3rd smallest.
  • In order, the numbers are 1, 2, 3, 4.
  • The 2nd smallest is 2 and the 3rd smallest is 3.
  • Median = (2 + 3) / 2 = 2.5, written with five decimals as 2.50000.
  • Result: 2.50000 ✅ (the expected output of Example 2)

⚠️ Constraints

  • nums1.length == m
  • nums2.length == n
  • 0 <= m <= 1000
  • 0 <= n <= 1000
  • 1 <= m + n <= 2000
  • -106 <= nums1[i], nums2[i] <= 106

3 🧠 How to Think About It (in Easy Words)

If you merge the two lists into one sorted list, the median is just the middle of it. That works, but the problem asks for something cleverer: we do not need to merge everything. We only need to find the cut that splits all the numbers into a 'small half' and a 'big half'. Binary search can find that cut by looking at only a few numbers.

Below you will find 3 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 🚀 Approach 1: Brute Force: Put Everything Together and Sort

Brute force

💡 Intuition

Copy both arrays into one big array, sort it, and read the middle one (or the average of the two middle ones).

Pour two decks of numbered cards into one pile, sort the pile, take the middle card.

🪜 Algorithm, Step by Step

  1. Join both arrays into one array.
  2. Sort it.
  3. Odd total: return the middle element. Even total: return the average of the two middle elements.

⏱️ Complexity

CostWhy
TimeO((m + n) log (m + n))Sorting m + n numbers costs O((m + n) log (m + n)).
SpaceO(m + n)The joined copy holds all m + n numbers.
Good sideWeak side
Almost impossible to get wrong.Ignores the fact that the arrays are already sorted; slower than needed.

💻 Code

class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        vector<int> all(nums1);                         // copy of the first array
        all.insert(all.end(), nums2.begin(), nums2.end());   // add the second array
        sort(all.begin(), all.end());                   // sort everything
        int total = all.size();
        if (total % 2 == 1) {
            return all[total / 2];                      // odd count: the single middle element
        }
        return (all[total / 2 - 1] + all[total / 2]) / 2.0;  // even count: average of the two middle ones
    }
};
class Solution {
    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        int m = nums1.length, n = nums2.length;
        int[] all = new int[m + n];                     // one big array
        System.arraycopy(nums1, 0, all, 0, m);          // copy the first array
        System.arraycopy(nums2, 0, all, m, n);          // copy the second array after it
        Arrays.sort(all);                               // sort everything
        int total = m + n;
        if (total % 2 == 1) {
            return all[total / 2];                      // odd count: the single middle element
        }
        return (all[total / 2 - 1] + all[total / 2]) / 2.0;  // even count: average of the two middle ones
    }
}
class Solution:

        total = len(merged)
        if total % 2 == 1:
            return float(merged[total // 2])            # odd count: the single middle element
        return (merged[total // 2 - 1] + merged[total // 2]) / 2   # even count: average of the two middle ones

5 🚀 Approach 2: Merge Like Merge Sort, Stop at the Middle

Optimized (linear)

💡 Intuition

Both arrays are already sorted, so we can merge them with two fingers: always take the smaller front number. We do not need to build the merged array: we only count steps until we reach the middle position(s), remembering the last two numbers taken.

Two queues of people sorted by height: call the shorter front person each time, and stop when you have called half of everybody.

🪜 Algorithm, Step by Step

  1. Put one finger i at the start of nums1 and one finger j at the start of nums2.
  2. Repeat (m + n) / 2 + 1 times: take the smaller front number (or the front of the array that still has numbers) and remember the previous and the current number taken.
  3. Odd total: return the current number. Even total: return (previous + current) / 2.

⏱️ Complexity

CostWhy
TimeO(m + n)We stop after about half of the m + n numbers: O(m + n).
SpaceO(1)Only two fingers and the last two numbers taken.
Good sideWeak side
Uses the sorted order; no extra array.Still walks half of all the numbers; the problem wants O(log(m+n)).

💻 Code

class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        int m = nums1.size(), n = nums2.size();
        int total = m + n;
        int i = 0, j = 0;                               // one finger in each array
        int prev = 0, cur = 0;                          // the last two numbers we took
        for (int step = 0; step <= total / 2; step++) { // take total/2 + 1 numbers in order
            prev = cur;
            if (i < m && (j >= n || nums1[i] <= nums2[j])) {
                cur = nums1[i++];                       // the front of nums1 is smaller (or nums2 is used up)
            } else {
                cur = nums2[j++];                       // the front of nums2 is smaller (or nums1 is used up)
            }
        }
        if (total % 2 == 1) return cur;                 // odd: the last number taken is the middle one
        return (prev + cur) / 2.0;                      // even: average of the last two numbers taken
    }
};

class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        m, n = len(nums1), len(nums2)
        total = m + n
        i = j = 0                                       # one finger in each array
        prev = cur = 0                                  # the last two numbers we took
        for _ in range(total // 2 + 1):                 # take total/2 + 1 numbers in order
            prev = cur
            if i < m and (j >= n or nums1[i] <= nums2[j]):
                cur = nums1[i]                          # the front of nums1 is smaller (or nums2 is used up)
                i += 1
            else:
                cur = nums2[j]                          # the front of nums2 is smaller (or nums1 is used up)
                j += 1
        if total % 2 == 1:
            return float(cur)                           # odd: the last number taken is the middle one
        return (prev + cur) / 2                         # even: average of the last two numbers taken

6 🚀 Approach 3: Binary Search on the Cut (Most Optimized)

Most optimized

💡 Intuition

Make sure A is the shorter array. We look for a cut position i in A and a matching cut j in B so that the left parts together hold exactly half of all numbers (i + j = (m + n + 1) / 2). The cut is correct when every number on the left is <= every number on the right, which only needs two checks: A[i-1] <= B[j] and B[j-1] <= A[i]. If A[i-1] is too big, move the cut in A left; if B[j-1] is too big, move it right. Binary search on i finds the cut in O(log(min(m, n))) steps. Then the median comes from the four numbers around the cut.

Two sorted rows of kids: find one rope position in each row so that the shorter-kids group on the left side of both ropes contains exactly half the children and nobody on the left is taller than anybody on the right.

🪜 Algorithm, Step by Step

  1. Make nums1 the shorter array (swap if needed); half = (m + n + 1) / 2.
  2. Binary search the cut i in nums1 between 0 and m; the cut in nums2 is j = half - i.
  3. Read the four border numbers a_left, a_right, b_left, b_right (use −∞ / +∞ when a cut is at an edge).
  4. If a_left <= b_right and b_left <= a_right, the cut is right: odd total → max(a_left, b_left); even → (max(a_left, b_left) + min(a_right, b_right)) / 2.
  5. If a_left > b_right, move the cut left (hi = i - 1); otherwise move it right (lo = i + 1).

⏱️ Complexity

CostWhy
TimeO(log(min(m, n)))Every step halves the range of possible cuts in the shorter array: O(log(min(m, n))).
SpaceO(1)Only a few indexes and four border values.
Good sideWeak side
Meets the required O(log(m+n)) bound.Tricky edge cases (empty arrays, cut at the very start/end): we use -infinity and +infinity as fake numbers.

💻 Code

class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        if (nums1.size() > nums2.size()) {
            return findMedianSortedArrays(nums2, nums1);   // always binary search the SHORTER array
        }
        int m = nums1.size(), n = nums2.size();
        int half = (m + n + 1) / 2;                     // how many numbers belong to the left side
        int lo = 0, hi = m;                             // possible cut positions in nums1: 0..m
        while (lo <= hi) {
            int i = (lo + hi) / 2;                      // cut in nums1: i numbers go left
            int j = half - i;                           // cut in nums2: j numbers go left
            // the numbers just outside each cut; use -inf / +inf when the cut is at an edge
            int aLeft  = (i == 0) ? INT_MIN : nums1[i - 1];
            int aRight = (i == m) ? INT_MAX : nums1[i];
            int bLeft  = (j == 0) ? INT_MIN : nums2[j - 1];
            int bRight = (j == n) ? INT_MAX : nums2[j];
            if (aLeft <= bRight && bLeft <= aRight) {   // perfect cut: left side <= right side
                if ((m + n) % 2 == 1) {
                    return max(aLeft, bLeft);           // odd: the biggest number on the left is the median
                }
                return (max(aLeft, bLeft) + min(aRight, bRight)) / 2.0;   // even: average of the two middle numbers
            } else if (aLeft > bRight) {
                hi = i - 1;                             // took too many from nums1: move the cut left
            } else {
                lo = i + 1;                             // took too few from nums1: move the cut right
            }
        }
        return 0.0;                                     // never reached for valid input
    }
};

            return self.findMedianSortedArrays(nums2, nums1)   # always binary search the SHORTER array

            j = half - i                                # cut in nums2: j numbers go left
            # the numbers just outside each cut; use -inf / +inf when the cut is at an edge
            a_left = nums1[i - 1] if i > 0 else float("-inf")
            a_right = nums1[i] if i < m else float("inf")
            b_left = nums2[j - 1] if j > 0 else float("-inf")
            b_right = nums2[j] if j < n else float("inf")
            if a_left <= b_right and b_left <= a_right:     # perfect cut: left side <= right side
                if (m + n) % 2 == 1:

                return (max(a_left, b_left) + min(a_right, b_right)) / 2   # even: average of the two middle numbers

            else:
                lo = i + 1                              # took too few from nums1: move the cut right
        return 0.0                                      # never reached for valid input

8 🔑 Key Insights

  • The median splits all numbers into a left half and a right half; you never need to build the merged array to find that split.
  • Searching on the shorter array keeps j = half - i inside the longer array and makes the work O(log(min(m, n))).
  • Using −∞ and +∞ for missing border values removes every edge case at the ends of the arrays.
  • The problem asks for O(log (m+n)) time; only the binary search on the cut meets it (log(min(m, n)) is never bigger than log(m + n)).

10 ⚠️ Common Mistakes

  • Forgetting that an even total needs the average of two middle numbers.
  • Using integer division for the average in C++/Java: write / 2.0 to keep the .5.
  • Binary searching the longer array: the second index j can then become negative.
  • Not handling empty arrays or cuts at the edges (use -infinity / +infinity sentinels).
  • Off-by-one in the 'left half size': (m + n + 1) / 2 makes the left side hold the extra element when the total is odd.

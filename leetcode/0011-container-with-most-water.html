Medium   Topics: Array, Two Pointers, Greedy

You are given an integer array height of length n. Picture n vertical lines standing on a flat floor: line i goes from the point (i, 0) up to the point (i, height[i]).

Choose any two lines. Together with the floor they form a container. Find the container that holds the most water and return that amount. The container cannot be tilted, and the lines themselves are infinitely thin.

2 💡 Examples and Constraints

Example 1

Input: height = [1,8,6,2,5,4,8,3,7]
Output: 49
Explanation: The best pair is the line of height 8 at index 1 and the line of height 7 at index 8. The width is 8 - 1 = 7 and the water level is limited by the shorter line, 7, so the area is 7 * 7 = 49.

Example 2

Input: height = [1,1]
Output: 1
Explanation: There are only two lines. The width is 1 and the shorter height is 1, so the area is 1.

📖 Example breakdown (Example 1), step by step
  • The lines have heights [1,8,6,2,5,4,8,3,7] at positions 0 to 8.
  • Start wide: line 0 (height 1) and line 8 (height 7). Width 8, level = the shorter line = 1, so the area is 8 * 1 = 8.
  • The left line is shorter, so move the left pointer inward to line 1 (height 8). Now the pair is (8, 7): width 7, level 7, area 7 * 7 = 49. That is the biggest value we ever see.
  • The right line (7) is now the shorter one, so we keep moving the right pointer and measure smaller and smaller widths, but none of the later pairs beats 49.
  • Result: 49 ✅ (the expected output of Example 1)

⚠️ Constraints

  • n == height.length
  • 2 <= n <= 105
  • 0 <= height[i] <= 104

3 🧠 How to Think About It (in Easy Words)

Imagine two walls and a floor between them. Water can only rise up to the lower wall, because it would spill over it. So the water held is width x lower wall. Trying every pair of walls works but is slow. The clever idea starts with the two walls that are farthest apart (the widest container) and then asks: which wall should I move? Moving the taller wall inward can never help (the width shrinks and the lower wall is still the same or lower), so always move the shorter wall and hope for a taller one.

Below you will find 3 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 🚀 Approach 1: Brute Force: Try Every Pair of Lines

Brute force

💡 Intuition

For every pair of lines (i, j) with i < j, compute the water min(height[i], height[j]) * (j - i) and remember the biggest value.

Try every possible pair of walls in a swimming-pool catalogue and measure each pool.

🪜 Algorithm, Step by Step

  1. Set best = 0.
  2. For every first line i, look at every line j to its right.
  3. Compute min(height[i], height[j]) * (j - i) (shorter line times distance).
  4. Keep the biggest value and return it at the end.

⏱️ Complexity

CostWhy
TimeO(n2)two nested loops look at about n * (n - 1) / 2 pairs
SpaceO(1)only a few number variables
Good sideWeak side
Very easy to write and to trust.With n = 100,000 lines that is about five billion pairs: far too slow.

💻 Code

class Solution {
public:
    int maxArea(vector<int>& height) {
        int n = height.size(), best = 0;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                int area = min(height[i], height[j]) * (j - i);   // water level = shorter line, width = distance
                best = max(best, area);
            }
        }
        return best;
    }
};

5 🚀 Approach 2: Two Pointers: Start Wide, Move the Shorter Line

Optimized

💡 Intuition

Put one pointer on the first line and one on the last line. Measure the container. Then move the pointer that stands on the shorter line one step inward. Repeat until the pointers meet.

Two people hold the ends of a rope against two walls and walk towards each other. The person at the lower wall is the weak link, so that person must move to find a higher wall.

🪜 Algorithm, Step by Step

  1. Put left on the first line and right on the last line; set best = 0.
  2. Compute the area of the current pair and update best.
  3. Move the pointer that stands on the shorter line one step inward (if both are equal, either one).
  4. Repeat until the pointers meet and return best.

⏱️ Complexity

CostWhy
TimeO(n)every step moves one pointer inward, so there are at most n - 1 steps
SpaceO(1)only two pointers and a best value
Good sideWeak side
One pass, no extra memory. This is the answer interviewers expect.It is not obvious why moving the shorter line is safe: you must be able to explain it.

💻 Code

class Solution {
public:
    int maxArea(vector<int>& height) {
        int left = 0, right = (int)height.size() - 1, best = 0;
        while (left < right) {
            int area = min(height[left], height[right]) * (right - left);
            best = max(best, area);
            if (height[left] < height[right]) left++;          // the shorter line limits the water: try a taller one
            else right--;
        }
        return best;
    }
};

6 🚀 Approach 3: Two Pointers That Skip Useless Lines (Most Optimized)

Most optimized

💡 Intuition

Same walk as before, but after measuring a container of level h, move past every line that is not taller than h on both sides. Such a line gives a narrower container with a level of at most h, so it can never beat what we just measured.

Instead of stepping over one short wall at a time, jump over the whole fence of walls that are no better than the one you just tested.

🪜 Algorithm, Step by Step

  1. Start with the two outer pointers and best = 0.
  2. Measure the current pair; its level is the shorter height level.
  3. Move left right while its line is not taller than level, and move right left while its line is not taller than level.
  4. Repeat while left < right; return best.

⏱️ Complexity

CostWhy
TimeO(n)every step moves at least one pointer, so there are still at most n - 1 steps
SpaceO(1)only two pointers and a best value
Good sideWeak side
Same worst case but often much fewer area computations (it skips obviously bad lines in one go).Slightly more code and two extra inner loops to explain.

💻 Code

class Solution {
public:
    int maxArea(vector<int>& height) {
        int left = 0, right = (int)height.size() - 1, best = 0;
        while (left < right) {
            int level = min(height[left], height[right]);
            best = max(best, level * (right - left));
            while (left < right && height[left] <= level) left++;      // lines not taller than 'level' cannot do better
            while (left < right && height[right] <= level) right--;
        }
        return best;
    }
};

8 🔑 Key Insights

  • The shorter line decides the water level. That is why the area is min(heights) * width.
  • Why moving the shorter line is safe: if you moved the taller one instead, the width would shrink and the level could not rise above the shorter line, so the new area could only be smaller or equal. Moving the shorter one is the only move that can help.
  • With n = 100,000 lines the brute force checks 4,999,950,000 pairs; the two-pointer walk makes fewer than 100,000 steps.
  • On the example the skipping version computes only 3 areas, the plain two-pointer version 8: skipping lines that cannot help saves work (but both are O(n)).

10 ⚠️ Common Mistakes

  • Using the taller line for the water level: water spills over the shorter wall, so the level is the minimum.
  • Forgetting the width: the area is the level times the distance between the lines, not just the level.
  • Moving the taller pointer inward: the width shrinks and the level cannot go up, so nothing is gained.
  • Using height[left] <= height[right] or < does not matter for correctness, but moving both pointers every step does: you may skip the best pair.
  • Thinking you must compare every pair: the two-pointer argument proves the pairs you skip are never better.

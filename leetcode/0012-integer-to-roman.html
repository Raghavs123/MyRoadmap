Medium   Topics: Hash Table, Math, String

Roman numerals use seven letters: I = 1, V = 5, X = 10, L = 50, C = 100, D = 500 and M = 1000. A number is written by putting letters next to each other and adding their values, starting with the biggest letter. There are two extra rules:

  • A letter is repeated at most three times in a row, so 3 is III but 4 is not IIII.
  • Six subtractive pairs are used instead: IV = 4, IX = 9, XL = 40, XC = 90, CD = 400 and CM = 900.

Given an integer num, return its Roman numeral as a string.

2 💡 Examples and Constraints

Example 1

Input: num = 3749
Output: MMMDCCXLIX
Explanation: 3000 = MMM, 700 = DCC, 40 = XL, 9 = IX. Put them together: MMM + DCC + XL + IX.

Example 2

Input: num = 58
Output: LVIII
Explanation: 50 = L, 5 = V, 3 = III.

Example 3

Input: num = 1994
Output: MCMXCIV
Explanation: 1000 = M, 900 = CM, 90 = XC, 4 = IV.

📖 Example breakdown (Example 1), step by step
  • The number is 3749. We pay it with the biggest values that fit, from 1000 downwards.
  • 1000 fits three times: write MMM (3000), 749 is left.
  • 900 and 500: 500 fits once: write D, 249 is left. 400 does not fit, 100 fits twice: write CC, 49 is left.
  • 90 does not fit, 50 does not fit, 40 fits once: write XL, 9 is left. 9 fits once: write IX, 0 is left.
  • Put the pieces in order: MMM + D + CC + XL + IX.
  • Result: MMMDCCXLIX ✅ (the expected output of Example 1)

⚠️ Constraints

  • 1 <= num <= 3999

3 🧠 How to Think About It (in Easy Words)

Think of paying an amount with coins of value 1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4 and 1 (the special pairs are just extra coins). Always pay with the biggest coin that still fits, as often as it fits. That is the greedy method. Another way: the thousands, hundreds, tens and ones digits are independent, so write each digit with its own little table.

Below you will find 2 approaches, from the simplest (brute force) to the best. Each one has the idea in plain words, its speed and memory cost, the code in C++, Java and Python (click the tabs; your choice is remembered), and a step-by-step dry run on a small input.

4 🚀 Approach 1: Greedy: Subtract the Biggest Value That Fits

Optimized

💡 Intuition

Keep two lists in the same order: the 13 values from 1000 down to 1 and their symbols (including the six subtractive pairs). Go through the list; while the number is at least the current value, subtract it and append its symbol.

Paying with the biggest coins first, like giving change.

🪜 Algorithm, Step by Step

  1. Keep two lists in the same order: the 13 values from 1000 down to 1, and their symbols.
  2. Go through the lists from the biggest value to the smallest.
  3. While the number is at least the current value, subtract the value and append its symbol.
  4. When the number reaches 0 return the text.

⏱️ Complexity

CostWhy
TimeO(1) (at most 13 steps of bounded repeats)the list has a fixed size of 13 and every value is used at most 3 times (the largest answer, 3888, has 15 letters)
SpaceO(1)a fixed list of 13 values and symbols, plus the answer of at most 15 letters
Good sideWeak side
Short, easy to explain, and the two lists make the special pairs just ordinary entries.You must remember all 13 values in the right order.

💻 Code

class Solution {
public:
    string intToRoman(int num) {
        int values[] = {1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1};
        string symbols[] = {"M", "CM", "D", "CD", "C", "XC", "L", "XL", "X", "IX", "V", "IV", "I"};
        string result;
        for (int i = 0; i < 13; i++) {
            while (num >= values[i]) {                         // the biggest value that still fits
                num -= values[i];
                result += symbols[i];
            }
        }
        return result;
    }
};
class Solution {

class Solution:
    def intToRoman(self, num: int) -> str:
        values = [1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1]
        symbols = ["M", "CM", "D", "CD", "C", "XC", "L", "XL", "X", "IX", "V", "IV", "I"]
        result = []
        for value, symbol in zip(values, symbols):
            while num >= value:                         # the biggest value that still fits
                num -= value
                result.append(symbol)
        return "".join(result)

5 🚀 Approach 2: Table Lookup: One Small Table per Digit (Most Optimized)

Most optimized

💡 Intuition

Split the number into thousands, hundreds, tens and ones. Each place has its own table of the 10 possible digit writings (for example the tens table is "", X, XX, XXX, XL, L, LX, LXX, LXXX, XC). Look up each digit and glue the four pieces together.

Four little dictionaries, one for each place of the number. Look the digit up and copy the answer.

🪜 Algorithm, Step by Step

  1. Prepare four tables with the 10 ways to write a digit in the thousands, hundreds, tens and ones place.
  2. Split the number: num / 1000, num % 1000 / 100, num % 100 / 10 and num % 10.
  3. Look up each digit in its own table.
  4. Join the four pieces from the thousands to the ones.

⏱️ Complexity

CostWhy
TimeO(1)four table lookups and three string joins, independent of the size of the number
SpaceO(1)four small fixed tables
Good sideWeak side
No loop at all: four array reads and string joins.Needs four hand-typed tables, so a typo is easy to make.

💻 Code

class Solution {
public:
    string intToRoman(int num) {
        static const string thousands[] = {"", "M", "MM", "MMM"};
        static const string hundreds[] = {"", "C", "CC", "CCC", "CD", "D", "DC", "DCC", "DCCC", "CM"};
        static const string tens[] = {"", "X", "XX", "XXX", "XL", "L", "LX", "LXX", "LXXX", "XC"};
        static const string ones[] = {"", "I", "II", "III", "IV", "V", "VI", "VII", "VIII", "IX"};
        return thousands[num / 1000] + hundreds[num % 1000 / 100] + tens[num % 100 / 10] + ones[num % 10];
    }
};

7 🔑 Key Insights

  • The six subtractive pairs are just extra coins (900, 400, 90, 40, 9, 4), so the greedy method needs no special cases.
  • No answer is longer than 15 letters: the longest numeral for 1 to 3999 is MMMDCCCLXXXVIII (3888), so the work is constant.
  • Every number from 1 to 3999 was converted by both approaches in the tests and checked against the independent reference.

9 ⚠️ Common Mistakes

  • Leaving out the subtractive pairs (CM, CD, XC, XL, IX, IV) and writing IIII for 4 or VIIII for 9.
  • Putting the values in the wrong order in the greedy lists: they must go from biggest to smallest, with each pair (like 900) between its neighbours (1000 and 500).
  • Using if instead of while in the greedy method: 3000 needs the value 1000 three times.
  • A typo in one of the four lookup tables: test numbers such as 4, 9, 40, 90, 400 and 900.
  • Mixing up the order of the pieces: thousands first, then hundreds, tens and ones.

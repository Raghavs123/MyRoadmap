2 How to Use These Pages

  1. Read the problem and the examples. Try to solve it yourself for 15 to 20 minutes.
  2. Read How to think about it (a daily-life picture of the idea).
  3. Read the approaches in order: brute force first. Click C++, Java or Python to switch the code (the page remembers your choice).
  4. Follow the dry run table with the code beside it, line by line.
  5. Close the page and write the best approach from memory in the language you use in interviews.
Each problem has the same layout: statement → examples → constraints → thinking → approaches → comparison → test report → common mistakes → related problems.

3 Honest Notes

  • Problem statements are written in my own words (same task, examples and constraints) because LeetCode's text is their copyright. Each page links to the official problem for the exact wording.
  • These solutions were not submitted to LeetCode (I have no way to log in or submit from here), so I do not claim 'Accepted'. They were compiled and run on the same hundreds of tests in all three languages (LeetCode's examples, edge cases, random cross-checks, and maximum-size inputs). Each test report shows the real numbers.
  • LeetCode's judge, compiler versions, time limits and hidden tests differ from mine; paste a solution there to confirm.
  • Two machines were used. Problems 1-5 were tested on 14 November 2026 (C++ with Clang 22 via Zig, JDK 25.0.5, Python 3.12). Problems 6-10 were tested on 16 November 2026 on a new machine (C++ with g++ 15.2.0, JDK 25.0.1, Python 3.14.2); each test report names its tools. Timings from the two machines must not be compared with each other.
  • Constraints are written from my knowledge of the problems on the date above: check the official page if you need to be sure.

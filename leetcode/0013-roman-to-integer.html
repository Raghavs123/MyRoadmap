Easy   Topics: Hash Table, Math, String

Roman numerals use the letters I = 1, V = 5, X = 10, L = 50, C = 100, D = 500 and M = 1000. They are normally written from the biggest letter to the smallest and the values are added. But six times a smaller letter stands in front of a bigger one and is then subtracted: IV = 4, IX = 9, XL = 40, XC = 90, CD = 400, CM = 900.

Given a Roman numeral s, return the integer it stands for.

2 💡 Examples and Constraints

Example 1

Input: s = "III"
Output: 3
Explanation: Three ones: 1 + 1 + 1 = 3.

Example 2

Input: s = "LVIII"
Output: 58
Explanation: L = 50, V = 5, III = 3, so 50 + 5 + 3 = 58.

Example 3

Input: s = "MCMXCIV"
Output: 1994
Explanation: M = 1000, CM = 900, XC = 90, IV = 4, so 1000 + 900 + 90 + 4 = 1994.

📖 Example breakdown (Example 3), step by step
  • MCMXCIV is read as M, CM, XC, IV.
  • M = 1000. C comes before M and is smaller, so it is subtracted: CM = 1000 - 100 = 900.
  • X comes before C: XC = 100 - 10 = 90. I comes before V: IV = 5 - 1 = 4.
  • Add everything: 1000 + 900 + 90 + 4.
  • Result: 1994 ✅ (the expected output of Example 3)

⚠️ Constraints

  • 1 <= s.length <= 15
  • s contains only the characters 'I', 'V', 'X', 'L', 'C', 'D', 'M'
  • It is guaranteed that s is a valid Roman numeral in the range [1, 3999].

3 🧠 How to Think About It (in Easy Words)

Read the numeral like a shopping bill. Normally every letter adds its value. The only surprise is a small letter in front of a bigger one (IV, IX, XL ...): then the small letter is taken away instead of added. So the rule for each letter is: if the letter after me is bigger, subtract me; otherwise add me. You can also read the numeral from the right: if the letter is smaller than the one you just read to its right, subtract it.

4 🚀 Approach 1: Rewrite the Six Special Pairs, Then Add Everything

Brute force

💡 Intuition

Replace each subtractive pair by plain additions of the same value (for example IV becomes IIII and CM becomes DCCCC). After that there are no special cases: add up the value of every letter.

Translate the strange abbreviations into the long form first, then simply add.

🪜 Algorithm, Step by Step

  1. Replace each of the six subtractive pairs by an addition of the same value (IV becomes IIII, CM becomes DCCCC, ...).
  2. Now no letter is in front of a bigger letter.
  3. Add the value of every letter.

⏱️ Complexity

CostWhy
TimeO(n)six replacement passes and one addition pass, each linear in the length (at most 15 letters)
SpaceO(n)the rewritten copy of the text is a little longer than the input
Good sideWeak side
Very easy to understand: after the rewrite it is just a sum.Makes a longer copy of the text and does six passes over it.

💻 Code

class Solution {
    int value(char c) {
        switch (c) {
            case 'I': return 1;    case 'V': return 5;    case 'X': return 10;   case 'L': return 50;
            case 'C': return 100;  case 'D': return 500;  default:  return 1000;  // 'M'
        }
    }
    void replaceAll(string& text, const string& from, const string& to) {
        size_t pos = 0;
        while ((pos = text.find(from, pos)) != string::npos) {
            text.replace(pos, from.size(), to);
            pos += to.size();
        }
    }
public:
    int romanToInt(string s) {
        replaceAll(s, "IV", "IIII");   replaceAll(s, "IX", "VIIII");
        replaceAll(s, "XL", "XXXX");   replaceAll(s, "XC", "LXXXX");
        replaceAll(s, "CD", "CCCC");   replaceAll(s, "CM", "DCCCC");
        int total = 0;
        for (char c : s) total += value(c);                    // no special cases are left: just add
        return total;
    }
};

5 🚀 Approach 2: Look at the Next Letter: Subtract if It Is Bigger

Optimized

💡 Intuition

Go from left to right. For each letter compare its value with the value of the letter after it. If the next one is bigger, this letter is the small one of a special pair, so subtract it; otherwise add it.

At every step you peek at the next coin: if it is bigger, the current one is a discount.

🪜 Algorithm, Step by Step

  1. Start with total = 0 and go through the letters from left to right.
  2. Look at the value of the current letter and of the next letter (if there is one).
  3. If the next letter is bigger, subtract the current value; otherwise add it.
  4. Return the total.

⏱️ Complexity

CostWhy
TimeO(n)one pass over at most 15 letters
SpaceO(1)a few number variables
Good sideWeak side
One pass, no copy of the text, and the rule is the exact meaning of Roman numerals.You must not read past the end of the string: the last letter is always added.

💻 Code

class Solution {
    int value(char c) {
        switch (c) {
            case 'I': return 1;    case 'V': return 5;    case 'X': return 10;   case 'L': return 50;
            case 'C': return 100;  case 'D': return 500;  default:  return 1000;  // 'M'
        }
    }
public:
    int romanToInt(string s) {
        int total = 0;
        for (size_t i = 0; i < s.size(); i++) {
            int current = value(s[i]);
            if (i + 1 < s.size() && current < value(s[i + 1])) total -= current;   // small letter before a bigger one
            else total += current;
        }
        return total;
    }
};

                total -= current
            else:
                total += current
        return total

6 🚀 Approach 3: Read from the Right: Subtract a Letter Smaller Than the Previous One

Most optimized

💡 Intuition

Walk from the last letter to the first and remember the value of the letter you just read. If the current letter is smaller than the previous one (the one to its right), subtract it; otherwise add it. No peeking ahead and no bounds check is needed.

Reading the bill backwards: when the price goes down compared to the item on its right, it is a discount.

🪜 Algorithm, Step by Step

  1. Start with total = 0 and previous = 0; go from the last letter to the first.
  2. If the current value is smaller than previous (the letter on its right), subtract it; otherwise add it.
  3. Remember the current value as the new previous.
  4. Return the total.

⏱️ Complexity

CostWhy
TimeO(n)one pass over at most 15 letters
SpaceO(1)a few number variables
Good sideWeak side
The shortest loop: no index check for 'is there a next letter?'.Reading right to left feels unusual at first, and you must use smaller than (not smaller or equal), or II would break.

💻 Code

class Solution {
    int value(char c) {
        switch (c) {
            case 'I': return 1;    case 'V': return 5;    case 'X': return 10;   case 'L': return 50;
            case 'C': return 100;  case 'D': return 500;  default:  return 1000;  // 'M'
        }
    }
public:
    int romanToInt(string s) {
        int total = 0, previous = 0;                           // previous = value of the letter on the right
        for (int i = (int)s.size() - 1; i >= 0; i--) {
            int current = value(s[i]);
            if (current < previous) total -= current;          // smaller than its right neighbour: subtract
            else total += current;
            previous = current;
        }
        return total;
    }
};

class Solution:
    def romanToInt(self, s: str) -> int:
        value = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}
        total, previous = 0, 0                          # previous = value of the letter on the right
        for letter in reversed(s):
            current = value[letter]
            if current < previous:                      # smaller than its right neighbour: subtract
                total -= current
            else:
                total += current
            previous = current
        return total

8 🔑 Key Insights

  • A small letter in front of a bigger one is subtracted, everything else is added. That one sentence is the whole problem.
  • Reading from the right removes the need to peek at the next letter, so there is no index check at all.
  • When reading from the right you must test smaller than, not smaller or equal: in III all three letters are equal and must all be added.
  • The inverse problem (Integer to Roman) and this one were tested together: every number from 1 to 3999 survives the round trip.

10 ⚠️ Common Mistakes

  • Always adding every letter: IV would become 6 instead of 4.
  • Reading past the end of the string when you peek at the next letter: check i + 1 < length first.
  • Using smaller or equal when reading from the right: in III the equal letters would be subtracted and the answer would be wrong.
  • Replacing pairs in the wrong order or with the wrong long form (for example CM must become DCCCC, which is 500 + 400).
  • Forgetting that only six pairs are allowed: you do not need to handle things like IL because the input is always valid.

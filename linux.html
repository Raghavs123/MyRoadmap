1 What is Linux? (The 10-Second Answer)

Linux is a free, open-source operating system kernel — the core program that lets software talk to a computer's hardware. Together with tools and programs around it (called a distribution), it becomes a complete operating system, just like Windows or macOS.
Daily-life picture: Think of a school. The kernel is the principal's office: it decides who may use the classrooms (CPU), the library (memory) and the playground (disk), and it keeps everyone from fighting over them. The shell is the front desk where you ask for things in words. The programs are the teachers and clubs. Linux is the principal's office; a distribution packs the whole school together so it is ready to use.

Linux was started in 1991 by a Finnish student, Linus Torvalds, as a hobby, and today it runs most of the internet's servers, every Android phone, the world's fastest supercomputers, routers, smart TVs, cars and the clouds of every big company.

Your very first commands (run for real)

first_commands.sh 

echo "Hello, Linux!"
pwd                       # where am I?
date +"%A %d %B %Y"       # what day is it?
uname -sr                 # which OS and kernel?
echo "Shell: $(ps -p $$ -o comm=)"
echo "2 + 3 = $((2 + 3))"

# ----- Output (real run) -----

# /tmp/work
# Tuesday 03 November 2026
# Linux 6.18.33.2-microsoft-standard-WSL2
# Shell: bash

echo prints text. pwd means "print working directory" — where am I? date shows the date (the +"%A %d %B %Y" part is a format recipe). uname -sr prints the kernel's name and version. $((2 + 3)) lets the shell do arithmetic. Everything after a # is a comment for humans.

7 How Linux Thinks: "Everything Is a File"

Linux (like Unix) follows a few simple, powerful ideas. Understand these and the rest feels logical:

📄 Everything is a file

Documents, folders, keyboards, disks, even running programs and the CPU's information appear as files you can read or write with the same tools (/dev, /proc, /sys).

🧩 Small tools, one job each

sort sorts, grep searches, wc counts. Combine them with pipes like LEGO bricks.

🔗 Text is the universal language

Tools exchange plain text, so any tool can feed any other. Config files are text, so you can read and edit them.

👥 Many users, strict ownership

Every file has an owner and permissions; ordinary users cannot break the system.

🪆 Processes

Every running program is a process with an ID, a parent and its own memory; the kernel schedules them.

🌳 One tree, one root

All storage appears under a single tree starting at /; there are no drive letters like C:.

Wildcards (called globbing) are expanded by the shell before the command runs: * = any characters, ? = exactly one character, [ab] = one of a or b. ls *.log found all three logs, a?.log matched only a1 and a2. {1..3} expands to 1 2 3. The tree shows we renamed notes.txt to ideas.txt (a move inside the same folder is a rename) and tucked todo.bak into archive/2026.

Safety trick: before a risky rm *.log, run ls *.log first — the wildcard matches exactly the same files, so you see what would be deleted.

39 Safe, Robust Scripts

By default bash keeps going after errors, which can turn a small mistake into a disaster (cd /wrong/folder; rm -rf *). Add a safety belt at the top of every serious script:

#!/bin/bash
set -euo pipefail     # -e stop on error · -u error on unset variables · -o pipefail: a pipeline fails if any stage fails
IFS=$'\n\t'           # safer word splitting
set -euo pipefail, trap cleanup and getopts (run for real) 

cat > safe.sh <<'EOF'
#!/bin/bash
set -euo pipefail                  # stop on errors, undefined variables and pipe failures
tmp=$(mktemp -d)
cleanup() { rm -rf "$tmp"; echo "cleaned up $tmp" | sed 's|/tmp/.*|<tmpdir>|'; }
trap cleanup EXIT                  # always runs, even on failure
echo "working in a temporary folder"
echo "step 1 ok"
false                              # this fails -> the script stops here
echo "step 2 (never printed)"
EOF
bash safe.sh; echo "script exit status: $?"
echo "--- without 'set -e' the script would carry on:"
bash -c 'false; echo "...and keeps going after a failure"'
echo "--- undefined variable protection"
bash -c 'set -u; echo "$not_defined"' 2>&1 | sed 's/^bash: line 1: //'
echo "--- pipefail: the pipeline fails if ANY stage fails"
bash -c 'false | cat; echo "without pipefail status=$?"'
bash -c 'set -o pipefail; false | cat; echo "with pipefail status=$?"'
echo "--- parse options with getopts"
cat > opts.sh <<'EOF'
#!/bin/bash
verbose=0; name="world"
while getopts "vn:" opt; do
  case $opt in v) verbose=1 ;; n) name=$OPTARG ;; *) exit 2 ;; esac
done
[ $verbose -eq 1 ] && echo "(verbose mode)"
echo "Hello, $name"
EOF
bash opts.sh -v -n Asha

# with pipefail status=1

55 Troubleshooting Playbook

Good admins don't guess; they work through a ladder from "is it even on?" to "why is it slow?". Use this order:

  1. Read the error message literally (Section 65 decodes the common ones).
  2. What changed? A recent update, config edit, disk full, certificate expiry? (grep -i install /var/log/dpkg.log | tail, git log for config repos.)
  3. Is it running? systemctl status X, ps aux | grep X.
  4. Logs: journalctl -u X -e, /var/log/…, dmesg -T | tail.
  5. Resources: df -h (disk), df -i (inodes), free -h (memory), uptime (load).
  6. Network: ss -tlnp (is it listening?), curl -v localhost:PORT, DNS with dig, firewall rules.
  7. Permissions: ls -l, namei -l path, SELinux/AppArmor denials (journalctl | grep -i denied).
  8. Reproduce in the simplest way; change one thing at a time; write down what you tried.
  9. Search smartly: paste the exact error in quotes plus the distro/version.

61 Project 4 — A Service Health Monitor

Skills: background processes, curl status codes, exit codes, retries, decisions. Idea: check.sh URL succeeds only if the URL answers HTTP 200 within a few tries; other programs (cron, CI, systemd) can use its exit status.

check.sh (run for real)

echo "up" > index.html
cat > ../check.sh <<'EOF'
#!/bin/bash
# check.sh URL [TRIES] - succeeds (exit 0) when the URL answers 200, fails (exit 1) after TRIES attempts
url="$1"; tries="${2:-3}"
for ((i=1; i<=tries; i++)); do
  code=$(curl -s -o /dev/null -m 2 -w '%{http_code}' "$url" || true)
  if [ "$code" = "200" ]; then echo "[ok]   $url answered 200 (attempt $i)"; exit 0; fi
  echo "[fail] $url -> HTTP ${code:-none} (attempt $i of $tries)"; sleep 0.5
done
exit 1
EOF

echo "== 3. a missing page =="
../check.sh http://127.0.0.1:8777/nothing 1; echo "exit status: $?"
kill $srv
echo "== 4. use the exit status in a decision =="

67 FAQ

Q: Is Linux hard to learn?

The terminal feels strange for a week or two, then becomes fast and powerful. Learn a few commands each day (this guide's Parts B–D), use Tab completion and man, and practise in a scratch folder. Everything builds on the same few ideas (Section 7).

Q: Which distribution should I start with?

Ubuntu LTS or Linux Mint for a gentle start; Fedora if you want newer software; Debian for stability. Beginners rarely regret Ubuntu because most tutorials assume it. Commands in this guide work on all major distros except the package manager (Section 41).

Q: Is Linux really free? How do companies earn money from it?

The software is free to use, study and share (open source). Companies earn from support, training, certifications, cloud services and enterprise subscriptions (e.g. Red Hat, Canonical, SUSE), and many hardware and cloud firms employ kernel developers.

Q: Do I need antivirus on Linux?

Desktop users rarely do — keep the system updated, install software from official repositories, and don't run unknown scripts. Servers benefit from hardening, updates, firewalls, log monitoring and backups (Section 50). Mail and file servers that handle files for Windows users may add scanners.

Q: What's the difference between Linux and Unix?

Unix is the family of operating systems that began at Bell Labs in 1969 (AIX, Solaris, BSD, macOS has Unix certification). Linux is a separate, Unix-like kernel written from scratch; it follows the same ideas and tools but isn't derived from Unix source code.

Q: Can I run Linux on Windows without dual booting?

Yes: WSL2 runs a real Linux kernel inside Windows (this guide's samples ran on WSL2). Virtual machines and live USB sticks are other safe options (Section 6).

Q: Why do people say "everything is a file"?

Linux exposes devices, processes, kernel settings and more as files or folders (/dev, /proc, /sys), so the same tools (cat, grep, redirection) work on them (Section 7 and 24).

Q: Should I use sudo for everything that says "permission denied"?

No. First understand why it was denied (ls -l, id). Use sudo only for tasks that need administrator rights, and never to dodge a permission problem in your own files — that can leave root-owned files in your home folder.

Q: How do I get good at the command line?

Use it daily for real tasks, read one man page a week, keep a personal notes file of commands, write small scripts for repeated jobs (Part E), do wargames like OverTheWire Bandit (resources), and review the projects in Part H.

Q: Are the new Rust tools in Ubuntu 26.04 going to break my scripts?

Everyday usage is compatible (our tests of ls, cat, sort and tr behaved the same), but small differences in rarely used options can exist. Test important scripts on 26.04 before upgrading production machines, and report differences upstream. Ubuntu kept GNU versions of some commands at release and lets you switch back (Section 56).

68 Interview Questions (With Answers) — The Complete Set

Grouped by category, easy → hard.

68.1 — Fundamentals

Q: What is Linux, and what is the difference between the kernel and a distribution?

Linux is an open-source kernel that manages hardware, processes, memory, files and networking. A distribution bundles the kernel with tools (shell, GNU/uutils utilities), a package manager, an installer and default software (Ubuntu, Fedora, Debian…).

Q: Explain the Linux directory structure.

One tree rooted at /. /etc configuration, /home user files, /var variable data and logs, /usr programs and libraries, /bin//sbin essential commands (links into /usr today), /tmp temporary files, /dev devices, /proc and /sys kernel interfaces, /boot kernel and boot loader, /opt optional software, /mnt//media mounts.

Q: What does "everything is a file" mean?

Hardware, processes and kernel state are presented through the filesystem and accessed with the same read/write operations. Examples: /dev/sda, /proc/cpuinfo, /dev/null, pipes and sockets.

Q: What is the difference between a shell, a terminal and a console?

The terminal is the window/device that shows text; the shell (bash, zsh) is the program interpreting commands inside it; the console is the physical or virtual (tty) terminal directly attached to the system.

Q: What are absolute and relative paths? What do ., .., ~ and - mean?

Absolute paths start at /; relative paths start at the current directory. . current dir, .. parent, ~ home directory, and cd - goes to the previous directory.

Q: Linux vs Unix vs Windows — key differences?

Linux is a Unix-like open-source kernel; Unix is the older family (proprietary and BSD variants); Windows uses a different kernel, drive letters, a registry and mostly GUI administration. Linux separates users strictly, treats paths case-sensitively and is heavily scriptable.

68.2 — Files, Permissions & Users

Q: Explain chmod 754 file.

7 = rwx for the owner, 5 = r-x for the group, 4 = r-- for others (read 4, write 2, execute 1). So the owner can read/write/execute, the group read/execute, others read only.

Q: What do the execute bit mean on a file versus a directory?

On a file it allows running it as a program. On a directory it allows entering it (cd) and accessing items inside by name; r lets you list names and w lets you create/delete entries.

Q: What are setuid, setgid and the sticky bit?

Setuid/setgid make a program run with its owner's/group's privileges (setgid on a directory makes new files inherit its group). The sticky bit on a directory (like /tmp) lets only a file's owner (or root) delete or rename it.

Q: Hard link vs symbolic link?

A hard link is another directory entry for the same inode (same data; survives deletion of the other name; same filesystem only; not for directories). A symbolic link is a separate file holding a path; it can cross filesystems and point to directories but dangles if the target disappears.

Q: What is an inode?

A filesystem structure storing a file's metadata (owner, permissions, size, timestamps, block pointers). Directory entries map names to inode numbers. You can run out of inodes (df -i) even with free space.

Q: What is umask?

A mask of permission bits removed from newly created files (base 666) and directories (base 777). A umask of 022 gives files 644 and directories 755; 077 gives 600/700.

Q: How do you give a user administrative rights safely?

Add them to the sudo (Debian/Ubuntu) or wheel group, or create a restricted rule in /etc/sudoers.d/ using visudo to allow only specific commands. Avoid sharing the root password and prefer SSH keys.

68.3 — Processes & System

Q: Difference between a process and a thread?

A process has its own address space and resources; threads are lightweight execution units inside a process that share its memory. In Linux both are scheduled as tasks and created with clone().

Q: What is a zombie process and how do you remove it?

A terminated process whose parent has not yet read its exit status, so it stays in the process table. It uses no CPU/memory; fix by making the parent call wait(), restarting/killing the parent (init then adopts and reaps the zombie).

Q: kill vs kill -9?

kill sends SIGTERM, which a process can catch to clean up. kill -9 sends SIGKILL, which cannot be caught or ignored, so no cleanup occurs; use it only if TERM fails.

Q: How do you find which process is using a port?

ss -tlnp | grep :80 or sudo lsof -i :80; then ps -p PID -o pid,cmd.

Q: What does load average mean?

The average number of tasks running or waiting (including uninterruptible I/O waits) over 1, 5 and 15 minutes. Compare it to the CPU count: load ≈ cores means fully used; much higher means queuing.

Q: What is the OOM killer?

When memory (and swap) is exhausted, the kernel selects and kills a process (by an "oom score") to free memory. Check dmesg -T | grep -i oom; fix with more memory, limits (cgroups), or by finding leaks.

Q: How do you run a command that survives logout?

Use tmux/screen (best), or nohup cmd &, or disown after backgrounding, or better: a systemd service/timer.

68.4 — Text Processing & Shell

Q: How do you count the number of unique IPs in a log?

awk '{print $1}' access.log | sort -u | wc -l. For the top talkers: awk '{print $1}' access.log | sort | uniq -c | sort -nr | head.

Q: grep vs sed vs awk?

grep selects lines matching a pattern; sed edits streams (substitute, delete, print ranges); awk processes records and fields with a small programming language (columns, arithmetic, grouping).

Q: What's the difference between >, >>, 2>&1 and |?

> overwrites a file with stdout, >> appends, 2>&1 sends stderr to wherever stdout goes, and | pipes stdout of one command into stdin of another.

Q: Explain single vs double quotes in bash.

Single quotes preserve everything literally; double quotes allow variable, command and arithmetic expansion but stop word splitting and globbing. Always double-quote variables: "$var".

Q: How do you delete files older than 30 days safely?

Preview: find /path -type f -mtime +30 -print; then find /path -type f -mtime +30 -delete (or -print0 | xargs -0 rm). Test on a copy and avoid running from the wrong directory.

Q: How do you replace a string in many files?

grep -rl 'old' dir | xargs sed -i 's/old/new/g' (preview with grep -rn; use -i.bak or version control to be able to undo).

68.5 — Shell Scripting

Q: What does set -euo pipefail do?

-e exit on any command failure, -u treat unset variables as errors, -o pipefail make a pipeline fail if any stage fails. Together they turn silent failures into early stops. Caveats: -e has exceptions (conditions, || lists), so still check critical steps explicitly.

Q: How do you pass arguments to a script and validate them?

Use $1…, "$@", $#; validate with tests or ${1:?usage …}; parse options with getopts (short) or a while/case loop (long options).

Q: What is the difference between $@ and $*?

Quoted "$@" expands to each argument as a separate word (preserving spaces); "$*" joins all arguments into a single word. Use "$@" almost always.

Q: How do you handle errors and clean up in a script?

Check exit statuses (if ! cmd; then …; fi), use set -e carefully, create temp files with mktemp and delete them in a trap 'cleanup' EXIT, and write errors to stderr with a non-zero exit code.

Q: How do you read a file line by line correctly?

while IFS= read -r line; do …; done < file — IFS= keeps leading spaces and -r stops backslash interpretation. Avoid for line in $(cat file), which splits on whitespace.

Q: When would you choose Python over bash?

When the logic gets complex (data structures, JSON/YAML, error handling, tests, many functions) or must run across platforms. Bash shines for gluing commands, pipelines and short automation.

68.6 — Networking & SSH

Q: How do you check which ports are listening and open one on a firewall?

ss -tulpn lists listening sockets with processes. Allow a port with sudo ufw allow 443/tcp (Ubuntu) or firewall-cmd --add-service=https --permanent (Red Hat). Remember cloud security groups too.

Q: How does SSH key authentication work?

The client holds a private key; the server stores the matching public key in authorized_keys. At login the server challenges the client to prove possession of the private key by signing data — the key never travels. Permissions must be strict (~/.ssh 700, private key 600).

Q: A server can't be reached. How do you debug?

Work down the layers: address (ip a), gateway (ping), internet by IP, DNS (dig), port reachability (nc -zv host 22), service listening (ss), firewall rules, logs (journalctl -u ssh), and use ssh -v.

Q: What's the difference between TCP and UDP, and which ports are well known?

TCP is connection-based and reliable (HTTP, SSH, databases); UDP is connectionless and lightweight (DNS queries, streaming, VoIP). Well-known: 22 SSH, 80/443 HTTP/HTTPS, 53 DNS, 25/587 SMTP.

Q: How do you securely copy files between servers?

scp or, better, rsync -avz -e ssh src/ user@host:/dst/ (resumable, only differences). For automation use SSH keys and restricted accounts.

68.7 — Administration & Systemd

Q: What is systemd and how do you manage a service?

systemd is PID 1: it starts services in parallel, supervises and logs them. Use systemctl start|stop|restart|status|enable --now and journalctl -u name. Services are described by unit files in /etc/systemd/system.

Q: Describe the Linux boot process.

Firmware (UEFI) → boot loader (GRUB) loads kernel + initramfs → kernel initialises hardware and mounts the real root → starts PID 1 (systemd) → systemd reaches the default target, starting services → login prompt or display manager.

Q: How do you install, update and remove software on Ubuntu/RHEL?

Ubuntu: sudo apt update && sudo apt install pkg, apt upgrade, apt remove|purge. RHEL/Fedora: sudo dnf install|upgrade|remove pkg. Prefer official repositories and verify third-party sources.

Q: What's the difference between cron and systemd timers?

Cron is simple time-based scheduling per user; systemd timers integrate with units, logging (journald), dependencies, randomised delays and "run missed jobs after downtime" (Persistent=true).

Q: What is LVM and why use it?

Logical Volume Manager abstracts storage into physical volumes → volume groups → logical volumes, allowing resizing, spanning disks and snapshots without repartitioning.

Q: How do you check disk usage and find what filled a disk?

df -h for the full filesystem, du -h --max-depth=1 / | sort -h and drill down, df -i for inodes, lsof +L1 for deleted-but-open files; clean logs/caches (journalctl --vacuum-size, apt clean).

Q: What is the difference between apt update and apt upgrade?

Update refreshes the package index (what is available); upgrade installs newer versions of already-installed packages. full-upgrade may also add or remove packages to resolve dependencies.

68.8 — Security

Q: How would you harden a new Linux server?

Update packages and enable automatic security updates; create a non-root sudo user; SSH keys only, no root login; firewall default-deny with only needed ports; disable unused services; enable AppArmor/SELinux; set strict permissions; centralise and monitor logs; fail2ban; backups; full-disk encryption for laptops.

Q: What is the difference between AppArmor and SELinux?

Both are mandatory access control. AppArmor uses path-based profiles per program (default on Ubuntu/Debian/SUSE, easier); SELinux labels every file and process and enforces policy rules (default on RHEL/Fedora, more granular and complex).

Q: Why are setuid programs a security concern, and how do you list them?

They run with their owner's (often root) privileges, so a bug can become privilege escalation. List with find / -perm -4000 -type f 2>/dev/null and compare with a known baseline.

Q: What should you do if you suspect a server was compromised?

Isolate it from the network (but preserve evidence), collect logs and volatile data, check logins (last, auth.log), processes and network connections, setuid files and cron jobs, rotate all credentials, then rebuild from a trusted image rather than "cleaning" it, and find the root cause.

Q: Why shouldn't you run curl … | sudo bash blindly?

It executes unreviewed remote code with full privileges; the content can change or be malicious (or the connection tampered with). Download first, read it, verify checksums/signatures, and run with least privilege.

68.9 — Scenarios, Containers & Modern Linux

Q: A script works in your terminal but not from cron. Why?

Cron's environment is minimal (short PATH, no profile, different working directory and shell). Use absolute paths, set PATH/variables in the script, redirect output to a log, and test with env -i.

Q: "No space left on device" but df -h shows free space. Why?

The filesystem may be out of inodes (df -i), reserved blocks may apply, a quota may be reached, or the free space is on a different mount point than the one being written.

Q: What are namespaces and cgroups, and how do they relate to containers?

Namespaces isolate what a process can see (pids, mounts, network, hostname, users); cgroups limit and account what it can use (CPU, memory, I/O). A container is a process (tree) in its own namespaces and cgroups, started from an image — sharing the host kernel, unlike a VM.

Q: Containers vs virtual machines?

VMs virtualise hardware and run full guest operating systems (stronger isolation, heavier, slower to start). Containers share the host kernel (lightweight, fast, higher density) but with a weaker isolation boundary.

Q: What is a "memory-safe" rewrite of core tools, and what changed in Ubuntu 26.04?

Rust rewrites avoid classes of memory bugs common in C. Ubuntu 26.04 LTS (23 April 2026) made sudo-rs and uutils coreutils the defaults (with GNU kept installed and a few commands such as cp, mv, rm still GNU at release, per press coverage). It also dropped the X.Org GNOME session and shipped on Linux 7.0.

Q: What does the Linux kernel release model look like?

Mainline releases roughly every 9–10 weeks (each preceded by release candidates, -rc), stable updates (x.y.z) fix bugs afterwards, and selected long-term (LTS) branches get fixes for years. As of Nov 2026: 7.3.1 stable, 7.4-rc1 mainline, with LTS branches 6.18, 6.12, 6.6 and older.

Q: How would you automate a nightly backup and make sure it works?

A script (tar/rsync/restic) with set -euo pipefail, checksums and retention; scheduled by cron or a systemd timer; logs to a file/journal; alerts on non-zero exit; off-site copy (3-2-1 rule); and a regular test restore (Project 3).

Q: How do you troubleshoot a slow server?

Check load (uptime), CPU (top), memory/swap (free, vmstat), disk I/O wait (iostat, vmstat wa), network (ss), then drill into the offending process (strace, lsof, /proc). Look for recent changes, runaway processes, full disks and OOM events.

69 Pitfalls & Checklist

🗑️ rm -rf accidents

No recycle bin. Preview with ls/find -print, quote variables, never run rm -rf "$DIR/" with an unset DIR (use set -u).

🔓 chmod 777

It "fixes" permission errors by removing security. Find the real owner/group problem instead.

🧪 sudo as a reflex

Creates root-owned files, hides mistakes, and magnifies typos. Understand first.

❝ Unquoted variables

Spaces and wildcards split or expand them. Always "$var".

📄 Overwriting with >

sort f > f empties the file. Write to a new file, then mv.

🔑 Weak SSH setup

Password logins and root login on the internet get brute-forced within minutes. Keys + firewall.

💾 Untested backups

A backup is real only after a successful restore test. 3-2-1.

🔄 Skipping updates

Most breaches use known, fixed bugs. Automate security updates; reboot for kernel fixes or use Livepatch.

📋 Pasting commands blindly

Read before you run. Especially curl | sudo bash and anything with dd, mkfs, rm.

📝 Windows line endings

Scripts edited on Windows can have CRLF and fail with "bad interpreter". Fix with dos2unix.

Before you put a Linux server on the internet:
  • ☐ Non-root admin user; SSH keys only; root login disabled
  • ☐ Firewall default-deny, only needed ports open (and checked from outside)
  • ☐ Automatic security updates enabled; reboot policy decided
  • ☐ Unused services disabled; AppArmor/SELinux enforcing
  • ☐ Logs rotated and monitored; alerts for failed logins and full disks
  • ☐ Backups automated, off-site, encrypted, with a tested restore
  • ☐ Time sync (chrony/systemd-timesyncd), correct time zone, hostname set
  • ☐ Secrets kept out of Git and shell history; permissions on keys 600
  • ☐ Documented how to rebuild it (script/Ansible/image), not "it just works on that box"

70 Quick Quiz 🎯

Click each question to reveal the answer.

Q1: Which folder holds system-wide configuration files?

/etc.

Q2: What permission does chmod 640 give?

Owner read+write (6), group read (4), others nothing (0): rw-r-----.

Q3: What does sort | uniq -c | sort -nr do?

Counts how often each line occurs and ranks them from most to least frequent (uniq only merges adjacent duplicates, so the first sort is needed).

Q4: A command returned exit status 127. What happened?

The shell could not find the command (not installed, typo, or not on the PATH).

Q5: Why did the symbolic link break but the hard link still work after deleting the original file?

The symlink stores the name of the original (now gone); the hard link is another name for the same inode, and the data stays until the last name is removed.

Q6: How do you make a script stop at the first error?

Add set -e (ideally set -euo pipefail) near the top, and use trap … EXIT for cleanup.

Q7: What are namespaces and cgroups used for in containers?

Namespaces isolate what a process can see (pids, network, mounts…); cgroups limit what it can use (CPU, memory, I/O).

Q8: Name two Rust-based tools that Ubuntu 26.04 LTS uses by default.

sudo-rs (the sudo command) and uutils coreutils (most basic commands like ls and cat).

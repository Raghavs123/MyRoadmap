Part A — Foundations

1 What is Python? (the 10-second answer)

Python is a free, general-purpose programming language known for being easy to read and write. You write instructions in something close to plain English, and the computer follows them.
A programming language is a way of giving very precise instructions to a very fast but very literal helper. Telling a person "make a sandwich" works; telling a computer needs every step spelled out. Python is like a polite, clear instruction language: if hungry: make_sandwich() reads almost like English.

With Python you can build websites, analyse data, automate boring tasks, control robots, create games, and train AI models — it's the most popular language for data science and AI, and a favourite first language for beginners.

5 How Python Runs Your Code

You write source code (text). Python turns it into a compact set of instructions called bytecode and a program called the interpreter (a virtual machine) carries them out, one at a time.

Fig 1 — From source to action. The interpreter that most people use is called CPython (written in C).

Like a recipe: the compiler turns your handwritten notes into a neat numbered card; the interpreter is the cook who follows the card one step at a time. If a step says "divide by zero", the cook stops and tells you exactly which step failed (that's the traceback).

Dynamic typing: a name can later point at a different type (x = 5 then x = "five") — Python checks types when the code runs. Strong typing: it won't silently mix incompatible things ("5" + 5 is an error).

Mutable vs immutable — the big idea

a = [1, 2]
b = a              # NOT a copy: b is a second NAME for the same list
b.append(3)
print("a =", a)
print("a is b:", a is b)

c = a.copy()       # a real, separate copy
c.append(4)
print("a =", a, "| c =", c)

# ----- Output (real run) -----
# a = [1, 2, 3]
# a is b: True
# a = [1, 2, 3] | c = [1, 2, 3, 4]
Two kids each hold a tag for the same toy box: if one adds a toy, the other sees it — same box. Numbers and strings are like a sealed gift: you can't change one, only get a new one.

Rules for names: letters, digits and underscores; can't start with a digit; case-sensitive (Age ≠ age); can't be a keyword like for or class.

Python 3.14: template strings (t-strings)

An f-string builds the final text immediately, so you can't intercept the inserted values. A t-string (prefix t) instead gives you a Template object that keeps the fixed text and the inserted values separate, so a library can safely escape them. It's the safe building block for HTML, SQL and shell commands (PEP 750). 

from string.templatelib import Template, Interpolation
import html

def safe_html(template: Template) -> str:
    parts = []
    for part in template:
        if isinstance(part, Interpolation):
            parts.append(html.escape(str(part.value)))   # escape ONLY the user-supplied bits
        else:
            parts.append(part)
    return "".join(parts)

user = "<script>alert('hi')</script>"
print(safe_html(t"<p>Hello {user}</p>"))

# ----- Output (real run) -----
# <p>Hello &lt;script&gt;alert(&#x27;hi&#x27;)&lt;/script&gt;</p>
Never build SQL, shell commands or HTML by pasting user input into an f-string — that's how injection attacks happen (Section 41). Use parameter placeholders, escaping helpers, or t-string-aware libraries.

Text encoding: text is stored as Unicode. From Python 3.15, open() without an encoding= uses UTF-8 everywhere (PEP 686) instead of the computer's local setting — but writing encoding="utf-8" explicitly is still good practice for older versions.

12 Pattern Matching — match / case

Added in Python 3.10, match checks a value against shapes and pulls pieces out at the same time. It's like a powerful if/elif for structured data.

def handle(command):
    match command.split():
        case ["go", direction]:
            return f"going {direction}"
        case ["pick", *items]:
            return f"picked {items}"
        case ["quit"]:
            return "bye"
        case _:
            return "unknown command"

for c in ("go north", "pick apple pear", "quit", "dance"):
    print(c, "->", handle(c))

point = (3, 0)
match point:
    case (0, 0): print("origin")
    case (x, 0): print("on the x-axis at", x)
    case (0, y): print("on the y-axis at", y)

# ----- Output (real run) -----
# go north -> going north
# pick apple pear -> picked ['apple', 'pear']
# quit -> bye
# dance -> unknown command
# on the x-axis at 3

case ["go", direction]:A 2-item list starting with "go" (captures the second as direction)
case ["pick", *items]:"pick" followed by any number of items

from dataclasses import dataclass

@dataclass
class Circle:
    r: float

@dataclass

    w: float
    h: float

def area(shape):

18 Scope & Closures — Who Can See Which Name?

Python looks up a name in this order — remembered as LEGB:

Fig 3 — Name lookup goes from the inside out. The first match wins.
x = "global"

    x = "enclosing"
    def inner():
        x = "local"
        return x
    return inner(), x

def counter():
    count = 0
    def step():
        nonlocal count               # change the enclosing variable

        return count
    return step

A closure is an inner function that remembers the variables around it even after the outer function has finished — in the example, step keeps its own private count.

Nested boxes with labels: you look for a label in the smallest box first, then the next bigger box, and so on. A closure is a little box that carries a note from the bigger box it came from.

20 Errors & Exceptions — When Things Go Wrong

An exception is Python's way of saying "something went wrong". If nobody handles it, the program stops and prints a traceback (a trail showing exactly where). You handle it with try/except.

Fig 4 — The try statement: an error jumps to the matching except; no error runs else; finally runs either way.
def divide(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print("cannot divide by zero")
        return None
    except TypeError as err:
        print("bad types:", err)
        return None
    else:
        print("division worked")      # runs only if no exception happened
        return result
    finally:
        print("done (always runs)")

print(divide(10, 2))
print(divide(1, 0))
print(divide(1, "x"))

23 Iterators & Generators — Lazy Sequences

An iterable is anything you can loop over (list, string, dict, file). An iterator hands out one item at a time with next() and remembers where it is. A generator is the easiest way to make one: a function that uses yield to pause and hand back a value, then resume later.

Fig 5 — Generators produce values lazily, so memory stays small even for enormous sequences.
def countdown(n):
    while n > 0:
        yield n               # pause here, hand back a value, resume later
        n -= 1

print(list(countdown(3)))

def fib():
    a, b = 0, 1
    while True:                # an infinite sequence, made lazily

Decorators — wrappers that add behaviour

A decorator is a function that takes a function and returns an upgraded version. @shout above a function is shorthand for greet = shout(greet). Typical uses: timing, logging, caching, access checks, retries. 

import functools

def shout(func):
    @functools.wraps(func)                 # keep the original name and docstring
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        return result.upper() + "!"
    return wrapper

@shout
def greet(name):
    """Say hello."""
    return f"hello {name}"

print(greet("ada"), greet.__name__, greet.__doc__)

@functools.lru_cache(maxsize=None)         # remember results
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(80))
print(fib.cache_info())

Easy wins, in order

  1. Use a better algorithm or data structure (a set instead of a list for lookups) — often 100× faster.

Part D — Concurrency & Internals

30 Threads, Processes & the GIL — Doing Many Things at Once

Modern programs often wait (for the internet, a disk, a database) or crunch numbers. Python offers three main ways to do several things "at once". Which one fits depends on whether you're waiting (I/O-bound) or calculating (CPU-bound).

Fig 6 — Three models of concurrency. Waiting-heavy work: threads or asyncio. Number-crunching: processes (or free-threading).

What is the GIL?

The Global Interpreter Lock is a rule inside standard CPython: only one thread at a time may run Python bytecode. It keeps the interpreter's memory management simple and safe, but it means ordinary threads can't use several CPU cores for pure-Python calculation. Threads still help a lot when they spend time waiting, because waiting releases the lock: 

from concurrent.futures import ThreadPoolExecutor
import time

def slow_io(n):
    time.sleep(0.2)                        # waiting releases the GIL, so threads overlap
    return n * n

start = time.perf_counter()
with ThreadPoolExecutor(max_workers=5) as pool:
    results = list(pool.map(slow_io, range(5)))
elapsed = time.perf_counter() - start
print(results, "| overlapped:", elapsed < 0.6)

# ----- Output (real run) -----
# [0, 1, 4, 9, 16] | overlapped: True

31 asyncio — One Cook, Many Pots

asyncio runs many tasks on a single thread. A task says await … when it has to wait; while it waits, the event loop runs another task. Nothing is truly simultaneous, but since most time is spent waiting, it feels (and measures) like everything happens at once. 

import asyncio, time

async def fetch(name, delay):
    await asyncio.sleep(delay)             # pretend this is a network call
    return f"{name} done after {delay}s"

async def main():
    start = time.perf_counter()
    results = await asyncio.gather(fetch("A", 0.3), fetch("B", 0.3), fetch("C", 0.3))
    elapsed = time.perf_counter() - start
    print(results)
    print("ran together (about 0.3s, not 0.9s):", elapsed < 0.6)

asyncio.run(main())

    def __init__(self, path):
        self.path = Path(path)
        self.items = json.loads(self.path.read_text(encoding="utf-8")) if self.path.exists() else []

    def add(self, title):
        self.items.append({"title": title, "done": False})
        self._save()

    def complete(self, index):
        try:
            self.items[index]["done"] = True
        except IndexError:
            raise ValueError(f"no task number {index}") from None
        self._save()

    def _save(self):
        self.path.write_text(json.dumps(self.items, indent=2), encoding="utf-8")

    def show(self):
        for i, item in enumerate(self.items):
            print(f"{i}. [{'x' if item['done'] else ' '}] {item['title']}")

44 Project 3 — Bank Accounts (OOP, inheritance, dataclasses, custom exceptions)

Skills: dataclass, inheritance, validation, a custom exception. Idea: model money safely — you can't withdraw more than you have.

bank.py (run for real) 
from dataclasses import dataclass, field

class InsufficientFunds(Exception):
    pass

@dataclass
class Account:
    owner: str
    balance: float = 0.0
    history: list = field(default_factory=list)

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("deposit must be positive")
        self.balance += amount
        self.history.append(("deposit", amount))

    def withdraw(self, amount):
        if amount > self.balance:
            raise InsufficientFunds(f"balance {self.balance}, tried {amount}")
        self.balance -= amount
        self.history.append(("withdraw", amount))

class Savings(Account):
    def add_interest(self, rate):
        self.deposit(round(self.balance * rate, 2))

acct = Savings("Mia", 100)
acct.deposit(50)
acct.add_interest(0.10)
print(acct.balance)
try:
    acct.withdraw(1000)
except InsufficientFunds as e:
    print("refused:", e)
print(acct.history)

# ----- Output (real run) -----
# 165.0
# refused: balance 165.0, tried 1000
# [('deposit', 50), ('deposit', 15.0)]

Savings inherits everything from Account and adds add_interest. The dataclass writes the constructor for us; field(default_factory=list) gives each account its own history list (remember the mutable-default trap!). Overdrawing raises InsufficientFunds with a clear message.

45 Project 4 — Retry Decorator & a Lazy Pipeline (decorators, generators)

Skills: decorators with arguments, closures, generator pipelines. Idea: retry flaky operations automatically; process data stage by stage without building giant lists.

pipeline.py (run for real) 
import functools, time

def retry(times):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except ConnectionError as e:
                    print(f"  attempt {attempt} failed: {e}")
            raise ConnectionError("all attempts failed")
        return wrapper
    return decorator

calls = {"n": 0}

@retry(times=3)
def flaky():
    calls["n"] += 1
    if calls["n"] < 3:
        raise ConnectionError("network blip")
    return "success"

print(flaky())

def read_lines(text):                    # generator pipeline: each stage is lazy
    for line in text.splitlines():
        yield line
def non_empty(lines):
    return (l for l in lines if l.strip())
def parse(lines):
    return (tuple(l.split(",")) for l in lines)

raw = "ada,36\n\nlinus,55\n"
print(list(parse(non_empty(read_lines(raw)))))

# ----- Output (real run) -----
#   attempt 1 failed: network blip
#   attempt 2 failed: network blip
# success
# [('ada', '36'), ('linus', '55')]

retry(times=3) returns a decorator, which returns a wrapper that catches ConnectionError and tries again — the function failed twice, then succeeded on attempt three. The three small generator functions form a pipeline: nothing runs until list(...) pulls values through, one line at a time, so even a gigabyte file would use almost no memory.

48 Project 7 — Doing Things at Once (threads vs asyncio)

Skills: ThreadPoolExecutor, asyncio.gather, measuring time. Idea: five jobs that each wait 0.2 s — how long do they take three different ways?

concurrency_race.py (run for real) 
import asyncio, time
from concurrent.futures import ThreadPoolExecutor

def wait_sync(n):
    time.sleep(0.2)
    return n

async def wait_async(n):
    await asyncio.sleep(0.2)
    return n

N = 5

t = time.perf_counter()
sequential = [wait_sync(i) for i in range(N)]
t_seq = time.perf_counter() - t

t = time.perf_counter()
with ThreadPoolExecutor(max_workers=N) as pool:
    threaded = list(pool.map(wait_sync, range(N)))
t_thr = time.perf_counter() - t

async def run_all():
    return await asyncio.gather(*(wait_async(i) for i in range(N)))
t = time.perf_counter()
asynced = asyncio.run(run_all())
t_asy = time.perf_counter() - t

print("same results:", sequential == threaded == asynced)
print(f"one after another : about {t_seq:.1f}s")
print(f"threads           : about {t_thr:.1f}s")
print(f"asyncio           : about {t_asy:.1f}s")

# ----- Output (real run) -----
# same results: True
# one after another : about 1.0s
# threads           : about 0.2s
# asyncio           : about 0.2s

52 FAQ

Q: Is Python good for beginners?

Yes. Its readable syntax, friendly error messages, instant feedback in the REPL and the huge amount of learning material make it one of the most common first languages. You can build something useful (a script, a small web app, a data analysis) within weeks.

Q: Python 2 or Python 3?

Only Python 3. Python 2 reached end of life on 1 January 2020 and no longer receives any fixes. Use a currently supported 3.x release (3.11–3.15 as of late Oct 2026; 3.10 reached end of life on 1 Oct 2026).

Q: Which Python version should I install?

For a new project, the newest or second-newest release your key libraries support — today 3.14 or 3.15. Older projects can stay on 3.11–3.13 while those get security fixes. Check the support table in Section 3.

Q: Is Python slow?

Pure-Python loops are slower than compiled languages, but most real programs spend their time waiting or inside fast libraries (NumPy, Polars, databases). Python also keeps getting faster (new interpreter optimisations, an experimental JIT, free-threading), and you can move hot spots to Rust/C when profiling proves a need.

Q: What's the GIL and should I worry?

The Global Interpreter Lock lets only one thread run Python code at a time in the standard build. It rarely matters for waiting-heavy programs (threads/asyncio work fine); for CPU-heavy parallel work use processes, vectorised libraries, or a free-threaded build (officially supported since 3.14).

Q: pip, venv, uv, conda — which one?

Any of them can work. In 2026 many new projects use uv (fast, all-in-one, with pyproject.toml and a lockfile). pip + venv is the built-in baseline; conda/pixi are common in data science when you need non-Python binaries. Whichever you pick, use one virtual environment per project.

Q: Why do I get "ModuleNotFoundError" after installing a package?

Almost always because it was installed into a different Python environment than the one running your code. Activate the right virtual environment (or use uv run), and install with python -m pip install … so pip matches that interpreter.

Q: Do I need type hints?

Not to run code — Python ignores them at run time. But they make larger programs much easier to understand and let editors and checkers (mypy, Pyright, ty) catch bugs early. A good habit: add them to function signatures in anything you'll maintain.

Q: Will AI tools make learning Python pointless?

No. AI assistants write a lot of Python, but you still need to read, test, debug and judge it — and to describe problems precisely. Learning the fundamentals makes AI help far more useful and safer (always review generated code, especially anything touching files, networks or secrets).

53 Interview Questions (With Answers) — The Complete Set

Grouped by category, easy → hard.

53.1 — Basics

Q: What is Python, and what kind of language is it?

A high-level, general-purpose, dynamically typed, interpreted language that supports procedural, object-oriented and functional styles. Code is compiled to bytecode and run by a virtual machine (CPython).

Q: Mutable vs immutable types — examples and why it matters?

Mutable (list, dict, set, most classes) can be changed in place; immutable (int, float, str, tuple, frozenset, bool, frozendict in 3.15) cannot. It matters for aliasing (two names, one list), dictionary keys (must be hashable), default arguments, and thread safety.

Q: List vs tuple vs set vs dict?

List: ordered, mutable, allows duplicates. Tuple: ordered, immutable. Set: unordered unique items with fast membership. Dict: key→value mapping with fast lookup, insertion-ordered since 3.7.

Q: == vs is?

== compares values (via __eq__); is compares identity (same object). Use is for None/True/False; never rely on is for numbers or strings.

Q: What are truthy and falsy values?

Falsy: False, None, zero of any numeric type, and empty containers/strings. Everything else is truthy (unless a class defines __bool__ or __len__ otherwise).

Q: What is PEP 8?

The official style guide: 4-space indentation, snake_case names, CamelCase classes, line-length and import conventions. Tools like Ruff enforce it automatically.

53.2 — Functions & Scope

Q: What is the mutable default argument problem?

Default values are evaluated once at function definition, so a default list/dict is shared across calls. Use None and create the object inside the function.

Q: Explain *args and **kwargs.

*args collects extra positional arguments into a tuple; **kwargs collects extra keyword arguments into a dict. They're also used to unpack iterables/dicts at call sites.

Q: Explain LEGB and nonlocal/global.

Name lookup order: Local, Enclosing, Global, Built-in. global lets a function rebind a module-level name; nonlocal lets an inner function rebind a name in the nearest enclosing function.

Q: What is a closure?

An inner function that retains access to variables of its enclosing scope after that scope has finished, e.g., a counter factory.

Q: What is a lambda and when not to use it?

An anonymous single-expression function, handy for short keys (sorted(x, key=lambda p: p.age)). Avoid it for anything non-trivial; use a named def for readability and better tracebacks.

Q: Are arguments passed by value or reference in Python?

Neither exactly: "pass by object reference" (assignment). The function gets a new name bound to the same object, so mutating a mutable argument is visible to the caller, while rebinding the name inside the function is not.

53.3 — Data Structures & Iteration

Q: Why is a set/dict lookup faster than a list lookup?

Sets and dicts use hash tables, giving average O(1) membership/lookup; a list must scan items one by one, O(n).

Q: Shallow vs deep copy?

A shallow copy (copy.copy, .copy(), slicing) duplicates the outer container but shares nested objects; copy.deepcopy recursively copies everything.

Q: List comprehension vs generator expression?

A list comprehension builds the entire list in memory; a generator expression yields items lazily, using constant memory — preferable when you only iterate once or the data is large.

Q: What's the iterator protocol?

An iterable implements __iter__ returning an iterator; an iterator implements __next__ (raising StopIteration when done) and __iter__. for loops use this protocol.

Q: How do generators work and why use yield?

A function with yield returns a generator; each next() runs until the next yield, preserving local state. They enable lazy, memory-efficient pipelines and infinite sequences.

Q: How do you count items or group them?

collections.Counter for counts, defaultdict(list) for grouping, itertools.groupby for consecutive groups (sort first).

53.4 — OOP & Advanced Language

Q: Class attribute vs instance attribute?

Class attributes live on the class and are shared by all instances (unless shadowed); instance attributes are set on self and belong to one object. Beware mutable class attributes.

Q: @staticmethod vs @classmethod vs instance method?

Instance method gets self; classmethod gets cls (alternative constructors, class-level behaviour); staticmethod gets neither (a utility function namespaced in the class).

Q: What is method resolution order (MRO)?

The order Python searches base classes for an attribute, computed by C3 linearisation; super() follows it, which makes multiple inheritance predictable. Inspect with Class.__mro__.

Q: What are dunder methods? Give examples.

Special methods that customise object behaviour: __init__, __repr__, __eq__, __len__, __iter__, __getitem__, __enter__/__exit__, __call__, operators like __add__.

Q: What does @dataclass do and when use frozen=True?

It generates __init__, __repr__, __eq__ (optionally ordering/hash) from annotated fields. frozen=True makes instances immutable and hashable — good for value objects and dictionary keys.

Q: How does a decorator work? Write one.

A decorator takes a function and returns a replacement (usually a wrapper). Use functools.wraps to preserve metadata. @d def f equals f = d(f). Decorators with arguments add one more level of nesting.

Q: What is a context manager and how do you write one?

An object supporting with by defining __enter__/__exit__, or a generator function decorated with contextlib.contextmanager that yields once. It guarantees cleanup even when exceptions occur.

Q: What is duck typing, and how do Protocols relate?

Duck typing means an object's suitability is determined by the methods it provides, not its class. typing.Protocol lets static type checkers express that structurally ("anything with .speak()").

53.5 — Errors, Testing & Quality

Q: Explain try/except/else/finally.

try runs risky code; except handles a matching exception; else runs only if no exception occurred; finally always runs (cleanup). Catch specific exceptions and keep the try block small.

Q: What are exception groups and except*?

Since 3.11, an ExceptionGroup bundles several unrelated exceptions (common in concurrent code, e.g., TaskGroup). except* handles matching members separately.

Q: EAFP vs LBYL?

EAFP ("easier to ask forgiveness than permission") tries the operation and handles failure; LBYL ("look before you leap") checks conditions first. Python style favours EAFP, which also avoids race conditions between check and use.

Q: How do you test Python code?

Write small automated tests with pytest (or unittest), cover edge cases, use fixtures/parametrisation and mocks sparingly, measure coverage, and run them in CI on every change.

Q: What do type hints do at run time?

Nothing enforced: they're metadata. Static checkers (mypy, Pyright, ty) analyse them; libraries like Pydantic and FastAPI can use them for validation. In 3.14+ annotations are evaluated lazily.

Q: Why prefer logging to print?

Levels, formatting, destinations (files, services), per-module loggers and runtime configurability — without editing code. print offers none of that and is hard to turn off in production.

53.6 — Concurrency & Internals

Q: What is the GIL, and how does free-threading change things?

The GIL lets only one thread execute Python bytecode at a time in standard CPython, simplifying memory management but preventing multi-core parallelism in threads. Free-threaded builds remove it (officially supported since 3.14, with a roughly 5–10% single-thread cost), at the price of needing thread-safe extensions and care with shared data.

Q: Threads vs processes vs asyncio — when each?

Threads/asyncio for I/O-bound work (waiting); asyncio scales to thousands of connections but needs async libraries. Processes (or free-threading/subinterpreters) for CPU-bound parallelism. Use vectorised libraries before parallelising pure Python.

Q: How does await work?

It suspends the current coroutine until the awaited thing completes, returning control to the event loop so other tasks can run. It only yields at await points, so blocking calls inside coroutines stall everything.

Q: How does Python manage memory?

Reference counting frees objects when counts hit zero, plus a cyclic garbage collector for reference cycles. Objects live on a private heap; there's no manual free. Leaks usually come from lingering references (caches, globals).

Q: What new things did Python 3.14 and 3.15 bring?

3.14: template strings, lazily-evaluated annotations, officially supported free-threaded build, multiple interpreters (concurrent.interpreters), Zstandard, safer remote debugging. 3.15: explicit lazy imports, built-in frozendict and sentinel, UTF-8 default encoding, unpacking in comprehensions, sampling profiler, upgraded experimental JIT, stable ABI for free-threaded builds.

Q: What is the experimental JIT?

A just-in-time compiler built into CPython (introduced in 3.13, improved through 3.15) that compiles frequently-run code to machine code. It's opt-in and gains vary, so benchmark your workload.

53.7 — Packaging & Ecosystem

Q: Why use virtual environments?

To isolate each project's dependencies and Python version, avoiding conflicts and keeping the system Python clean; recreate them reproducibly from a lockfile.

Q: What is pyproject.toml?

The standard configuration file for a Python project: metadata, dependencies, build backend and tool settings (Ruff, pytest, etc.).

Q: What is uv and why has it spread so quickly?

An extremely fast Rust-based tool that unifies pip, venv, pyenv, pipx and project/lockfile management, and supports PEP 723 scripts. Speed and a single coherent workflow drove adoption; it comes from Astral, which OpenAI announced it would acquire in March 2026 while pledging to keep supporting the open-source tools.

Q: pandas vs Polars vs NumPy?

NumPy: fast numeric arrays. pandas: labelled tables with a huge ecosystem. Polars: newer, Rust-based, multi-threaded, lazy-query DataFrames, often faster and more memory-efficient. All avoid Python-level row loops.

Q: Django vs Flask vs FastAPI?

Django: full-featured framework with ORM/admin/auth. Flask: minimal and flexible. FastAPI: type-hint-driven, async-friendly API framework with automatic validation and docs via Pydantic. Choose by project shape and team familiarity.

53.8 — Security, Performance & Scenarios

Q: Why is eval or pickle.loads on untrusted input dangerous?

Both can execute arbitrary code. Use json, ast.literal_eval or safe loaders and never unpickle data you don't trust.

Q: How do you prevent SQL injection in Python?

Never build queries with string formatting; pass values as parameters (cursor.execute("… WHERE name = ?", (name,))) or use an ORM, which parameterises for you.

Q: A script is slow. What do you do?

Measure with a profiler (cProfile, or the sampling profiler in 3.15); fix the algorithm/data structure first; use built-ins and vectorised libraries; cache repeated work; then consider concurrency, a JIT/PyPy, or compiled extensions for proven hot spots.

Q: How would you read a 50 GB file safely?

Iterate over it lazily line by line (or in chunks) with a generator pipeline, or use a library designed for out-of-core data (Polars lazy scan, DuckDB) rather than loading it into memory.

Q: Your dependency was reported compromised. What's your response?

Identify affected projects (lockfiles/SBOM), pin or roll back to a safe version, rotate any secrets the package could have seen, rebuild, and add protections: lockfiles, hash-checking, delayed adoption of new releases, and vulnerability scanning in CI.

Q: What should you check before using an AI-generated Python snippet?

That you understand it, it runs on your Python version, it has tests, it handles errors and edge cases, it doesn't hard-code secrets or use unsafe patterns (eval, shell=True, string-built SQL), and its dependencies are real and trustworthy.

54 Pitfalls & Checklist

📛 Mutable default arguments

def f(x, bucket=[]) shares one list across calls. Default to None.

🏷️ Aliasing surprises

b = a is not a copy. Use .copy() / deepcopy; beware [[0]*3]*3.

🔢 Float equality

0.1 + 0.2 != 0.3. Use isclose or Decimal.

🤐 Bare except:

Hides bugs. Catch specific exceptions and log or re-raise.

📦 System-wide installs

Always use a virtual environment (or uv) per project.

📄 Missing encoding / timeout

Pass encoding="utf-8" to open() (needed before 3.15) and timeout= to network calls.

🔒 eval, pickle, f-string SQL

Classic injection routes. Use safe parsers and placeholders.

🐌 Blocking in async code

One time.sleep or blocking request freezes the event loop. Use await-friendly calls or asyncio.to_thread.

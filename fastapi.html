Part A — APIs, HTTP and Why FastAPI

1 What Is an API?

Picture: A restaurant waiter. You (the app) never walk into the kitchen (the server's database and code). You tell the waiter what you want from the menu, the waiter brings it back. The menu is the API's documentation; the waiter is the API.

Request / responseThe question and the answerYour order / your plate

Good to know

  • A web API uses HTTP (the language of the web). The phone app, the website and partner companies can all use the same API.
  • FastAPI is a Python library for building web APIs quickly, with automatic checking of data and automatic documentation.
  • Related guides: Python, Computer Networks (HTTP, TCP, TLS), DBMS, Docker & Kubernetes, MLOps & LLMOps (serving models), System Design.

3 Designing a Good REST API

  • Design for idempotent retries: clients and networks repeat requests; idempotency keys protect payments.

from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI(title="Hello API", version="1.0.0")

@app.get("/")                       # when a GET request arrives for "/" ...
def home():                         # ... FastAPI calls this function ...
    return {"message": "Hello, world!"}     # ... and turns the dict into JSON

@app.get("/hello/{name}")
def hello(name: str):
    return {"greeting": f"Hello, {name}!"}

client = TestClient(app)            # a pretend browser that talks to the app directly
r = client.get("/")
print(r.status_code, r.headers["content-type"], r.json())
print(client.get("/hello/Asha").json())
print(client.get("/nope").status_code, client.get("/nope").json())
print("free documentation pages:", [p for p in ("/docs", "/redoc", "/openapi.json") if client.get(p).status_code == 200])

# ----- Output (real run) -----
# 200 application/json {'message': 'Hello, world!'}
# {'greeting': 'Hello, Asha!'}
# 404 {'detail': 'Not Found'}
# free documentation pages: ['/docs', '/redoc', '/openapi.json']

The dictionary became JSON automatically; an unknown path gives 404 with a standard error body; the interactive docs (/docs, Swagger UI), ReDoc and the raw OpenAPI file exist without writing anything.

7 Path and Query Parameters (and Automatic Validation)

Picture: An address and extra instructions on a parcel: /items/5 says which item (path), ?limit=3&size=large says how (query).
Typed parameters, limits, enums, and the 422 errors FastAPI writes for you (run for real)
from enum import Enum
from typing import Annotated
from fastapi import FastAPI, Path, Query
from fastapi.testclient import TestClient

app = FastAPI()

class Size(str, Enum):
    small = "small"
    large = "large"

@app.get("/items/{item_id}")
def read_item(item_id: Annotated[int, Path(ge=1, description="Item number, 1 or more")],     # PATH parameter: part of the URL
              q: str | None = None,                                                          # QUERY parameter, optional
              limit: Annotated[int, Query(ge=1, le=100)] = 10,                               # query with a default and limits
              size: Size = Size.small):                                                      # only allowed values
    return {"item_id": item_id, "q": q, "limit": limit, "size": size}

c = TestClient(app)
for url in ["/items/5", "/items/5?q=pen&limit=3&size=large", "/items/abc", "/items/0", "/items/5?limit=500", "/items/5?size=huge"]:
    r = c.get(url)
    body = r.json()
    if r.status_code == 422:                                             # FastAPI rejected the request BEFORE our function ran
        body = [(e["loc"], e["msg"]) for e in body["detail"]]
    print("%-36s %d  %s" % (url, r.status_code, body))

# ----- Output (real run) -----
# /items/5                             200  {'item_id': 5, 'q': None, 'limit': 10, 'size': 'small'}
# /items/5?q=pen&limit=3&size=large    200  {'item_id': 5, 'q': 'pen', 'limit': 3, 'size': 'large'}
# /items/abc                           422  [(['path', 'item_id'], 'Input should be a valid integer, unable to parse string as an integer')]
# /items/0                             422  [(['path', 'item_id'], 'Input should be greater than or equal to 1')]
# /items/5?limit=500                   422  [(['query', 'limit'], 'Input should be less than or equal to 100')]
# /items/5?size=huge                   422  [(['query', 'size'], "Input should be 'small' or 'large'")]

'abc' is not an int, 0 is below the minimum 1, 500 is above the limit, 'huge' is not an allowed size: every bad request was rejected with status 422 and a precise location (['path', 'item_id']) before our function ran.

Declare it asFastAPI reads it from
A name in the path {item_id} + function argumentThe URL path
A simple-type argument not in the pathThe query string
A Pydantic model argumentThe JSON body
Header(), Cookie()Headers, cookies
Form(), File()/UploadFileForm fields, uploaded files
RequestThe raw request object

Good to know

  • Use Annotated[int, Query(ge=1, le=100)] (the recommended modern style) to add limits, descriptions, aliases and examples.
  • Optional parameters: give a default (q: str | None = None). Lists: tags: Annotated[list[str], Query()] = [] reads ?tags=a&tags=b.

8 Pydantic Models: Describing Your Data

Picture: A form at the post office with boxes marked 'name (at least 2 letters)', 'age (5 to 100)', 'email'. The clerk checks every box and corrects small slips like extra spaces.
Validation, conversion and serialisation with Pydantic v2 (run for real)
# Pydantic: describe the SHAPE of data with a class; Pydantic checks and converts incoming data.
from datetime import date
from pydantic import BaseModel, EmailStr, Field, ValidationError, field_validator

class Student(BaseModel):
    name: str = Field(min_length=2, max_length=50)
    email: EmailStr
    age: int = Field(ge=5, le=100)
    joined: date
    hobbies: list[str] = []

    @field_validator("name")
    @classmethod
    def tidy(cls, v: str) -> str:
        return v.strip().title()

s = Student(name="  asha rao ", email="asha@example.com", age="15", joined="2026-06-01")   # "15" (text) becomes 15 (int)
print(s)
print("model_dump():", s.model_dump())
print("model_dump_json():", s.model_dump_json())
try:
    Student(name="A", email="not-an-email", age=300, joined="yesterday")
except ValidationError as e:
    print("\n%d problems found:" % e.error_count())
    for err in e.errors(): print("  ", err["loc"], "->", err["msg"])
print("\nJSON Schema keys:", list(Student.model_json_schema()["properties"]))

# ----- Output (real run) -----
# name='Asha Rao' email='asha@example.com' age=15 joined=datetime.date(2026, 6, 1) hobbies=[]
# model_dump(): {'name': 'Asha Rao', 'email': 'asha@example.com', 'age': 15, 'joined': datetime.date(2026, 6, 1), 'hobbies': []}
# model_dump_json(): {"name":"Asha Rao","email":"asha@example.com","age":15,"joined":"2026-06-01","hobbies":[]}
#
# 4 problems found:
#    ('name',) -> String should have at least 2 characters
#    ('email',) -> value is not a valid email address: An email address must have an @-sign.
#    ('age',) -> Input should be less than or equal to 100
#    ('joined',) -> Input should be a valid date or datetime, input is too short
#
# JSON Schema keys: ['name', 'email', 'age', 'joined', 'hobbies']

The text '15' was converted to the number 15, the name was tidied by a validator, and bad data produced four separate error messages at once. model_dump() gives a dict, model_dump_json() JSON text.

m.model_dump(exclude_unset=True)To dict, only fields the client sent (PATCH)

Good to know

  • Pydantic v1 code (.dict(), @validator, class Config) still appears in old tutorials; v2 names are model_dump, field_validator, model_config.
  • Special types: EmailStr (needs email-validator), HttpUrl, SecretStr, UUID, datetime, Decimal.

9 Request Bodies and Response Models

Picture: Two different forms: the application form you fill in (with your password), and the membership card you get back (no password printed on it).
Separate input and output models; response_model hides the password (run for real)
from fastapi import FastAPI, status
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field

app = FastAPI()

class UserIn(BaseModel):              # what the client SENDS
    username: str = Field(min_length=3)
    password: str = Field(min_length=8)
    full_name: str | None = None

class UserOut(BaseModel):             # what we SEND BACK (no password!)
    id: int
    username: str
    full_name: str | None = None

db: list[dict] = []

@app.post("/users", response_model=UserOut, status_code=status.HTTP_201_CREATED)
def create_user(user: UserIn):        # a Pydantic parameter = read the JSON request BODY
    record = {"id": len(db) + 1, **user.model_dump()}
    db.append(record)
    return record                     # contains the password, but response_model filters it out

c = TestClient(app)
r = c.post("/users", json={"username": "asha", "password": "s3cret-pass", "full_name": "Asha Rao"})
print(r.status_code, r.json())
r = c.post("/users", json={"username": "ab", "password": "short"})
print(r.status_code, [(e["loc"], e["msg"]) for e in r.json()["detail"]])
r = c.post("/users", content="not json", headers={"content-type": "application/json"})
print(r.status_code, r.json()["detail"][0]["type"])
print("stored internally:", db[0])

# ----- Output (real run) -----
# 201 {'id': 1, 'username': 'asha', 'full_name': 'Asha Rao'}
# 422 [(['body', 'username'], 'String should have at least 3 characters'), (['body', 'password'], 'String should have at least 8 characters')]
# 422 json_invalid
# stored internally: {'id': 1, 'username': 'asha', 'password': 's3cret-pass', 'full_name': 'Asha Rao'}

The stored record contains the password, but the response contains only the UserOut fields. Too-short fields and broken JSON both give 422 with clear reasons.

Good to know

  • Pattern: XCreate (input), XUpdate (all fields optional, for PATCH), XPublic (output), plus the table model.
  • You can also annotate the return type (def f() -> UserOut); FastAPI then validates and filters the output the same way.
  • Never return database objects directly if they contain secrets; always use an output model.

11 A Complete CRUD API

Picture: A notebook with four actions: write a new page (Create), read pages (Read), rewrite or correct a page (Update), tear out a page (Delete).
Create, list, filter, PATCH, PUT, DELETE, and 404 (run for real)
# A complete CRUD API (Create, Read, Update, Delete) kept in memory, with 404s and partial updates.
from fastapi import FastAPI, HTTPException, status
from fastapi.testclient import TestClient
from pydantic import BaseModel

app = FastAPI()

class TodoIn(BaseModel):
    title: str
    done: bool = False

class TodoPatch(BaseModel):
    title: str | None = None
    done: bool | None = None

class Todo(TodoIn):
    id: int

todos: dict[int, Todo] = {}
next_id = 1

@app.post("/todos", status_code=status.HTTP_201_CREATED)
def create(t: TodoIn) -> Todo:
    global next_id
    todo = Todo(id=next_id, **t.model_dump()); todos[next_id] = todo; next_id += 1
    return todo

@app.get("/todos")
def list_todos(done: bool | None = None) -> list[Todo]:
    return [t for t in todos.values() if done is None or t.done == done]

def get_or_404(todo_id: int) -> Todo:
    if todo_id not in todos:
        raise HTTPException(status_code=404, detail=f"Todo {todo_id} not found")
    return todos[todo_id]

@app.get("/todos/{todo_id}")
def read(todo_id: int) -> Todo:
    return get_or_404(todo_id)

@app.put("/todos/{todo_id}")
def replace(todo_id: int, t: TodoIn) -> Todo:
    get_or_404(todo_id); todos[todo_id] = Todo(id=todo_id, **t.model_dump()); return todos[todo_id]

@app.patch("/todos/{todo_id}")
def update(todo_id: int, p: TodoPatch) -> Todo:
    old = get_or_404(todo_id)
    todos[todo_id] = old.model_copy(update=p.model_dump(exclude_unset=True))   # only the fields the client actually sent
    return todos[todo_id]

@app.delete("/todos/{todo_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete(todo_id: int):
    get_or_404(todo_id); del todos[todo_id]

c = TestClient(app)
def show(r): print("%-6s %-14s -> %d %s" % (r.request.method, r.request.url.path, r.status_code, r.text or "(empty)"))
show(c.post("/todos", json={"title": "learn FastAPI"})); show(c.post("/todos", json={"title": "drink water", "done": True}))
show(c.get("/todos")); show(c.get("/todos?done=true"))
show(c.patch("/todos/1", json={"done": True})); show(c.put("/todos/2", json={"title": "drink more water"}))
show(c.delete("/todos/2")); show(c.get("/todos/2")); show(c.get("/todos"))

# ----- Output (real run) -----
# POST   /todos         -> 201 {"title":"learn FastAPI","done":false,"id":1}
# POST   /todos         -> 201 {"title":"drink water","done":true,"id":2}
# GET    /todos         -> 200 [{"title":"learn FastAPI","done":false,"id":1},{"title":"drink water","done":true,"id":2}]
# GET    /todos         -> 200 [{"title":"drink water","done":true,"id":2}]
# PATCH  /todos/1       -> 200 {"title":"learn FastAPI","done":true,"id":1}
# PUT    /todos/2       -> 200 {"title":"drink more water","done":false,"id":2}
# DELETE /todos/2       -> 204 (empty)
# GET    /todos/2       -> 404 {"detail":"Todo 2 not found"}
# GET    /todos         -> 200 [{"title":"learn FastAPI","done":true,"id":1}]

PATCH changed only done because model_dump(exclude_unset=True) keeps just the fields the client sent; PUT replaced the whole item (its done went back to the default false). DELETE answered 204 with an empty body, and reading the deleted item gave 404 from HTTPException.

Good to know

  • raise HTTPException(status_code=404, detail=...) stops the request and returns that error.
  • This version keeps data in a dict (lost on restart); Part C uses a real database.

12 Dependency Injection: Depends()

Picture: A hotel concierge. Your room service order says 'I need a clean towel and a key card'; the concierge fetches them before you need them and tidies up after you leave. You never write the fetching code in every room.
Fig S3 — Dependencies form a graph; FastAPI resolves it for every request (and caches each dependency once per request).
Shared parameters, a yield dependency, auth checks and overrides (run for real)
# Dependency injection: FastAPI calls helper functions FOR you and hands their results to your endpoint.
from typing import Annotated
from fastapi import Depends, FastAPI, Header, HTTPException
from fastapi.testclient import TestClient

app = FastAPI()
log = []

def pagination(skip: int = 0, limit: int = 3):                    # a reusable set of query parameters
    return {"skip": skip, "limit": limit}

def get_db():                                                    # 'yield' dependency: setup, hand over, then clean up
    log.append("open db"); db = {"items": [f"item{i}" for i in range(10)]}
    try:
        yield db
    finally:
        log.append("close db")

# Login with OAuth2 password flow: hashed passwords (Argon2 via pwdlib) + signed JWT access tokens.
from datetime import datetime, timedelta, timezone
from typing import Annotated
import jwt
from fastapi import Depends, FastAPI, HTTPException, status
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from fastapi.testclient import TestClient
from pwdlib import PasswordHash

SECRET_KEY = "demo-only-change-me-use-a-long-random-value-from-an-env-var"   # NEVER hard-code a real secret
ALGORITHM = "HS256"
hasher = PasswordHash.recommended()
users = {"asha": {"username": "asha", "hashed": hasher.hash("correct horse battery"), "role": "student"}}
print("stored password hash starts with:", users["asha"]["hashed"][:30], "...")

app = FastAPI()

def make_token(sub: str, minutes: int) -> str:
    payload = {"sub": sub, "exp": datetime.now(timezone.utc) + timedelta(minutes=minutes)}
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)

@app.post("/token")
def login(form: Annotated[OAuth2PasswordRequestForm, Depends()]):
    u = users.get(form.username)
    if not u or not hasher.verify(form.password, u["hashed"]):
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Incorrect username or password", headers={"WWW-Authenticate": "Bearer"})
    return {"access_token": make_token(u["username"], 30), "token_type": "bearer"}

def current_user(token: Annotated[str, Depends(oauth2)]):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    except jwt.ExpiredSignatureError:
        raise HTTPException(401, "Token expired", headers={"WWW-Authenticate": "Bearer"})
    except jwt.InvalidTokenError:
        raise HTTPException(401, "Invalid token", headers={"WWW-Authenticate": "Bearer"})
    return users[payload["sub"]]

@app.get("/me")
def me(user: Annotated[dict, Depends(current_user)]):
    return {"username": user["username"], "role": user["role"]}

19 async def vs def (Measured)

Picture: A waiter who takes an order, and while the kitchen cooks, serves other tables (async). A waiter who stands frozen at the kitchen door until the dish is ready (blocking) makes every other table wait.

Three endpoint styles under 10 concurrent requests (run for real)
# async def vs def, MEASURED: 10 requests at the same time to endpoints that wait 0.2 s each.
import asyncio, time
import httpx
from fastapi import FastAPI

app = FastAPI()

@app.get("/async-await")
async def good_async():
    await asyncio.sleep(0.2)          # non-blocking wait: the event loop serves others meanwhile
    return {"ok": True}

@app.get("/sync-def")
def plain_def():
    time.sleep(0.2)                   # blocking, BUT plain 'def' endpoints run in a thread pool
    return {"ok": True}

@app.get("/async-blocking")
async def bad_async():
    time.sleep(0.2)                   # BLOCKING call inside async def: freezes the whole event loop
    return {"ok": True}

async def burst(path, n=10):
    async with httpx.AsyncClient(transport=httpx.ASGITransport(app=app), base_url="http://test") as client:
        t = time.perf_counter()
        rs = await asyncio.gather(*[client.get(path) for _ in range(n)])
        return time.perf_counter() - t, {r.status_code for r in rs}

for path in ["/async-await", "/sync-def", "/async-blocking"]:
    secs, codes = asyncio.run(burst(path))
    print("%-16s 10 concurrent requests took %.2f s  %s" % (path, secs, codes))
print("Ideal is about 0.2 s (all waits overlap). 2 s means the requests were handled ONE AT A TIME.")

# ----- Output (real run) -----

# /sync-def        10 concurrent requests took 0.24 s  {200}

23 Rate Limiting and HTTP Caching

Picture: A water fountain that lets each child drink three times per minute (rate limit), and a teacher who says 'you already have the latest worksheet, no need for a new copy' (304 Not Modified).
A token-style rate limit (429 + Retry-After) and ETag / If-None-Match (304) (run for real)
# Two production tricks done by hand: a per-client rate limit (429) and ETag caching (304 Not Modified).
import hashlib, json, time
from fastapi import Depends, FastAPI, HTTPException, Request, Response
from fastapi.testclient import TestClient

app = FastAPI()
buckets: dict[str, list[float]] = {}

def rate_limit(request: Request, limit: int = 3, window: float = 60.0):
    key = request.headers.get("X-API-Key", request.client.host)
    now = time.monotonic(); hits = [t for t in buckets.get(key, []) if now - t < window]
    if len(hits) >= limit:
        raise HTTPException(429, "Too many requests", headers={"Retry-After": str(int(window - (now - hits[0])))})
    buckets[key] = hits + [now]

CATALOG = {"pens": 12, "books": 4}

@app.get("/catalog", dependencies=[Depends(rate_limit)])
def catalog(request: Request, response: Response):
    body = json.dumps(CATALOG, sort_keys=True).encode()
    etag = '"' + hashlib.sha256(body).hexdigest()[:16] + '"'
    if request.headers.get("If-None-Match") == etag:
        return Response(status_code=304, headers={"ETag": etag})     # client's copy is still fresh: send no body
    response.headers["ETag"] = etag
    return CATALOG

c = TestClient(app)
r1 = c.get("/catalog", headers={"X-API-Key": "A"}); print("1st:", r1.status_code, r1.json(), "ETag", r1.headers["etag"])
r2 = c.get("/catalog", headers={"X-API-Key": "A", "If-None-Match": r1.headers["etag"]}); print("2nd with If-None-Match:", r2.status_code, "body bytes:", len(r2.content))
r3 = c.get("/catalog", headers={"X-API-Key": "A"}); print("3rd:", r3.status_code)
r4 = c.get("/catalog", headers={"X-API-Key": "A"}); print("4th:", r4.status_code, r4.json(), "Retry-After:", r4.headers.get("retry-after"))
print("other client B:", c.get("/catalog", headers={"X-API-Key": "B"}).status_code)
print("(in-memory limits work for ONE process only; use Redis or the API gateway when you run many workers)")

# ----- Output (real run) -----
# 1st: 200 {'pens': 12, 'books': 4} ETag "6aa1c8d435534491"
# 2nd with If-None-Match: 304 body bytes: 0
# 3rd: 200
# 4th: 429 {'detail': 'Too many requests'} Retry-After: 59

Good to know

  • Real deployments rate-limit in an API gateway, the reverse proxy, or with Redis-backed libraries (e.g. slowapi, fastapi-limiter), because each worker process has its own memory.
  • Response caching: Cache-Control headers for clients/CDNs, Redis for server-side caching of expensive results.

33 Interview Questions (With Answers)

Picture: Grouped by theme, easiest first. Click to reveal.

A. Basics

Q1: What is FastAPI and why is it popular?

A Python ASGI web framework built on Starlette and Pydantic that uses type hints for automatic validation, serialization and OpenAPI docs, with good performance and little code.

Q2: WSGI vs ASGI?

WSGI is the synchronous Python server interface (Flask, classic Django); ASGI supports async, WebSockets and long-lived connections (FastAPI, Starlette).

Q3: Path vs query parameters vs body?

Path identifies the resource (/items/5); query refines it (?limit=3); body carries data (JSON for POST/PUT/PATCH).

Q4: What does a 422 mean in FastAPI?

The request failed validation (wrong type, missing field, out of range); FastAPI returns details of each problem.

Q5: PUT vs PATCH?

PUT replaces the whole resource; PATCH changes only the sent fields (use model_dump(exclude_unset=True)).

B. Pydantic and models

Q6: Why separate input and output models?

To control what clients may set (no mass assignment) and what they see (no passwords or internal fields).

Q7: What changed in Pydantic v2?

Rust core (faster), renamed APIs (model_dump, model_validate, field_validator, model_config), stricter behaviours.

Q8: What is response_model for?

Validates and filters the output and documents it in OpenAPI.

C. Dependencies and architecture

Q9: What is dependency injection in FastAPI?

Depends() declares helpers (DB session, current user, settings) that FastAPI resolves per request, can nest, cache per request, clean up with yield, and override in tests.

Q10: How do yield dependencies work?

Code before yield runs before the endpoint, the yielded value is injected, code after runs after the response is ready (cleanup).

Q11: How do you structure a large FastAPI project?

APIRouters per domain, schemas vs models, services for business logic, deps module, settings, migrations, tests; lifespan for shared resources.

Q12: What replaced @app.on_event('startup')?

The lifespan async context manager passed to FastAPI(lifespan=...).

D. Async and performance

Q13: When do you use async def vs def?

async def when everything inside is awaitable (async drivers); def for blocking code, which FastAPI runs in a thread pool.

Q14: What happens if you call time.sleep or a blocking DB driver in async def?

It blocks the event loop; all requests on that worker wait (our demo: 2.0 s instead of 0.2 s for 10 requests).

Q15: How do you scale a FastAPI app?

Multiple worker processes/containers behind a load balancer, stateless design, shared state in Redis/DB, caching, async I/O, background queues.

Q16: BackgroundTasks vs Celery?

BackgroundTasks run in-process after the response (light work, lost on crash); Celery/queues run in separate workers with retries and persistence.

E. Security

Q17: How does JWT authentication work?

Login verifies the password hash and returns a signed token with sub/exp; protected routes verify signature and expiry on every request.

Q18: Is a JWT encrypted?

Usually not: it is signed (tamper-evident) but its payload is readable base64; never put secrets in it.

Q19: 401 vs 403?

401: not authenticated (missing/invalid credentials). 403: authenticated but not allowed.

Q20: What is CORS and is it a security feature for APIs?

A browser rule controlling which websites' scripts may read your responses; it protects browser users, not your API from other clients.

Q21: How do you store passwords?

Hash with a slow, salted algorithm (Argon2id, bcrypt); never store or log plain passwords.

Q22: What is broken object-level authorization?

Users accessing others' objects by changing ids; always check ownership in queries.

F. Testing and deployment

Q23: How do you test with a fake database or user?

app.dependency_overrides to swap the session/user dependencies; TestClient or httpx AsyncClient.

Q24: How do you deploy FastAPI?

Container with Uvicorn (fastapi run, workers), behind a reverse proxy/load balancer with TLS, migrations, health checks, logs and metrics.

Q25: How would you stream an LLM response?

An async endpoint returning StreamingResponse with text/event-stream, yielding chunks from the async SDK stream.

Q: Do I need to know async to use FastAPI?

No. Plain def endpoints work fine; learn async when you use async libraries.

Q: FastAPI or Django?

FastAPI for APIs and services with full control; Django when you want an admin site, ORM, auth and templates built in.

Q: Is FastAPI production-ready although its version starts with 0?

It is widely used in production; pin the exact version and read release notes before upgrading.

Q: Were these examples really run?

Yes, with FastAPI 0.164.0, Pydantic 2.14.3 and Python 3.14 on 19 Nov 2026; Docker, PostgreSQL, Redis, Celery and Claude API code are templates.

Q: Where do I put my secret key?

In an environment variable or secrets manager, read through settings; never in code or Git.

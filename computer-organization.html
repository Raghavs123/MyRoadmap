4 Measuring Performance: The Iron Law

Picture: Travel time = number of steps × time per step. A car with a faster engine (clock) can still arrive later if it takes a longer road (more instructions) or stops often (high CPI).

CPU time = Instruction count × CPI × Clock period (= IC × CPI ÷ clock rate). CPI = cycles per instruction. MIPS = millions of instructions per second (easy to misuse).

Two example machines and an instruction mix (ASSUMED numbers) (run for real)
# The 'iron law' of performance: CPU time = instructions x CPI x clock period.
def t(ic, cpi, ghz): return ic * cpi / (ghz * 1e9)
A = (2.0e9, 1.5, 3.0); B = (1.4e9, 2.2, 3.6)          # (instruction count, CPI, GHz): ASSUMED example machines/compilers
for name, (ic, cpi, ghz) in [("A", A), ("B", B)]:
    print("machine %s: %.1e instructions x CPI %.1f / %.1f GHz = %.3f s   MIPS = %.0f" % (name, ic, cpi, ghz, t(ic, cpi, ghz), ic / t(ic, cpi, ghz) / 1e6))
print("B has the faster clock, but A finishes first: clock speed alone (and MIPS) can mislead.")
mix = {"ALU": (0.50, 1), "load": (0.20, 5), "store": (0.10, 3), "branch": (0.20, 2)}
cpi = sum(f * c for f, c in mix.values())
print("average CPI from an instruction mix %s = %.2f" % ({k: v[0] for k, v in mix.items()}, cpi))
print("if loads got twice as fast (CPI 5 -> 2.5): new CPI %.2f, speedup %.2fx" % (cpi - 0.20 * 2.5, cpi / (cpi - 0.20 * 2.5)))

# ----- Output (real run) -----
# machine A: 2.0e+09 instructions x CPI 1.5 / 3.0 GHz = 1.000 s   MIPS = 2000
# machine B: 1.4e+09 instructions x CPI 2.2 / 3.6 GHz = 0.856 s   MIPS = 1636
# B has the faster clock, but A finishes first: clock speed alone (and MIPS) can mislead.
# average CPI from an instruction mix {'ALU': 0.5, 'load': 0.2, 'store': 0.1, 'branch': 0.2} = 2.20
# if loads got twice as fast (CPI 5 -> 2.5): new CPI 1.70, speedup 1.29x

Machine B has the faster clock but takes 0.856 s vs A's 1.000 s here only because of its smaller instruction count; with CPI 2.2 vs 1.5 the comparison could easily go the other way. Lowering the cost of loads (20% of instructions) cut average CPI from 2.20 to 1.70.

Good to know

  • Benchmarks: SPEC CPU (standard), Geekbench (consumer), MLPerf (AI). Always test your workload.
  • Throughput (jobs per second) vs latency (time for one job): different goals, different designs.
  • Power matters as much as speed today: dynamic power ≈ C × V² × f (capacitance, voltage squared, frequency).

6 Signed Integers and Two's Complement

Picture: A car's odometer that rolls back from 0000 to 9999 when you reverse. In 8-bit two's complement, going below 0 rolls to 1111 1111, which we agree means −1.
Two's complement, carry and overflow (run for real)
# Signed integers: two's complement. To negate: flip all bits, add 1. One adder works for + and -.
def bits(x, n=8): return format(x & ((1 << n) - 1), "0%db" % n)
def val(b): n = len(b); x = int(b, 2); return x - (1 << n) if b[0] == "1" else x
for x in (5, -5, 127, -128, -1, 0):
    print("%5d -> %s" % (x, bits(x)))
print("negate 5: %s -> flip %s -> +1 %s = %d" % (bits(5), bits(~5 & 0xFF), bits(-5), val(bits(-5))))
print("8-bit range: %d .. %d (unsigned 0 .. 255)" % (-(1 << 7), (1 << 7) - 1))
def add8(a, b):
    s = (a + b) & 0xFF; sa, sb, ss = a >> 7 & 1, b >> 7 & 1, s >> 7 & 1
    carry = (a + b) >> 8 & 1; overflow = (sa == sb) and (ss != sa)
    return s, carry, overflow
for a, b in [(100, 27), (100, 28), (0b11111111, 1), (-100 & 0xFF, -29 & 0xFF)]:
    s, c, o = add8(a, b)
    print("%s + %s = %s  as signed %4d + %4d = %4d   carry=%d overflow=%s" % (bits(a), bits(b), bits(s), val(bits(a)), val(bits(b)), val(bits(s)), c, o))
print("Overflow (signed) happens when two numbers of the SAME sign give a result of the OTHER sign; carry matters for unsigned numbers.")

7 Floating Point (IEEE 754)

Picture: Scientific notation in binary: 6.02 × 1023 becomes 1.something × 2exponent. A fixed number of digits means most decimals (like 0.1) cannot be stored exactly, the same way 1/3 cannot be written exactly in decimal.

A 32-bit float has 1 sign bit, 8 exponent bits (stored with a bias of 127) and 23 fraction bits (plus a hidden leading 1). A 64-bit double has 1, 11 (bias 1023) and 52. Value = (−1)sign × 1.fraction × 2exponent − bias.

Real IEEE 754 bit patterns and the classic surprises (run for real)

    print("%-12s %s %s %s  (%s)" % (repr(x), sign, exp, frac, kind))
for x in (1.0, -2.5, 0.1, 1e-45, float("inf"), float("nan")):

Good to know

  • Never use binary floats for money: use integers (paise/cents) or decimal types.

  • Rounding modes: round to nearest even (default), toward zero, up, down.

10 Error Detection and Correction (Parity, Hamming, ECC)

Picture: Sending a long number over a noisy phone line. Adding a check digit lets the listener notice a mistake; cleverer check digits let them even fix it.
Hamming(7,4): find and fix any single flipped bit (run for real)
# Hamming(7,4): add 3 parity bits so that any single flipped bit can be FOUND and FIXED.
def encode(d):                       # d = [d1,d2,d3,d4]; positions 1..7: p1 p2 d1 p3 d2 d3 d4
    p1 = d[0] ^ d[1] ^ d[3]; p2 = d[0] ^ d[2] ^ d[3]; p3 = d[1] ^ d[2] ^ d[3]
    return [p1, p2, d[0], p3, d[1], d[2], d[3]]
def decode(c):
    s1 = c[0] ^ c[2] ^ c[4] ^ c[6]; s2 = c[1] ^ c[2] ^ c[5] ^ c[6]; s3 = c[3] ^ c[4] ^ c[5] ^ c[6]
    pos = s1 + 2 * s2 + 4 * s3                       # the syndrome IS the position of the bad bit
    c = c[:]
    if pos: c[pos - 1] ^= 1
    return [c[2], c[4], c[5], c[6]], pos
data = [1, 0, 1, 1]; code = encode(data)
print("data", data, "-> codeword", code)
for bad in (0, 3, 6):
    r = code[:]; r[bad] ^= 1
    fixed, pos = decode(r)
    print("flip bit %d -> received %s -> syndrome says position %d -> corrected data %s %s" % (bad + 1, r, pos, fixed, "OK" if fixed == data else "WRONG"))
r = code[:]; r[0] ^= 1; r[1] ^= 1
fixed, pos = decode(r); print("TWO flips -> 'corrected' data %s: %s (Hamming(7,4) cannot handle 2 errors; ECC memory adds 1 more bit to DETECT them: SECDED)" % (fixed, "OK" if fixed == data else "WRONG"))

# ----- Output (real run) -----
# data [1, 0, 1, 1] -> codeword [0, 1, 1, 0, 0, 1, 1]
# flip bit 1 -> received [1, 1, 1, 0, 0, 1, 1] -> syndrome says position 1 -> corrected data [1, 0, 1, 1] OK
# flip bit 4 -> received [0, 1, 1, 1, 0, 1, 1] -> syndrome says position 4 -> corrected data [1, 0, 1, 1] OK
# flip bit 7 -> received [0, 1, 1, 0, 0, 1, 0] -> syndrome says position 7 -> corrected data [1, 0, 1, 1] OK
# TWO flips -> 'corrected' data [0, 0, 1, 1]: WRONG (Hamming(7,4) cannot handle 2 errors; ECC memory adds 1 more bit to DETECT them: SECDED)

Each single-bit error is located by the 'syndrome' and corrected. Two flipped bits are 'corrected' into the wrong data: that is why ECC memory uses SECDED (single error correct, double error detect) with one extra parity bit.

15 Multiplication and Booth's Algorithm

Picture: Long multiplication from school, in binary: for each 1 in the multiplier, add a shifted copy of the multiplicand. Booth's trick: a run of 1s like 0111 can be done as 1000 − 0001: one subtract and one add instead of three adds.
Booth's algorithm step by step (4-bit signed) (run for real)
# Booth's algorithm: multiply signed numbers with shifts and add/subtract. 4-bit example: 3 x (-4).
def booth(m, q, n=4):
    mask = (1 << n) - 1
    A, Q, Q_1, M = 0, q & mask, 0, m & mask
    print("step  A     Q     Q-1  action")
    print("init  %s  %s  %d" % (format(A, "04b"), format(Q, "04b"), Q_1))
    for step in range(1, n + 1):
        pair = (Q & 1, Q_1); act = "shift"
        if pair == (1, 0): A = (A - M) & mask; act = "A = A - M, shift"
        elif pair == (0, 1): A = (A + M) & mask; act = "A = A + M, shift"
        Q_1 = Q & 1                                                       # arithmetic shift right of A,Q,Q-1 together
        Q = ((Q >> 1) | ((A & 1) << (n - 1))) & mask
        A = ((A >> 1) | (A & (1 << (n - 1)))) & mask
        print("%4d  %s  %s  %d    %s" % (step, format(A, "04b"), format(Q, "04b"), Q_1, act))
    r = (A << n) | Q
    if r & (1 << (2 * n - 1)): r -= 1 << (2 * n)
    return r
r = booth(3, -4)
print("result:", r, " check:", 3 * -4)
r = booth(-7, 5); print("result:", r, " check:", -7 * 5)

16 Division: Restoring and Non-Restoring

# Restoring division (unsigned), step by step: 13 / 4 with 4-bit registers.
def restoring(dividend, divisor, n=4):
    A, Q, M = 0, dividend, divisor
    print("step  A       Q     action")
    for step in range(1, n + 1):
        A = (A << 1) | (Q >> (n - 1)); Q = (Q << 1) & ((1 << n) - 1)      # shift A,Q left
        A -= M
        if A < 0: A += M; act = "A-M < 0 -> restore, Q0 = 0"
        else: Q |= 1; act = "A-M >= 0 -> keep,   Q0 = 1"
        print("%4d  %s  %s  %s" % (step, format(A, "05b"), format(Q, "04b"), act))
    return Q, A

R, MEM, pc, cycles, executed = [0] * 4, {}, 0, 0, 0
CPI = {"LOAD": 1, "ADD": 1, "ADDI": 1, "BLT": 2, "STORE": 3, "HALT": 1}          # ASSUMED cycles per instruction type

Ideal speed-up with k stages ≈ k (each instruction still takes k cycles, but one finishes every cycle). Time for n instructions on a k-stage pipeline = (k + n − 1) cycles. Speed-up = n·k ÷ (k + n − 1) → k for large n.

Good to know

  • Real pipelines have 10–20+ stages; deeper pipelines allow higher clocks but make mispredicted branches cost more.
  • Anything that stops the next instruction from starting is a hazard (next section).

    for i, (op, rd, srcs) in enumerate(prog):

        ready[rd] = done
        rows.append((op, rd, srcs, start, stalls)); start = start + 1 + stalls
    total = rows[-1][3] + rows[-1][4] + 5
    return rows, total

27 Branch Prediction

Picture: A traffic officer guessing which way each car will turn so the road ahead can be cleared in time. Right guesses keep traffic flowing; wrong guesses mean everyone behind must reverse.
1-bit vs 2-bit predictors on a loop branch (run for real)
# Branch prediction: 1-bit vs 2-bit saturating counters on a loop branch (taken 9 times, then not taken), repeated 10 times.
pattern = ([1] * 9 + [0]) * 10
def run(bits):
    state = (1 << bits) - 1; hits = 0
    for t in pattern:
        pred = 1 if state >= (1 << (bits - 1)) else 0
        hits += pred == t
        state = min(state + 1, (1 << bits) - 1) if t else max(state - 1, 0)
    return hits / len(pattern)
print("always 'taken'   : %.0f%%" % (100 * sum(pattern) / len(pattern)))
print("1-bit predictor  : %.0f%%  (mispredicts twice per loop: at the exit AND at the next entry)" % (100 * run(1)))
print("2-bit predictor  : %.0f%%  (one surprise is not enough to change its mind)" % (100 * run(2)))
import random; random.seed(0); rnd = [random.randint(0, 1) for _ in range(1000)]
pattern = rnd; print("random branches  : %.0f%% with 2 bits (nothing can predict coin flips)" % (100 * run(2)))

# 1-bit predictor  : 81%  (mispredicts twice per loop: at the exit AND at the next entry)

  • Modern predictors (TAGE, perceptron-based) use global history and reach very high accuracy on typical code; a misprediction costs about the pipeline depth in cycles (often 15–20).

import math

31 Cache Simulation and AMAT

Hit rates for three access patterns; AMAT arithmetic (run for real)
# A cache simulator: direct-mapped vs 2-way vs 4-way vs fully associative (LRU), same total size (8 lines of 16 bytes).
import random
def simulate(trace, lines=8, ways=1, block=16):
    sets = lines // ways; cache = [[] for _ in range(sets)]; hits = 0
    for addr in trace:
        blk = addr // block; s = blk % sets; tag = blk // sets; row = cache[s]
        if tag in row: hits += 1; row.remove(tag); row.append(tag)
        else:
            if len(row) == ways: row.pop(0)
            row.append(tag)
    return hits / len(trace)
seq = [i * 4 for i in range(256)] * 4                                # walk 1 KiB of ints 4 times
conflict = [0, 128, 0, 128, 0, 128] * 50                              # two addresses that map to the same direct-mapped set
random.seed(1); loopish = [random.choice(range(0, 96, 4)) for _ in range(2000)]   # random reuse within 96 bytes (fits)
print("trace              direct  2-way  4-way  fully-assoc")
for name, t in [("sequential walk", seq), ("ping-pong conflict", conflict), ("small hot set", loopish)]:
    print("%-18s %6.2f  %5.2f  %5.2f  %11.2f" % (name, *(simulate(t, ways=w) for w in (1, 2, 4, 8))))
print("\nAMAT = hit time + miss rate x miss penalty  (ASSUMED 1 ns hit, 100 ns penalty)")
for mr in (0.02, 0.05, 0.10):

42 Amdahl's Law and Gustafson's Law

Picture: Ten friends can wash the dishes faster, but they cannot shorten the one person who must drive to the shop first. The part that cannot be shared limits the whole job.

Speedup table (run for real)
# Amdahl's law: speedup = 1 / ((1 - p) + p / n). The part you cannot parallelise limits everything.
print("cores   p=50%   p=90%   p=95%   p=99%")
for n in (1, 2, 4, 8, 16, 64, 1024):

print("limit with infinite cores: p=90% -> 10x, p=99% -> 100x")

# ----- Output (real run) -----

#     4    1.60    3.08    3.48    3.88

With 90% parallel code, 1024 cores give only 9.9× (the limit is 10×). Gustafson's view: when the problem grows with the machine (bigger simulations), scaled speedup can be near-linear.

Good to know

  • Speedup = 1 ÷ ((1 − p) + p ÷ n). Efficiency = speedup ÷ n.
  • Also remember communication and synchronization overhead, which Amdahl's simple form ignores.

45 Interview Questions (With Answers)

Picture: Grouped by theme, easiest first. Click to reveal.

A. Basics

Q1: Computer architecture vs organization?

Architecture: what the programmer sees (ISA, registers, addressing). Organization: how hardware implements it (pipelines, caches, buses).

Q2: What is the von Neumann bottleneck?

The single CPU–memory path limits throughput because the CPU waits for memory; caches and parallel paths reduce it.

Q3: Why two's complement?

One zero, and the same adder handles addition and subtraction.

Q4: Why is 0.1 + 0.2 not 0.3 in floating point?

0.1 and 0.2 have no exact binary representation; the rounded values add to 0.30000000000000004.

B. Logic and arithmetic

Q5: Which gates are universal?

NAND and NOR.

Q6: Combinational vs sequential?

Combinational output depends only on current inputs; sequential also on stored state (flip-flops, clock).

Q7: Why is a ripple-carry adder slow?

Each bit waits for the previous carry; carry-lookahead computes carries in parallel.

Q8: What does Booth's algorithm improve?

Handles signed multiplication directly and reduces additions for runs of 1s.

Q9: How does Hamming code correct an error?

Parity bits cover overlapping positions; the syndrome gives the position of the flipped bit.

C. CPU and ISA

Q10: CISC vs RISC?

CISC: many complex, variable-length instructions with memory operands. RISC: simple fixed-length instructions, load/store, many registers, pipeline-friendly.

Q11: Explain the instruction cycle.

Fetch (IR ← M[PC], PC advances), decode, execute, memory access, write back, check interrupts.

Q12: Name five addressing modes.

Immediate, register, direct, register indirect, base+displacement (also indexed, PC-relative).

Q13: Hardwired vs microprogrammed control?

Hardwired: logic circuits, fast, fixed. Microprogrammed: microcode sequences, flexible, updatable.

D. Pipelining

Q14: What are pipeline hazards?

Structural (resource conflict), data (dependence), control (branches).

Q15: What is forwarding?

Sending a result directly from a later stage to an earlier one so the dependent instruction need not wait for write-back.

Q16: Why does a load-use hazard still stall with forwarding?

The loaded value is available only after the MEM stage, one cycle too late for the next instruction's EX.

Q17: Why is a 2-bit predictor better than 1-bit for loops?

One unusual outcome (loop exit) does not flip the prediction, so the next loop entry is predicted correctly (90% vs 81% in our demo).

Q18: What is out-of-order execution?

Executing instructions when their operands are ready, not strictly in program order, then committing results in order.

E. Memory

Q19: Why do caches work?

Programs show temporal and spatial locality.

Q20: Direct-mapped vs set-associative vs fully associative?

One possible line vs one of k lines in a set vs any line; more associativity = fewer conflict misses, more compare hardware.

Q21: Compute tag/index/offset for a 32 KiB, 8-way cache with 64 B lines and 32-bit addresses.

512 lines, 64 sets: offset 6, index 6, tag 20 bits.

Q22: What is AMAT?

Average memory access time = hit time + miss rate × miss penalty.

Q23: Write-through vs write-back?

Write-through updates memory on every write; write-back only on eviction of a dirty line.

Q24: What is false sharing?

Threads writing different variables in the same cache line cause coherence traffic (about 5× slowdown in our run).

Q25: SRAM vs DRAM?

SRAM: 6-transistor cells, fast, no refresh, used for caches. DRAM: capacitor cells, dense, needs refresh, main memory.

F. I/O and parallelism

Q26: What is DMA?

A controller transfers data between device and memory without the CPU copying each word.

Q27: State Amdahl's law.

Speedup = 1 / ((1 − p) + p/n); the serial part limits speedup (90% parallel → max 10×).

Q28: SIMD vs MIMD?

One instruction on many data elements vs independent instruction streams on independent data.

Q29: CPU vs GPU?

Few complex low-latency cores vs thousands of simple throughput-oriented cores with high-bandwidth memory.

Q30: Why did clock speeds stop rising around 2005?

Power and heat: Dennard scaling ended, so designers turned to multiple cores and specialisation.

47 FAQ

Q: Do programmers really need COA?

For everyday code, less; for fast code, systems work, embedded, compilers, GPUs and interviews, yes. The 19× row/column difference on this page is pure COA.

Q: Is x86 dying because of ARM and RISC-V?

All three are actively used; ARM has grown in laptops and servers and RISC-V in embedded. Market facts change, so check current sources.

Q: Why did the branch test show no difference?

g++ -O2 compiled the branch into branch-free code. Different compilers, flags or code shapes can show a large difference: always measure.

Q: Were the results really measured?

Yes: the C++ programs were compiled with g++ 15.2 (-O2) and run on this machine; timings depend on the machine. Verilog and RISC-V assembly are templates.

Q: Which books are classic?

Patterson and Hennessy 'Computer Organization and Design'; Hennessy and Patterson 'Computer Architecture: A Quantitative Approach'; Stallings; Hamacher; Morris Mano for digital logic.

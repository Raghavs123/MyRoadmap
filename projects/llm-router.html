Part A — Start Here

1 What We Are Building (and the Result)

A hospital front desk. A nurse looks at each patient for a few seconds: small cuts stay with the nurse, strange pains go to the specialist. Does the desk save time without sending sick people home? This project measures exactly that for language models.

You will build, from an empty folder, an LLM router: a small, fast model reads each question and says EASY or HARD; easy questions stay on the small model, hard ones go to a big model. The project is really the measurement: "small only", "big only" and "router" answer the same 40 questions, a judge model grades every answer against a reference, you check the judge yourself, and one table shows the speed-versus-quality trade-off. The idea comes from LMSYS's RouteLLM, which reported cost reductions of over 85% on MT Bench (45% on MMLU, 35% on GSM8K) compared with GPT-4 alone while keeping 95% of GPT-4's quality (LMSYS blog, 1 July 2024; their result, not ours).

  • A command line and a web API
  • 48 automatic tests
  • Resumable result files + generated reports
  • README, demo GIF, CI, Docker

What you learn

The honest headline. The first router (v1) kept big-only quality (32/40 vs 32/40) but was only 6% faster, because its small classifier called most easy questions HARD. The few-shot router (v2) sent only 35% of questions to the big model and cut the assumed cost by 52%, but its longer prompt made each routing decision take 4.9 s on a CPU, which ate most of the time it saved. On this hardware no router came close to the oracle (a perfect router: 35/40 at 7.8 s). Even the stricter judge prompt made grading worse, so accuracy here comes from a full review of the answers. These are real findings, and the page explains why.

2 How It Works: One Request, the Measurement, the Modules

A hospital front desk. A nurse looks at each patient for a few seconds: a small cut is treated at the nurse's own table, a strange pain goes to the specialist. The specialist is slower and costs more, so you only want the patients who need one to see one. The project measures whether the front desk really saves time without sending sick people home.
Fig 1 — One request: the small model decides, then the chosen model answers. Routing time counts as latency.
  1. Rule (only in the router-rules strategy): a regular expression spots obvious hard questions (code words, "why", "compare", arithmetic) and sends them to the big model with no model call at all.
  2. Classify: the small model reads the question and replies one word, EASY or HARD. This is a real model call, so its time is part of the router's latency.
  3. Answer: EASY goes to the small model, HARD to the big one. An unclear label goes to the big model (safe side).
Fig 2 — The measurement: every strategy answers the same 40 questions, the judge grades each answer, every call is cached, and the report is rebuilt from the files.

To measure it, every strategy answers the same 40 questions and the big model judges each answer against a short reference answer. Then you read some verdicts yourself, because an LLM judge can be wrong.

Fig 3 — The modules. Each file has one job and talks to the models only through llm/.

One Settings class (pydantic-settings) reads every ROUTER_* variable, checks its type and range, and gives defaults. DEFAULT_MODELS picks the small/big pair per provider. Empty strings mean "use the default" (the validator), so a blank line in .env never breaks anything.

Full content of src/llmrouter/config.py: copy it exactly
src/llmrouter/config.py
"""All settings in one place (12-factor style: environment variables or a .env file).

Every variable starts with ROUTER_, for example ROUTER_PROVIDER=anthropic or ROUTER_SLEEP_S=4.
API keys are NOT stored here: each provider SDK reads its own variable
(ANTHROPIC_API_KEY, OPENAI_API_KEY / GROQ_API_KEY ...).
"""

from __future__ import annotations

from functools import lru_cache
from pathlib import Path
from typing import Literal

from pydantic import Field, field_validator
from pydantic_settings import BaseSettings, SettingsConfigDict

Provider = Literal["local", "fake", "anthropic", "openai"]

# (small model, big model) used when ROUTER_SMALL_MODEL / ROUTER_BIG_MODEL are empty
DEFAULT_MODELS: dict[str, tuple[str, str]] = {
    "local": ("Qwen/Qwen2.5-0.5B-Instruct", "Qwen/Qwen2.5-3B-Instruct"),
    "fake": ("fake-small", "fake-big"),
    "anthropic": ("claude-haiku-5-5", "claude-opus-5-5"),
    "openai": ("", ""),  # OpenAI-compatible servers (Groq, Gemini, Ollama ...): set both names
}


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="ROUTER_", env_file=".env", extra="ignore")

    # --- models -----------------------------------------------------------------------------
    provider: Provider = "local"
    small_model: str | None = None  # empty = DEFAULT_MODELS[provider][0]
    big_model: str | None = None  # empty = DEFAULT_MODELS[provider][1]
    judge_model: str | None = None  # empty = the big model (as in the project brief)
    openai_base_url: str | None = None  # e.g. https://api.groq.com/openai/v1
    openai_api_key_env: str = "OPENAI_API_KEY"  # name of the variable that holds the key

    # --- generation -------------------------------------------------------------------------
    max_answer_tokens: int = Field(384, ge=16, le=4096)
    device: Literal["cpu", "cuda", "auto"] = "cpu"  # local provider only
    dtype: Literal["bfloat16", "float32", "float16"] = "bfloat16"  # local provider only
    threads: int | None = None  # local provider: torch threads (None = torch default)
    sleep_s: float = Field(0.0, ge=0.0)  # pause after each API call (free tiers: try 4)

    # --- prompts (versions are in llmrouter/prompts.py) ---------------------------------------
    judge_prompt: Literal["v1", "v2"] = "v1"

    # --- files ------------------------------------------------------------------------------
    questions_path: Path = Path("questions.jsonl")
    results_dir: Path = Path("results")
    reports_dir: Path = Path("reports")

    @field_validator("small_model", "big_model", "judge_model", "openai_base_url", mode="before")
    @classmethod
    def _empty_means_none(cls, v):
        return None if isinstance(v, str) and v.strip().lower() in ("", "none") else v

    @property
    def small(self) -> str:
        return self.small_model or DEFAULT_MODELS[self.provider][0]

    @property
    def big(self) -> str:
        return self.big_model or DEFAULT_MODELS[self.provider][1]

    @property
    def judge(self) -> str:
        return self.judge_model or self.big


@lru_cache(maxsize=1)
def get_settings() -> Settings:
    return Settings()

7 Step 3: Write the 40 Test Questions (and 20 Hold-out Questions)

A teacher writing the exam and the answer key before the class starts, so nobody can argue later about what was right.

The test set is the heart of the project: 40 questions, one JSON object per line. 20 are easy (8 facts, 6 definitions, 6 short rewrites) and 20 are hard (8 multi-step maths, 6 code, 6 "compare / explain why"). Each has a short reference answer that the judge compares with. We added two fields to the brief's format: id (to save results per question) and category (for the analysis). The router never sees level: it is only our label, used to count misroutes.

The second file has 20 new questions (the hold-out set). We use it only on Day 3, to check that an improved router is really better and not just tuned to the 40 questions.

"""Load and check the question set (questions.jsonl: one JSON object per line)."""

from __future__ import annotations

import json
from dataclasses import dataclass
from pathlib import Path

LEVELS = ("easy", "hard")


@dataclass(frozen=True)
class Case:
    id: str
    level: str  # "easy" or "hard": the label WE wrote, used only for analysis, never by the router
    category: str  # fact | definition | rewrite | math | code | compare
    question: str
    reference: str


def load_cases(path: Path | str) -> list[Case]:
    cases, seen = [], set()
    for n, line in enumerate(Path(path).read_text(encoding="utf-8").splitlines(), start=1):
        if not line.strip():
            continue
        raw = json.loads(line)
        missing = {"id", "level", "question", "reference"} - raw.keys()
        if missing:
            raise ValueError(f"{path}:{n}: missing {sorted(missing)}")
        if raw["level"] not in LEVELS:
            raise ValueError(f"{path}:{n}: level must be easy or hard, got {raw['level']!r}")
        if raw["id"] in seen:
            raise ValueError(f"{path}:{n}: duplicate id {raw['id']}")
        seen.add(raw["id"])
        cases.append(
            Case(
                id=raw["id"],
                level=raw["level"],
                category=raw.get("category", ""),
                question=raw["question"].strip(),
                reference=raw["reference"].strip(),
            )
        )
    return cases

9 Step 5: Model Clients (the llm/ folder)

Wall sockets: a lamp, a fan and a phone charger all plug into the same socket shape. Our router plugs into any model the same way.

Every model client has one method: chat(messages, max_tokens), returning a Reply (text, token counts, seconds). Four clients:

  • local.py: Qwen models on your own computer with Hugging Face transformers. All our numbers were measured with this. Greedy decoding (no randomness) means the same question always gets the same answer.
  • fake.py: an offline stand-in for tests and CI. It knows the easy answers (small) or all answers (big).
  • anthropic_client.py and openai_compat.py: templates for Claude and for any OpenAI-compatible server (Groq, Gemini, Ollama, OpenAI). Not run here: no API key on the build machine.

The first run downloads the models (about 1 GB + 6 GB). Put them on a disk with space by setting HF_HOME, for example in PowerShell $env:HF_HOME="D:\hf-cache" (cmd: set HF_HOME=D:\hf-cache).

"""Open-weight models running on your own machine with Hugging Face transformers.

This is the provider the numbers in reports/ were measured with: no API key, no quota.
The first call downloads the model (Qwen2.5-0.5B-Instruct ~1 GB, Qwen2.5-3B-Instruct ~6 GB);
set HF_HOME to put the download on a disk with space.

Decoding is greedy (do_sample=False), so the same prompt gives the same answer every time.
That makes results repeatable and lets the result cache reuse an answer safely.
"""

from __future__ import annotations

import time

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

from llmrouter.llm.base import Reply


class LocalModel:
    def __init__(
        self, name: str, device: str = "cpu", threads: int | None = None, dtype: str = "bfloat16"
    ) -> None:
        self.name = name
        if threads:
            torch.set_num_threads(threads)
        if device == "auto":
            device = "cuda" if torch.cuda.is_available() else "cpu"
        self.device = device
        # bfloat16 = the precision the Qwen weights are published in, and half the bytes of
        # float32. Generating text on a CPU is limited by memory speed (every new token reads
        # all the weights), so on the build laptop bfloat16 was 1.6x faster than float32.
        torch_dtype = getattr(torch, dtype)
        self.tokenizer = AutoTokenizer.from_pretrained(name)
        self.model = AutoModelForCausalLM.from_pretrained(name, dtype=torch_dtype).to(device)
        self.model.eval()

    @torch.inference_mode()
    def chat(self, messages: list[dict], max_tokens: int) -> Reply:
        start = time.perf_counter()
        ids = self.tokenizer.apply_chat_template(
            messages, add_generation_prompt=True, return_tensors="pt", return_dict=True
        ).to(self.device)
        out = self.model.generate(
            **ids,
            max_new_tokens=max_tokens,
            do_sample=False,  # greedy: repeatable answers
            temperature=None,  # unset the sampling defaults from generation_config.json
            top_p=None,
            top_k=None,
            pad_token_id=self.tokenizer.eos_token_id,
        )
        new = out[0, ids["input_ids"].shape[1] :]
        text = self.tokenizer.decode(new, skip_special_tokens=True).strip()
        finished = bool(len(new)) and new[-1].item() in _stop_ids(self.tokenizer, self.model)
        return Reply(
            text=text,
            model=self.name,
            input_tokens=int(ids["input_ids"].shape[1]),
            output_tokens=int(len(new)),
            seconds=time.perf_counter() - start,
            finish="stop" if finished or len(new) < max_tokens else "length",
        )


def _stop_ids(tokenizer, model) -> set[int]:
    eos = model.generation_config.eos_token_id
    ids = set(eos if isinstance(eos, list) else [eos])
    if tokenizer.eos_token_id is not None:
        ids.add(tokenizer.eos_token_id)
    return ids

"""An offline stand-in model for tests, CI and quick demos. It never calls a network.

* As a classifier it says HARD when the question has a "hard-looking" keyword.
* As a judge it says CORRECT when the answer contains the reference's first word.
* As an answerer it returns the reference for the questions it "knows", otherwise a wrong
  answer. The factory lets fake-small know only the easy questions and fake-big know all.
* `seconds` is a fixed, made-up latency that is reported, not slept.
"""

from __future__ import annotations

import re

from llmrouter.llm.base import Reply

HARD_WORDS = re.compile(r"\b(code|python|sql|why|compare|solve|how many|average|sum)\b", re.I)


class FakeModel:
    def __init__(self, name: str, seconds: float, known: dict[str, str] | None = None) -> None:
        self.name = name
        self.seconds = seconds
        self.known = known or {}
        self.calls = 0

    def chat(self, messages: list[dict], max_tokens: int) -> Reply:
        self.calls += 1
        prompt = messages[-1]["content"]
        if "Reference answer:" in prompt:
            text = _judge(prompt)
        elif "EASY or HARD" in prompt:
            question = prompt.rsplit("Question:", 1)[-1]
            text = "HARD" if HARD_WORDS.search(question) else "EASY"
        else:
            text = self.known.get(prompt.strip(), "I am not sure, maybe 42.")
        return Reply(
            text=text,
            model=self.name,
            input_tokens=len(prompt.split()),
            output_tokens=len(text.split()),
            seconds=self.seconds,
        )


def _judge(prompt: str) -> str:
    ref = prompt.split("Reference answer:", 1)[1].split("\n", 1)[0]
    got = prompt.split("Model answer:", 1)[1].rsplit("\n", 1)[0]
    words = re.findall(r"\w+", ref.lower())
    return "CORRECT" if words and words[0] in re.findall(r"\w+", got.lower()) else "INCORRECT"

"""Claude via the official Anthropic SDK.   pip install -e ".[anthropic]"

Template - not run while building this repo (no API key on the build machine).
Run it yourself:  ANTHROPIC_API_KEY=...  ROUTER_PROVIDER=anthropic  llmrouter run

Choices:
* small = claude-haiku-5-5, big (and judge) = claude-opus-5-5 (see config.DEFAULT_MODELS).
* No temperature / top_p / top_k: current Claude models reject sampling parameters.
* effort "low": the classifier and the judge answer with one word, and the FAQ-style answers
  are short. Raise it (ROUTER_EFFORT is not wired; edit EFFORT) if hard answers look rushed.
* Opus 5.5 gets the server-side refusal fallback; Haiku has none, so a refusal is returned
  as text and the judge will mark it INCORRECT.
"""

from __future__ import annotations

import time

import anthropic

from llmrouter.llm.base import Reply

EFFORT = "low"


class AnthropicModel:
    def __init__(self, name: str) -> None:
        self.name = name
        self._client = anthropic.Anthropic()  # reads ANTHROPIC_API_KEY or an `ant` profile

    def chat(self, messages: list[dict], max_tokens: int) -> Reply:
        system = "\n".join(m["content"] for m in messages if m["role"] == "system")
        turns = [m for m in messages if m["role"] != "system"]
        kwargs = dict(
            model=self.name,
            max_tokens=max(max_tokens, 1024),  # leave room for adaptive thinking
            output_config={"effort": EFFORT},
            messages=turns,
        )
        if system:
            kwargs["system"] = system
        start = time.perf_counter()
        if self.name.startswith("claude-opus"):
            resp = self._client.beta.messages.create(
                betas=["server-side-fallback-2026-07-01"], fallbacks="default", **kwargs
            )
        else:
            resp = self._client.messages.create(**kwargs)
        seconds = time.perf_counter() - start
        text = "".join(b.text for b in resp.content if b.type == "text").strip()
        return Reply(
            text=text,
            model=resp.model,
            input_tokens=resp.usage.input_tokens,
            output_tokens=resp.usage.output_tokens,
            seconds=seconds,
            finish="stop" if resp.stop_reason == "end_turn" else str(resp.stop_reason),
        )

"""Any OpenAI-compatible chat server.   pip install -e ".[openai]"

Template - not run while building this repo (no keys and no Ollama on the build machine).
The same client works for many free tiers and local servers, because they all speak the
OpenAI Chat Completions format. Examples (check each provider's docs for current model names):

  Groq        ROUTER_OPENAI_BASE_URL=https://api.groq.com/openai/v1
              ROUTER_OPENAI_API_KEY_ENV=GROQ_API_KEY
  Gemini      ROUTER_OPENAI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
              ROUTER_OPENAI_API_KEY_ENV=GEMINI_API_KEY
  Ollama      ROUTER_OPENAI_BASE_URL=http://localhost:11434/v1   (any non-empty key works)
  OpenAI      leave ROUTER_OPENAI_BASE_URL empty, key in OPENAI_API_KEY

Then set ROUTER_PROVIDER=openai, ROUTER_SMALL_MODEL=... and ROUTER_BIG_MODEL=...
Free tiers limit requests per minute: set ROUTER_SLEEP_S=4 and let the result cache resume.
"""

from __future__ import annotations

import os
import time

from openai import OpenAI

from llmrouter.llm.base import Reply


class OpenAICompatModel:
    def __init__(self, name: str, base_url: str | None, api_key_env: str) -> None:
        if not name:
            raise ValueError("set ROUTER_SMALL_MODEL and ROUTER_BIG_MODEL for provider 'openai'")
        self.name = name
        self._client = OpenAI(base_url=base_url, api_key=os.environ.get(api_key_env, "unset"))

    def chat(self, messages: list[dict], max_tokens: int) -> Reply:
        start = time.perf_counter()
        resp = self._client.chat.completions.create(
            model=self.name, messages=messages, max_tokens=max_tokens
        )
        seconds = time.perf_counter() - start
        choice = resp.choices[0]
        usage = resp.usage
        return Reply(
            text=(choice.message.content or "").strip(),
            model=self.name,
            input_tokens=usage.prompt_tokens if usage else 0,
            output_tokens=usage.completion_tokens if usage else 0,
            seconds=seconds,
            finish=choice.finish_reason or "stop",
        )

"""Model clients. build_models() returns {"small": ..., "big": ..., "judge": ...}."""

from __future__ import annotations

from collections.abc import Callable

from llmrouter.config import Settings
from llmrouter.llm.base import ChatModel, Reply

__all__ = ["ChatModel", "LazyModel", "Reply", "build_models"]


class LazyModel:
    """Loads a local model on its first chat() call, then makes one untimed warm-up call.

    So a model that a command never uses is never loaded (a re-judging run needs only the
    judge: ~6 GB less RAM), and loading/warm-up time never ends up in a measured latency
    (every client measures Reply.seconds inside its own chat()).
    """

    def __init__(self, name: str, make: Callable[[], ChatModel]) -> None:
        self.name = name
        self._make = make
        self._model: ChatModel | None = None

    @property
    def loaded(self) -> bool:
        return self._model is not None

    def load(self) -> ChatModel:
        if self._model is None:
            self._model = self._make()
            self._model.chat([{"role": "user", "content": "Say OK."}], max_tokens=4)  # warm-up
        return self._model

    def chat(self, messages: list[dict], max_tokens: int) -> Reply:
        return self.load().chat(messages, max_tokens)


def build_models(settings: Settings, cases=None) -> dict[str, ChatModel]:
    names = {"small": settings.small, "big": settings.big, "judge": settings.judge}
    cache: dict[str, ChatModel] = {}  # the judge usually IS the big model: load it once

    def make(name: str) -> ChatModel:
        if name in cache:
            return cache[name]
        if settings.provider == "local":
            from llmrouter.llm.local import LocalModel

            model = LazyModel(
                name,
                lambda: LocalModel(
                    name, device=settings.device, threads=settings.threads, dtype=settings.dtype
                ),
            )
        elif settings.provider == "fake":
            from llmrouter.llm.fake import FakeModel

            easy_only = name == settings.small
            known = {
                c.question: c.reference for c in (cases or []) if c.level == "easy" or not easy_only
            }
            model = FakeModel(name, seconds=0.2 if easy_only else 1.0, known=known)
        elif settings.provider == "anthropic":
            from llmrouter.llm.anthropic_client import AnthropicModel

            model = AnthropicModel(name)
        else:
            from llmrouter.llm.openai_compat import OpenAICompatModel

            model = OpenAICompatModel(name, settings.openai_base_url, settings.openai_api_key_env)
        cache[name] = model
        return model

    return {role: make(name) for role, name in names.items()}

11 Step 7: The Router and the Judge (routing.py, judge.py)

A hospital front desk (the router) and an examiner with the answer key (the judge).

The router asks the small model "EASY or HARD?" and sends HARD questions to the big model. The judge asks the big model whether an answer matches the reference. Two small but important choices:

  • The brief tested "HARD" in reply; we take the first EASY/HARD word, and an unclear reply goes to the big model (the safe side).
  • The brief tested "INCORRECT" not in reply, which scores an empty reply as CORRECT. We accept only a clear CORRECT and count unclear replies (the report shows how many).

There is also a rule (a regular expression) that sends obvious hard questions (code words, "why", "compare", arithmetic) to the big model without any model call. We use it on Day 3.

src/llmrouter/routing.py
"""The router: decide SMALL or BIG for one question.

Two kinds of router:
* classifier router  - ask the small model "EASY or HARD?" (prompt version v1 or v2)
* rules + classifier - a regular expression sends obvious hard questions (code, maths,
                       "why", "compare") straight to the big model with no model call;
                       everything else goes to the classifier.
"""

from __future__ import annotations

import re
import time
from dataclasses import dataclass

from llmrouter.llm.base import ChatModel
from llmrouter.prompts import CLASSIFY

# Words that almost always mean "needs several steps" in our question set.
HARD_RULE = re.compile(
    r"\b(python|sql|code|function|print|bug|complexity|why|compare|explain|solve|calculate)\b"
    r"|\d+\s*[-+*/x%]\s*\d+",  # arithmetic such as 3 * 4, 20%
    re.IGNORECASE,
)


@dataclass(frozen=True)
class Route:
    label: str  # "EASY" or "HARD"
    role: str  # "small" or "big": which model answers
    raw: str  # what the classifier actually said ("" when a rule decided)
    rule: bool  # True when the regex decided and no model was called
    seconds: float  # time spent deciding (counts as latency)
    input_tokens: int = 0
    output_tokens: int = 0


def parse_label(text: str) -> str | None:
    """First EASY/HARD word in the reply wins. None if neither word appears.

    The brief's version was `"HARD" in reply.upper()`, which also sends "EASY (not hard)"
    to the big model; taking the first word is closer to what the model meant.
    """
    found = re.search(r"\b(EASY|HARD)\b", text.upper())
    return found.group(1) if found else None


def classify(small: ChatModel, question: str, version: str = "v1") -> Route:
    prompt = CLASSIFY[version].format(question=question)
    reply = small.chat([{"role": "user", "content": prompt}], max_tokens=8)
    label = parse_label(reply.text)
    if label is None:  # unclear reply: play safe and use the big model
        label = "HARD"
    return Route(
        label=label,
        role="big" if label == "HARD" else "small",
        raw=reply.text,
        rule=False,
        seconds=reply.seconds,  # the model call, timed by the client (a lazy load is excluded)
        input_tokens=reply.input_tokens,
        output_tokens=reply.output_tokens,
    )


def rule_route(question: str) -> Route | None:
    start = time.perf_counter()
    if HARD_RULE.search(question):
        return Route("HARD", "big", "", True, time.perf_counter() - start)
    return None

"""LLM-as-a-judge: the big model compares an answer with the reference answer."""

from __future__ import annotations

import re
from dataclasses import dataclass

from llmrouter.llm.base import ChatModel
from llmrouter.prompts import JUDGE


@dataclass(frozen=True)
class Verdict:
    correct: bool
    parsed: bool  # False when the judge said neither CORRECT nor INCORRECT
    raw: str
    seconds: float


def parse_verdict(text: str) -> bool | None:
    """INCORRECT / NOT CORRECT -> False, CORRECT -> True, anything else -> None.

    The brief's version was `"INCORRECT" not in reply.upper()`, which counts an empty or
    off-topic reply as CORRECT. Here an unclear reply is None and is scored as wrong.
    """
    t = text.upper()
    if re.search(r"\bINCORRECT\b|\bNOT\s+CORRECT\b", t):
        return False
    if re.search(r"\bCORRECT\b", t):
        return True
    return None


def judge(model: ChatModel, question: str, reference: str, answer: str, version: str = "v1"):
    prompt = JUDGE[version].format(question=question, reference=reference, answer=answer)
    reply = model.chat([{"role": "user", "content": prompt}], max_tokens=8)
    ok = parse_verdict(reply.text)
    return Verdict(correct=bool(ok), parsed=ok is not None, raw=reply.text, seconds=reply.seconds)

13 Step 9: The Comparison Runner (store.py, experiment.py)

A shop that writes every sale in a ledger: if the power goes off, it reopens and continues from the last line instead of starting the day again.

The runner tries each strategy on every question. Three cache files make it cheap and resumable:

  • answers.json: one answer per (model, question), shared by all strategies, so "router" reuses what "small-only" and "big-only" already paid for.
  • routes-v1.json: the classifier's label per question.
  • verdicts-v1.json: the judge's verdict per (answering model, question).

Plus one file per strategy with its finished rows, as the brief asks ("save each strategy's results so a rerun skips what's done"). A naive run makes about 280 calls (3 strategies × 40 × answer + judge, plus 40 labels); with the shared caches it is 80 answers + 80 verdicts + 40 labels = 200, and a rerun makes 0.

Latency of one question = routing time + answer time. Judge time is not latency: a real user never waits for a judge. The file also has the oracle (a perfect router that already knows which answers are right: the best any router could do) and an assumed cost column.

"""A tiny JSON file store, so an interrupted run resumes instead of paying again.

Each file is one dict {key: record}. Every put() rewrites the file atomically
(write to a temp file, then rename), so a crash never leaves half a file behind.
"""

from __future__ import annotations

import json
import os
from pathlib import Path


class JsonStore:
    def __init__(self, path: Path) -> None:
        self.path = Path(path)
        self.data: dict = {}
        if self.path.exists():
            self.data = json.loads(self.path.read_text(encoding="utf-8"))

    def __contains__(self, key: str) -> bool:
        return key in self.data

    def __len__(self) -> int:
        return len(self.data)

    def get(self, key: str):
        return self.data.get(key)

    def put(self, key: str, value) -> None:
        self.data[key] = value
        self.path.parent.mkdir(parents=True, exist_ok=True)
        tmp = self.path.with_suffix(self.path.suffix + ".tmp")
        text = json.dumps(self.data, indent=1, ensure_ascii=False, sort_keys=True)
        tmp.write_bytes((text + "\n").encode("utf-8"))  # bytes: same LF file on every OS
        os.replace(tmp, self.path)

"""The measurement: run each strategy over the same questions and compare.

Strategies
  small-only    every question -> small model
  big-only      every question -> big model
  router-v1     small model classifies (brief's prompt), then the chosen model answers
  router-v2     same, with the few-shot classifier prompt
  router-rules  regex rule first (no model call), classifier v1 for the rest

Latency of one question = routing time + answer time (judge time is NOT latency: in real
use there is no judge). All model calls go through three caches in results/<provider>/:
  answers.json     model + question -> answer      (shared by every strategy)
  routes-<v>.json  classifier label per question
  verdicts-<v>.json judge verdict per (answering model, question)
so 'router' reuses the answers 'small-only' and 'big-only' already paid for, and a
crashed or rate-limited run resumes where it stopped. With greedy decoding (local
models) a repeated call would return the same text, so reuse changes nothing but cost.
Each strategy's per-question results are also saved: strategy-<name>__judge-<v>.json.
"""

from __future__ import annotations

import statistics
import time
from collections.abc import Callable
from pathlib import Path

from llmrouter.data import Case
from llmrouter.judge import judge
from llmrouter.llm.base import ChatModel
from llmrouter.prompts import ANSWER_SYSTEM
from llmrouter.routing import classify, rule_route
from llmrouter.store import JsonStore

STRATEGIES = ("small-only", "big-only", "router-v1", "router-v2", "router-rules")

# ASSUMED prices (USD per million tokens) used only for the cost column: what the same
# token counts would cost at Claude Haiku 5.5 (small) and Claude Opus 5.5 (big) list prices,
# as cached on 3 Nov 2026. Local Qwen tokens are not Claude tokens, so this is a rough guide.
PRICES = {"small": (0.10, 0.50), "big": (4.00, 20.00)}


class Experiment:
    def __init__(
        self,
        models: dict[str, ChatModel],
        results_dir: Path,
        *,
        max_answer_tokens: int = 384,
        sleep_s: float = 0.0,
        log: Callable[[str], None] = print,
    ) -> None:
        self.models = models
        self.dir = Path(results_dir)
        self.max_answer_tokens = max_answer_tokens
        self.sleep_s = sleep_s
        self.log = log
        self.answers = JsonStore(self.dir / "answers.json")
        self._stores: dict[str, JsonStore] = {}
        self.calls_made = 0  # real model calls in this process (cache hits not counted)

    # ---------------------------------------------------------------- cached model calls
    def _pause(self) -> None:
        self.calls_made += 1
        if self.sleep_s:
            time.sleep(self.sleep_s)  # free-tier rate limit; not part of measured latency

    def answer(self, role: str, case: Case) -> dict:
        model = self.models[role]
        key = f"{model.name}::{case.id}"
        if key not in self.answers:
            messages = [
                {"role": "system", "content": ANSWER_SYSTEM},
                {"role": "user", "content": case.question},
            ]
            r = model.chat(messages, max_tokens=self.max_answer_tokens)
            self.answers.put(
                key,
                {
                    "text": r.text,
                    "seconds": round(r.seconds, 4),
                    "input_tokens": r.input_tokens,
                    "output_tokens": r.output_tokens,
                    "finish": r.finish,
                },
            )
            self.log(f"  answer {role:5s} {case.id}  {r.seconds:6.2f}s  {r.output_tokens} tokens")
            self._pause()
        return self.answers.get(key)

    def route(self, case: Case, version: str) -> dict:
        if version == "rules":
            hit = rule_route(case.question)
            if hit:
                return {
                    "label": hit.label,
                    "role": hit.role,
                    "raw": "",
                    "rule": True,
                    "seconds": round(hit.seconds, 6),
                    "input_tokens": 0,
                    "output_tokens": 0,
                }
            version = "v1"
        store = self._store(f"routes-{version}.json")
        key = f"{self.models['small'].name}::{case.id}"
        if key not in store:
            r = classify(self.models["small"], case.question, version)
            store.put(
                key,
                {
                    "label": r.label,
                    "role": r.role,
                    "raw": r.raw,
                    "rule": False,
                    "seconds": round(r.seconds, 4),
                    "input_tokens": r.input_tokens,
                    "output_tokens": r.output_tokens,
                },
            )
            self.log(f"  route  {version}   {case.id}  {r.seconds:6.2f}s  -> {r.label}")
            self._pause()
        return store.get(key)

    def verdict(self, role: str, case: Case, version: str) -> dict:
        ans = self.answer(role, case)
        store = self._store(f"verdicts-{version}.json")
        key = f"{self.models['judge'].name}::{self.models[role].name}::{case.id}"
        if key not in store:
            v = judge(self.models["judge"], case.question, case.reference, ans["text"], version)
            store.put(
                key,
                {
                    "correct": v.correct,
                    "parsed": v.parsed,
                    "raw": v.raw,
                    "seconds": round(v.seconds, 4),
                },
            )
            self.log(f"  judge  {version}   {case.id}  {role:5s} -> {v.raw!r}")
            self._pause()
        return store.get(key)

    def _store(self, name: str) -> JsonStore:
        if name not in self._stores:
            self._stores[name] = JsonStore(self.dir / name)
        return self._stores[name]

    # ---------------------------------------------------------------- strategies
    def run_strategy(self, name: str, cases: list[Case], judge_version: str = "v1") -> list[dict]:
        if name not in STRATEGIES:
            raise ValueError(f"unknown strategy {name!r}; choose from {STRATEGIES}")
        out = self._store(f"strategy-{name}__judge-{judge_version}.json")
        self.log(f"[{name}] judge {judge_version}: {len(out)}/{len(cases)} already done")
        for case in cases:
            if case.id in out:
                continue  # resume: this question is finished for this strategy
            if name == "small-only":
                route = {
                    "label": "-",
                    "role": "small",
                    "raw": "",
                    "rule": False,
                    "seconds": 0.0,
                    "input_tokens": 0,
                    "output_tokens": 0,
                }
            elif name == "big-only":
                route = {
                    "label": "-",
                    "role": "big",
                    "raw": "",
                    "rule": False,
                    "seconds": 0.0,
                    "input_tokens": 0,
                    "output_tokens": 0,
                }
            else:
                route = self.route(case, name.removeprefix("router-"))
            ans = self.answer(route["role"], case)
            ver = self.verdict(route["role"], case, judge_version)
            out.put(
                case.id,
                {
                    "id": case.id,
                    "level": case.level,
                    "category": case.category,
                    "label": route["label"],
                    "route_raw": route["raw"],
                    "rule": route["rule"],
                    "role": route["role"],
                    "model": self.models[route["role"]].name,
                    "route_s": route["seconds"],
                    "answer_s": ans["seconds"],
                    "latency_s": round(route["seconds"] + ans["seconds"], 4),
                    "correct": ver["correct"],
                    "judge_parsed": ver["parsed"],
                    "judge_raw": ver["raw"],
                    "finish": ans["finish"],
                    "route_tokens": [route["input_tokens"], route["output_tokens"]],
                    "answer_tokens": [ans["input_tokens"], ans["output_tokens"]],
                },
            )
        return [out.get(c.id) for c in cases]


# -------------------------------------------------------------------- summaries
def summarize(name: str, records: list[dict]) -> dict:
    n = len(records)
    lat = [r["latency_s"] for r in records]
    by_level = {
        lvl: sum(r["correct"] for r in records if r["level"] == lvl) for lvl in ("easy", "hard")
    }
    totals = {lvl: sum(r["level"] == lvl for r in records) for lvl in ("easy", "hard")}
    return {
        "strategy": name,
        "n": n,
        "correct": sum(r["correct"] for r in records),
        "accuracy": round(sum(r["correct"] for r in records) / n, 4) if n else 0.0,
        "easy_correct": f"{by_level['easy']}/{totals['easy']}",
        "hard_correct": f"{by_level['hard']}/{totals['hard']}",
        "avg_latency_s": round(statistics.fmean(lat), 2) if lat else 0.0,
        "median_latency_s": round(statistics.median(lat), 2) if lat else 0.0,
        "sent_to_big": sum(r["role"] == "big" for r in records),
        "big_share": round(sum(r["role"] == "big" for r in records) / n, 4) if n else 0.0,
        "avg_route_s": round(statistics.fmean(r["route_s"] for r in records), 3) if n else 0.0,
        "cost_usd_assumed": round(cost_usd(records), 5),
        "unparsed_verdicts": sum(not r["judge_parsed"] for r in records),
        "cut_off_answers": sum(r["finish"] != "stop" for r in records),
    }


def cost_usd(records: list[dict]) -> float:
    """ASSUMED cost: routing tokens at small prices + answer tokens at the answering role's."""
    total = 0.0
    for r in records:
        pin, pout = PRICES["small"]
        total += (r["route_tokens"][0] * pin + r["route_tokens"][1] * pout) / 1e6
        pin, pout = PRICES[r["role"]]
        total += (r["answer_tokens"][0] * pin + r["answer_tokens"][1] * pout) / 1e6
    return total


def oracle(small: list[dict], big: list[dict]) -> list[dict]:
    """A perfect router that KNOWS which answers are right: small if small was correct,
    else big. Not a real strategy (it needs the answers first); it is the upper bound."""
    out = []
    for s, b in zip(small, big, strict=True):
        pick = s if s["correct"] or not b["correct"] else b
        out.append({**pick, "label": "oracle", "route_s": 0.0})
    return out


def routing_confusion(records: list[dict]) -> dict:
    """How the router's choice compares with OUR easy/hard label (from questions.jsonl)."""
    m = {"easy->small": 0, "easy->big": 0, "hard->small": 0, "hard->big": 0}
    for r in records:
        m[f"{r['level']}->{r['role']}"] += 1
    return m

def sample(
    results_dir: Path, cases: list[Case], version: str, n: int = 10, seed: int = 7
) -> list[dict]:
    by_id = {c.id: c for c in cases}
    verdicts = JsonStore(Path(results_dir) / f"verdicts-{version}.json").data
    answers = JsonStore(Path(results_dir) / "answers.json").data
    keys = sorted(verdicts)
    # half easy, half hard, so the check is not all trivial facts

    easy = [k for k in keys if by_id[k.rsplit("::", 1)[1]].level == "easy"]
    hard = [k for k in keys if by_id[k.rsplit("::", 1)[1]].level == "hard"]
    picked = rng.sample(easy, min(n // 2, len(easy))) + rng.sample(hard, min(n - n // 2, len(hard)))
    rows = []
    for key in sorted(picked, key=lambda k: k.rsplit("::", 1)[1]):
        _judge, model, qid = key.split("::")
        case = by_id[qid]
        rows.append(

                "key": key,
                "id": qid,
                "model": model,
                "question": case.question,
                "reference": case.reference,
                "answer": answers[f"{model}::{qid}"]["text"],
                "judge": "CORRECT" if verdicts[key]["correct"] else "INCORRECT",
                "human": None,
                "note": "",
            }
        )
    return rows


def write_rows(path: Path, rows: list[dict]) -> None:

def read_rows(path: Path) -> list[dict]:

def agreement(rows: list[dict]) -> dict:
    labelled = [r for r in rows if r["human"] is not None]
    disagree = [r for r in labelled if r["human"] != (r["judge"] == "CORRECT")]
    return {

        "agree": len(labelled) - len(disagree),
        "disagree": len(disagree),

        "verdict": "OK (at most 1 disagreement)"

def compare_with_labels(
    results_dir: Path, labels: list[dict], version: str, judge_model: str

        "judge": version,
        "compared": n,
        "agree": n - len(lenient) - len(strict),
        "agreement": round((n - len(lenient) - len(strict)) / n, 4) if n else 0.0,
        "too_lenient": lenient,
        "too_strict": strict,
    }

    if not labels:

                        "question": by_id[r["id"]].question,
                    }
                    for r in recs
                    if (r["level"] == "hard") != (r["role"] == "big")
                ],
            }
    extra = None
    if "small-only" in records and "big-only" in records:
        best = oracle(records["small-only"], records["big-only"])
        extra = {**summarize("oracle (upper bound)", best), "reviewer_correct": None}
        both = sum(
            s["correct"] and b["correct"]
            for s, b in zip(records["small-only"], records["big-only"], strict=True)
        )
        small_wins = sum(
            s["correct"] and not b["correct"]
            for s, b in zip(records["small-only"], records["big-only"], strict=True)
        )
        extra["note"] = (
            f"both right {both}, only small right {small_wins}, "
            f"needs big {extra['correct'] - both - small_wins}"
        )
    reviewed_oracle = None
    if extra and labels and reviewer_correct(records["small-only"], labels) is not None:
        # the same perfect router, but "right" means right by the person's labels
        def relabel(recs):
            return [{**r, "correct": labels[f"{r['model']}::{r['id']}"]} for r in recs]

        best = oracle(relabel(records["small-only"]), relabel(records["big-only"]))
        reviewed_oracle = summarize("oracle (reviewer labels)", best)
    return {
        "date": date.today().isoformat(),
        "judge": judge_version,
        "meta": meta,
        "rows": rows,
        "oracle": extra,
        "oracle_reviewer": reviewed_oracle,
        "routers": routers,
        "judge_agreement": agreement,
    }

def _experiment(s: Settings, cases, quiet: bool = False) -> Experiment:
    from llmrouter.llm import build_models

    models = build_models(s, cases)  # local models load lazily, on first use (llm/__init__.py)

    )

def cmd_report(args) -> int:
    from llmrouter import report

    s = _settings(args)
    cases = load_cases(s.questions_path)
    meta = report.environment(s)
    labels, agreement = None, None
    label_file = s.reports_dir / "review_labels.jsonl"  # a person's verdicts, if you made them
    if label_file.exists():
        from llmrouter import judge_check

        rows = judge_check.read_rows(label_file)
        labels = {r["key"]: r["human"] for r in rows if r["human"] is not None}
        agreement = judge_check.compare_with_labels(_results_dir(s), rows, s.judge_prompt, s.judge)
    summary = report.build(
        _results_dir(s), cases, s.judge_prompt, STRATEGIES, meta, labels, agreement
    )

    for r in summary["rows"] + ([summary["oracle"]] if summary["oracle"] else []):
        rev = r.get("reviewer_correct")
        print(

            f"avg latency {r['avg_latency_s']:6.2f}s  sent to big model {r['big_share']:.0%}"
            + ("" if rev is None else f"  (reviewer-graded {rev}/{r['n']})")
        )
    print(f"wrote {path}")
    return 0


def cmd_ask(args) -> int:
    from llmrouter.data import Case

    s = _settings(args)
    exp = _experiment(s, [], quiet=True)
    case = Case(id="cli", level="easy", category="", question=args.question, reference="")
    from llmrouter.prompts import ANSWER_SYSTEM
    from llmrouter.routing import classify, rule_route

    route = (rule_route(case.question) if args.router == "rules" else None) or classify(
        exp.models["small"], case.question, "v1" if args.router == "rules" else args.router
    )
    model = exp.models[route.role]
    reply = model.chat(
        [{"role": "system", "content": ANSWER_SYSTEM}, {"role": "user", "content": case.question}],
        max_tokens=s.max_answer_tokens,
    )
    how = "rule" if route.rule else f"classifier said {route.raw!r}"
    print(
        f"route : {route.label} -> {route.role} model ({model.name})  [{how}, {route.seconds:.2f}s]"
    )
    print(f"answer: {reply.text}")
    print(
        f"time  : {route.seconds + reply.seconds:.2f}s total ({route.seconds:.2f}s routing + "
        f"{reply.seconds:.2f}s answer, {reply.output_tokens} tokens)"
    )
    return 0

    s = _settings(args)

"""HTTP API.   Run:  llmrouter serve   then open http://127.0.0.1:8000/docs"""

from __future__ import annotations

from contextlib import asynccontextmanager

from fastapi import FastAPI, Request
from pydantic import BaseModel, Field

from llmrouter import __version__
from llmrouter.config import Settings, get_settings
from llmrouter.prompts import ANSWER_SYSTEM
from llmrouter.routing import classify, rule_route


class AskRequest(BaseModel):
    question: str = Field(min_length=1, max_length=2000, examples=["What is the capital of Peru?"])
    router: str = Field("v1", pattern=r"^(v1|v2|rules)$")


class AskResponse(BaseModel):
    label: str
    model: str
    rule: bool
    answer: str
    route_s: float
    answer_s: float
    total_s: float
    output_tokens: int


def create_app(settings: Settings | None = None, models: dict | None = None) -> FastAPI:
    @asynccontextmanager
    async def lifespan(app: FastAPI):
        from llmrouter.llm import build_models

        app.state.models = models or build_models(settings or get_settings())
        yield

    app = FastAPI(title="LLM Router", version=__version__, lifespan=lifespan)

    @app.get("/healthz")
    def healthz() -> dict:
        return {"status": "ok"}

    @app.get("/v1/models")
    def list_models(request: Request) -> dict:
        return {role: m.name for role, m in request.app.state.models.items()}

    @app.post("/v1/ask", response_model=AskResponse)
    def ask(body: AskRequest, request: Request) -> dict:
        # plain `def`: FastAPI runs it in a thread pool, so blocking model calls are fine
        m = request.app.state.models
        route = (rule_route(body.question) if body.router == "rules" else None) or classify(
            m["small"], body.question, "v1" if body.router == "rules" else body.router
        )
        reply = m[route.role].chat(
            [
                {"role": "system", "content": ANSWER_SYSTEM},
                {"role": "user", "content": body.question},
            ],
            max_tokens=(settings or get_settings()).max_answer_tokens,
        )
        return {
            "label": route.label,
            "model": m[route.role].name,
            "rule": route.rule,
            "answer": reply.text,
            "route_s": round(route.seconds, 4),
            "answer_s": round(reply.seconds, 4),
            "total_s": round(route.seconds + reply.seconds, 4),
            "output_tokens": reply.output_tokens,
        }

    return app


app = create_app()

"""Turn reports/demo_output.txt into docs/demo.gif (a ~20-second terminal animation).

    pip install -e ".[demo]"      (Pillow)
    python scripts/make_demo_gif.py

Commands are "typed" letter by letter, outputs appear line by line. The text is the real
saved output of scripts/record_demo.py; the GIF only animates it (not a screen capture).
"""

from __future__ import annotations

import sys
import textwrap
from pathlib import Path

from PIL import Image, ImageDraw, ImageFont

ROOT = Path(__file__).resolve().parent.parent
WIDTH, HEIGHT, PAD, COLS = 960, 400, 18, 86
BG, FG, CMD, DIM = (24, 26, 33), (220, 223, 228), (126, 231, 135), (139, 148, 158)


def font(size: int = 16):
    for name in ("consola.ttf", "DejaVuSansMono.ttf", "Menlo.ttc"):
        try:
            return ImageFont.truetype(name, size)
        except OSError:
            continue
    return ImageFont.load_default(size=size)


def frame(lines: list[tuple[str, tuple]], fnt, line_h: int) -> Image.Image:
    img = Image.new("RGB", (WIDTH, HEIGHT), BG)
    d = ImageDraw.Draw(img)
    for i, color in enumerate([(255, 95, 86), (255, 189, 46), (39, 201, 63)]):  # window dots
        d.ellipse((PAD + i * 22, 10, PAD + i * 22 + 12, 22), fill=color)
    visible = lines[-((HEIGHT - 40) // line_h) :]
    for i, (text, color) in enumerate(visible):
        d.text((PAD, 34 + i * line_h), text, font=fnt, fill=color)
    return img


def main() -> int:
    src = ROOT / "reports" / "demo_output.txt"
    raw = src.read_text(encoding="utf-8").splitlines()
    fnt, line_h = font(16), 21
    frames, durations, shown = [], [], []
    for line in raw:
        if line.startswith("$ "):
            for n in range(2, len(line) + 1, 3):  # type the command, 3 letters per frame
                frames.append(frame([*shown, (line[:n] + "_", CMD)], fnt, line_h))
                durations.append(60)
            shown.append((line, CMD))
            frames.append(frame(shown, fnt, line_h))
            durations.append(1800)  # "thinking"
            continue
        for part in textwrap.wrap(line, COLS) or [""]:
            shown.append((part, DIM if part.startswith(("route", "time")) else FG))
            frames.append(frame(shown, fnt, line_h))
            durations.append(1100)
    durations[-1] = 5000  # hold the last frame
    out = ROOT / "docs" / "demo.gif"
    out.parent.mkdir(exist_ok=True)
    frames[0].save(out, save_all=True, append_images=frames[1:], duration=durations, loop=0)
    print(f"wrote {out}: {len(frames)} frames, {sum(durations) / 1000:.1f} s")
    return 0


if __name__ == "__main__":
    sys.exit(main())

# 3-day build roadmap (easy language)

Goal: build an **LLM router** and, more important, **measure it**. Easy questions go to a small,
fast model; hard ones go to a big, slow model. At the end you have one table that compares
"small only", "big only" and "router" on the same 40 questions, plus one improved router.

seconds: a small cut goes to the nurse's own table, a strange pain goes to the specialist
(the big model). The project asks: does the front desk save time **without** sending sick
people home?

Time needed: about 3 days of 4-6 hours. Most of day 2 is waiting for models to answer.

## Day 1 - the parts (about 5 hours)

**1. Set up (30 min).** Make the folder, a virtual environment and `pyproject.toml`.
`pip install -e ".[dev,local]"`. Check: `python -c "import llmrouter"`.

**2. Settings (20 min) - `config.py`.** One `Settings` class reads `ROUTER_*` variables.
Why: you will switch between the local models, a fake model for tests and a real API without
touching code.

**3. The test set (60 min) - `questions.jsonl`.** 20 easy (8 facts, 6 definitions,
6 short rewrites) and 20 hard (8 multi-step maths, 6 code, 6 "compare/explain why").
Every line has a short reference answer. **Check every maths answer with Python** (we did:
for example the sum of the multiples of 3 or 5 up to 200 really is 9368). Write
`holdout_questions.jsonl` too: 20 different questions you never look at while tuning.

**4. Load the data (15 min) - `data.py`.** Reject a wrong level, a missing field or a
duplicate id early, with the line number.

**5. Model clients (60 min) - `llm/`.** One tiny interface: `chat(messages, max_tokens)`
returns text, token counts and seconds. Write the local client first (Hugging Face
`transformers`, greedy decoding so answers repeat exactly), then the fake one for tests.
The Anthropic and OpenAI-compatible clients are templates you run only if you have a key.

**6. Prompts (15 min) - `prompts.py`.** Copy the brief's classifier and judge prompts
word for word as `v1`. Rule: never edit a prompt in place, add `v2`. Saved results are
filed under the version, so old numbers stay valid.

**7. Router + judge (45 min) - `routing.py`, `judge.py`.** Parse the reply carefully:
the brief's `"INCORRECT" not in reply` counts an empty reply as CORRECT, so we only accept
a clear CORRECT and score anything else as wrong (and count how often it happens).

**8. Tests (30 min).** `pytest` - all offline with the fake model.

```mermaid
flowchart LR
```

## Is the judge right? (we checked)

1. **The brief's check:** 10 random verdicts (5 easy, 5 hard), read by hand: `reports/judge_check_v1.jsonl`. 10/10 agreed, so by the
   brief's rule ("more than 1 of 10 wrong → make it stricter") nothing needed to change.
2. **The full check:** all 80 answers labelled, then compared with every verdict (`llmrouter judge-agree`): judge v1 agreed on
   **72/80**. 7 of its 8 mistakes were *lenient*: CORRECT for "50 minutes" when the answer is 5, for "−4%" and "a
   decrease of 40%" in the same answer, for a wrong bug diagnosis. The 10-sample missed them because they sit in the hard answers.
3. **Judge v2** (`prompts.py`) adds one rule per mistake seen: no final answer → wrong; two different answers → wrong; wrong reason
   when the question asks why → wrong; a rewrite must keep the meaning. **It made things worse: 65/80**
   (9 too lenient, 6 too strict). The 3B judge still passed the same wrong hard answers ("50 minutes",
   "−4% and −40%") and now failed right answers that had a harmless wrong side detail. A longer rubric does not make a small
   judge smarter. Its total for the small model (29/40) even equals the reviewer's 29/40, but on different answers: matching
   totals can hide poor answer-by-answer agreement. (Judge v2 ran in float32; reading long prompts in bfloat16 was about 5×
   slower on this CPU. The answers it graded are the same cached answers.)
4. **Decision:** the headline accuracy is the reviewer column; of the two automatic judges, v1 is the better one. A stronger
   judge model, or extracting the final number and comparing it exactly for the maths questions, is the next step.

Other things that failed on the way:

* The first speed test gave 4 tokens/s for the 0.5B model: generating text on a CPU is limited by memory speed. bfloat16 (half the
  bytes) was 1.6× faster than float32 and 6 threads beat 10 (6 performance cores). Reading long prompts, though, was ~5× *slower*
  in bfloat16, hence float32 for the judge-only run.
* The brief's parsers were too trusting: `"INCORRECT" not in reply` scores an empty reply as CORRECT, and `"HARD" in reply` routes
  "EASY (not hard)" to the big model. Both are stricter here, with tests.
* Models now load lazily: a re-judging run never loads the small model, and loading time can never leak into a latency.

**Why the router did not win here:** every question pays an extra model call, a 0.5B model is a weak classifier, and on a CPU even a
one-word reply needs the whole prompt to be read first. The oracle shows the prize is real: 35/40 at 7.8 s per
question instead of 32/40 at 17.1 s, if routing were perfect and free.

## What I'd build next

1. A **cheap trained router**: logistic regression on sentence embeddings, trained on labelled questions; milliseconds per decision
   instead of seconds.
2. **Rule + few-shot together**, then a fresh, bigger hold-out set (40 questions is 2.5% per answer).
3. **A better judge**: a stronger model as judge, plus exact matching of the final number for maths questions.
4. **Route on cost as well as latency** with real API prices, and run the same table on Claude Haiku/Opus or Groq.
5. A **confidence fallback**: if the small model's answer looks unsure, escalate to the big model.

21 What We Did, What Failed, What We Changed

A cooking diary: the first cake sank, so you changed the oven and wrote it down. This is the diary, so you know why each line of the final recipe is the way it is.

What we did, in the real order (20–21 November 2026)

  1. Chose local models instead of an API. The build machine had no API key, so we used two open models from one family: Qwen2.5-0.5B-Instruct (small) and Qwen2.5-3B-Instruct (big and judge). Download: about 1 GB + 6 GB at ~3 MB/s.
  2. The first speed test was 4 tokens per second for the 0.5B model, far too slow. Measuring showed that writing text on a CPU is limited by memory speed. bfloat16 (half the bytes) gave 17.9 tokens/s against 10.9 in float32, and 6 threads beat 10. We made bfloat16 the default.
  3. Run 1 (small-only, big-only, router v1, judge v1): 200 real model calls in 40 minutes. Judge v1 said small 32/40, big 35/40, router 35/40.
  4. The judge check passed... and was wrong. The brief's 10-verdict sample agreed 10/10 with the reviewer. But a review of all 80 answers agreed only 72/80: 7 times the judge said CORRECT for a wrong answer (for example "50 minutes" for 5 minutes, or "−4%" and "−40%" in one answer). A random 10 can miss a problem that sits in the hard answers.
  5. Judge v2 was written from those exact mistakes (two different final answers, no final answer, a wrong reason, a rewrite that changes the meaning). It made grading worse: 65/80 (9 too lenient, 6 too strict). The 3B judge still passed the same wrong hard answers and now failed right ones with a harmless wrong side detail: a longer rubric does not make a small judge smarter. So the headline accuracy is the reviewer's, and v1 stays the better automatic judge. Reading long prompts was very slow in bfloat16 on this CPU (a 120-token prompt on the 3B model: 57 s vs 11 s in float32), so the v2 judge ran in float32. The answers did not change: they come from the cache.
  6. Router v1 misroutes: 13 of 20 easy questions were called HARD ("What is the capital of Australia?"), and 4 hard ones EASY (algebra, two "what does this code print", SQL). So it sent 72% to the big model and saved little time.
  7. Improvement 1, few-shot (router v2): 8 labelled examples (none from the test set). It fixed the easy questions (16/20 right) but now sent 10 hard ones to the small model, and its longer prompt took 4.9 s per decision instead of 1.6 s.
  8. Improvement 2, rule (router rules): a regex for code words, "why", "compare" and arithmetic, then the v1 classifier. It sent every hard question to the big model (82% to big in total), so quality stayed at big-only level but it was not faster.
  9. Hold-out check (20 new questions, labels only): v1 12/20, v2 11/20, rules 14/20. The improvements did not carry over strongly: the 0.5B classifier is the weak part.
  10. Two code fixes found while measuring: models now load lazily (a judge-only run never loads the small model: about 1–2 GB less RAM, and loading time can never leak into a latency), and routing time is taken from the model client's own timer.

Why the router did not win on a CPU

  • The router pays one extra model call (the classification) on every question. On a CPU even a one-word answer from the small model costs ~1.5 s because the whole prompt must be read first.
  • A 0.5B model is a weak classifier: it either calls everything HARD (v1) or misses maths and code (v2).
  • The oracle shows the size of the prize: if routing were free and perfect, 35/40 at 7.8 s per question instead of 32/40 at 17.1 s. Better routers (a tiny trained classifier, the regex rule plus few-shot, or a fast API classifier) are the next step.

What we chose NOT to do (and why)

  • A paid API run: no key on the build machine; the Claude and OpenAI-compatible clients are ready to run.
  • Combining rule + few-shot: the brief says "try one change"; we tried two, separately, and list the combination as the next step instead of tuning more on the same 40 questions.
  • A GPU run: the CUDA build of PyTorch was not installed (see the GPU section).

22 Do You Need a GPU?

A bicycle or a motorbike for the same trip. The bicycle (CPU) gets you there; the motorbike (GPU) is faster, but you need to buy fuel (the CUDA build of PyTorch, ~2.5 GB) and know how to ride it.

Short answer: a CPU is enough, and all numbers on this page were measured on one. On the build laptop (Intel Core i7-13620H, 24 GB RAM, CPU only) one big-model answer took 17.1 s on average and one small-model answer 6.3 s; the full first run took about 40 minutes.

Why CPU is fine for this project

  • The project is about the comparison (small vs big vs router), not about raw speed. On a CPU the gap between the 0.5B and the 3B model is large and easy to see, which makes the trade-off clear.
  • Anyone can repeat it: no driver, no CUDA version to match, no cloud bill.
  • It runs only once (the caches keep every answer), so an hour of waiting is acceptable.

When a GPU helps, and how (not run here)

The build laptop has an NVIDIA GeForce RTX 5050 Laptop GPU with 8 GB of memory, but the installed PyTorch is the CPU-only build, so it was not used. The 3B model in 16-bit needs about 6 GB, so it would fit. To try it:

  1. Install a CUDA build of PyTorch with the command that pytorch.org/get-started/locally gives for your system (new RTX 50-series cards need a recent CUDA build).
  2. Check: python -c "import torch; print(torch.cuda.is_available())" must print True.
  3. Set ROUTER_DEVICE=cuda and ROUTER_DTYPE=float16 in .env.
  4. Delete nothing: use a new results folder (ROUTER_RESULTS_DIR=results-gpu), so CPU and GPU numbers are never mixed.
Expect a different trade-off on a GPU. Both models get much faster, so the router saves fewer seconds per question, while the classification call still costs one extra round trip. The same happens with fast cloud APIs. Measure again and report both settings separately; never mix CPU and GPU latencies in one table.

25 Interview Questions (With Answers)

A. Basics

Q: What is an LLM router?

Code that picks which model answers each request, usually a cheap fast one for easy requests and a strong slow one for hard requests, to save time or money without losing much quality.

Q: How does your router decide?

The small model reads the question and replies EASY or HARD (one word). Optionally a regex sends obvious hard questions (code words, why, compare, arithmetic) straight to the big model with no model call.

Q: Why compare against small-only and big-only?

They are the two limits: the router is only worth it if it is close to big-only quality and clearly cheaper or faster than big-only.

Q: What is the oracle row?

A perfect router that already knows which answers are right. It is the upper bound: how much any router could gain on this data.

B. Evaluation

Q: How do you know your LLM judge is right?

We checked it. The brief's 10-sample check agreed 10/10, but a review of all 80 answers agreed only 72/80, mostly too lenient on wrong hard answers. A stricter prompt written from those errors made it worse (65/80), so we report reviewer-graded accuracy and keep v1 as the better judge.

Q: Why can a 10-item check mislead?

With few items, a problem concentrated in one group (here wrong hard answers from the small model) may not be in the sample at all. Sample by group, or label everything if the set is small.

Q: Why a hold-out set?

The improved routers were designed after looking at the 40 test questions, so they may be tuned to them. 20 new questions check whether the improvement carries over.

Q: What counts as latency?

Routing time + answer time. Judge time does not, because a real user never waits for a judge.

C. Design and production

Q: Why did the router not save much time?

Every question pays an extra classification call, and on a CPU even a one-word reply costs time because the prompt must be read first (1.6 s for v1, 4.9 s for the longer few-shot prompt). And a 0.5B classifier makes many mistakes.

Q: How would you make routing cheaper?

A tiny trained classifier (logistic regression on embeddings, or a BERT-size model) that answers in milliseconds, rules for obvious cases, caching the decision per question, or a fast API model.

Q: How do you keep a long, rate-limited run safe?

Cache every call to disk (answers, labels, verdicts) with atomic writes; a rerun skips finished work, so a crash or a free-tier limit only pauses the run.

Q: Why did you use bfloat16 for answers but float32 for the judge?

Generating text is limited by memory speed, so fewer bytes (bfloat16) is faster; reading a long prompt is limited by maths speed, and this CPU has no fast bfloat16 maths, so float32 was about 5 times faster for the judge.

26 Mini Glossary

LLM router
Code that picks which model answers each request.
Small / big model
A cheaper, faster model and a stronger, slower one (here 0.5B and 3B parameters).
Parameter
One learned number inside a model; 3B = about 3 billion.
Classifier
Something that puts an input into a group: here EASY or HARD.
LLM-as-a-judge
Using a model to grade answers against a reference.
Reference answer
The short correct answer written with each question.
Latency
How long one request takes, from question to answer.
Median
The middle value: half of the requests were faster.
Oracle
An imaginary perfect router that already knows which answers are right; the upper bound.
Misroute
An easy question sent to the big model (wastes time) or a hard one sent to the small model (risks a wrong answer).
Few-shot prompt
A prompt with a few labelled examples.
Hold-out set
Questions kept aside and used only to check a change.
Overfitting
Tuning so closely to your test questions that the result does not carry over to new ones.
Greedy decoding
Always taking the most likely next token: same input, same output.
Token
A piece of a word; models read and write tokens.
bfloat16
A 16-bit number format: half the memory of float32, almost the same range.
Rate limit
How many requests per minute a provider allows.
Idempotent / resumable
Running again does not repeat finished work.

29 Quick Quiz 🎯

Q1: Why does the router's latency include the classification?

Because the user waits for it: the small model must answer EASY/HARD before the real answer starts.

To test a change on questions you did not look at while designing it.

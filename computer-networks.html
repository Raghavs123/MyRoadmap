Good to know

  • Packet switching (the Internet): data is chopped into packets that share links with everyone else. Circuit switching (old telephone network): a dedicated path is reserved for the whole call.
  • The Internet is a network of networks: tens of thousands of independent networks (ISPs, companies, universities) connected by agreements.

7 Bandwidth, Latency, Throughput and Delay

Picture: A highway: bandwidth is the number of lanes, latency is the travel time for one car, throughput is how many cars actually arrive per hour (traffic jams included).

Total delay of a packet = transmission (size ÷ bandwidth) + propagation (distance ÷ signal speed) + queueing (waiting in router buffers) + processing.

Transmission vs propagation, and the bandwidth-delay product (run for real)
# Delay and throughput arithmetic: transmission vs propagation delay, bandwidth-delay product, and why window size matters.
def show(name, size_bytes, bw_bps, dist_km):
    tx = size_bytes * 8 / bw_bps; prop = dist_km * 1000 / 2e8          # signal speed in fibre ~ 2/3 of light speed
    print("%-34s transmission %8.3f ms  propagation %7.2f ms" % (name, tx * 1e3, prop * 1e3))
show("1500 B packet, 100 Mbit/s, 1 km", 1500, 100e6, 1)
show("1500 B packet, 1 Gbit/s, Delhi-Mumbai ~1400 km", 1500, 1e9, 1400)
show("10 MB file, 100 Mbit/s, 1 km", 10e6, 100e6, 1)
rtt = 0.1; bw = 1e9
print("\nbandwidth-delay product for 1 Gbit/s and 100 ms RTT = %.1f MB 'in flight' to keep the pipe full" % (bw * rtt / 8 / 1e6))
for win in (64 * 1024, 1024 * 1024, 16 * 1024 * 1024):
    print("   window %8d bytes -> max throughput %7.1f Mbit/s" % (win, min(bw, win * 8 / rtt) / 1e6))
print("This is why TCP has 'window scaling' (the original 16-bit field allowed only 64 KiB).")

# 1500 B packet, 1 Gbit/s, Delhi-Mumbai ~1400 km transmission    0.012 ms  propagation    7.00 ms
# 10 MB file, 100 Mbit/s, 1 km       transmission  800.000 ms  propagation    0.01 ms

#    window    65536 bytes -> max throughput     5.2 Mbit/s

For one packet across India the distance dominates (7 ms of propagation vs 0.012 ms to transmit at 1 Gbit/s); for a 10 MB file on a slow link the size dominates (800 ms). A 1 Gbit/s path with 100 ms RTT needs 12.5 MB in flight; with only a 64 KiB window you get about 5 Mbit/s no matter how fast the link is.

Good to know

  • Jitter = variation in delay (bad for calls and games). Packet loss = packets that never arrive.
  • Units: network speeds use bits per second (Mbit/s); file sizes use bytes. 100 Mbit/s ≈ 12.5 MB/s.

9 Framing and Error Detection (Checksum, CRC)

Picture: When you send a long number by phone, you also send a check digit. If the listener's check does not match, they ask you to repeat.
Internet checksum vs CRC-32, and CRC by hand (run for real)
# Error detection: the Internet checksum (IP, TCP, UDP) and CRC-32 (Ethernet, ZIP). Real values.
import zlib
def inet_checksum(data):
    if len(data) % 2: data += b"\x00"
    s = sum(int.from_bytes(data[i:i + 2], "big") for i in range(0, len(data), 2))
    while s >> 16: s = (s & 0xFFFF) + (s >> 16)                        # fold carries back in (one's complement sum)
    return ~s & 0xFFFF
msg = b"HELLO NETWORK!"
cs = inet_checksum(msg); print("Internet checksum of %r = 0x%04X" % (msg, cs))
print("receiver check (sum including checksum folds to 0):", inet_checksum(msg + cs.to_bytes(2, "big")) == 0)
ws = msg[2:4] + msg[0:2] + msg[4:]
print("swap the first two 16-bit words -> checksum unchanged?", inet_checksum(ws) == cs, " <- the simple sum cannot see reordering")
print("CRC-32 of the original 0x%08X, of the word-swapped 0x%08X (CRC catches it)" % (zlib.crc32(msg), zlib.crc32(ws)))
def crc_div(bits, gen):                                               # CRC by hand: binary long division with XOR
    pad = bits + "0" * (len(gen) - 1); r = list(pad)
    for i in range(len(bits)):
        if r[i] == "1":
            for j, g in enumerate(gen): r[i + j] = str(int(r[i + j]) ^ int(g))
    return "".join(r[-(len(gen) - 1):])
print("textbook example: data 1101011011, generator 10011 (x^4+x+1) -> remainder", crc_div("1101011011", "10011"), "-> send 1101011011" + crc_div("1101011011", "10011"))

# ----- Output (real run) -----
# Internet checksum of b'HELLO NETWORK!' = 0xDF3D
# receiver check (sum including checksum folds to 0): True
# swap the first two 16-bit words -> checksum unchanged? True  <- the simple sum cannot see reordering
# CRC-32 of the original 0xC321FA71, of the word-swapped 0x25537A78 (CRC catches it)
# textbook example: data 1101011011, generator 10011 (x^4+x+1) -> remainder 1110 -> send 11010110111110

Swapping two 16-bit words leaves the Internet checksum unchanged (it is just a sum), but CRC-32 changes completely. That is why Ethernet uses CRC-32 for frames while IP/TCP/UDP use the cheaper checksum (and rely on the link CRC too).

Good to know

  • Framing methods: byte count, flag bytes with byte stuffing (PPP), bit stuffing (HDLC), preamble + length (Ethernet).
  • Detection asks for a resend; correction (Hamming, Reed–Solomon, LDPC) fixes errors without one. See COA → error correction.
  • A CRC with generator degree r detects all burst errors up to r bits long.

10 Reliable Delivery: Stop-and-Wait, Go-Back-N, Selective Repeat

Picture: Posting pages of a long letter: wait for a 'got it' after each page (stop-and-wait), send 8 pages and resend from the lost one onwards (go-back-N), or resend only the lost page (selective repeat).
Fig S4 — Round trips needed to deliver 200 frames with 10% loss (simulated, window 8).
Three ARQ protocols on the same lossy link (run for real)
# Reliable delivery over a lossy link: Stop-and-Wait vs Go-Back-N vs Selective Repeat (simulation, same random losses).
import random
def simulate(protocol, n=200, window=8, loss=0.1, seed=7):
    rnd = random.Random(seed); sent = 0; delivered = 0; base = 0; acked = set()
    rounds = 0
    while base < n:
        rounds += 1
        w = 1 if protocol == "stop-and-wait" else window
        batch = [i for i in range(base, min(base + w, n)) if not (protocol == "selective repeat" and i in acked)]
        ok = []
        for i in batch:
            sent += 1
            if rnd.random() > loss: ok.append(i)
        if protocol == "go-back-n":
            k = base
            while k in ok: k += 1                                         # receiver accepts only in-order frames
            base = k
        else:
            acked.update(ok)
            while base in acked: base += 1
    return sent, rounds
print("200 frames, 10% of frames lost (same random losses for each), window 8; one 'round' = one round-trip time")
print("protocol            frames sent   round trips   efficiency")
for p in ("stop-and-wait", "go-back-n", "selective repeat"):
    s, r = simulate(p); print("%-18s  %11d   %11d   %9.0f%%" % (p, s, r, 100 * 200 / s))
print("Go-Back-N resends every frame after a loss; Selective Repeat resends only the lost one; Stop-and-Wait wastes time waiting.")

# ----- Output (real run) -----
# 200 frames, 10% of frames lost (same random losses for each), window 8; one 'round' = one round-trip time
# protocol            frames sent   round trips   efficiency
# stop-and-wait               226           226          88%
# go-back-n                   330            43          61%
# selective repeat            226            36          88%
# Go-Back-N resends every frame after a loss; Selective Repeat resends only the lost one; Stop-and-Wait wastes time waiting.

Stop-and-wait sends few extra frames but needs 226 round trips. Go-Back-N needs only 43 but sends 330 frames (it resends everything after each loss). Selective repeat gets both: 226 frames sent and 36 round trips.

Good to know

  • Window limits: Go-Back-N window ≤ 2k − 1, selective repeat ≤ 2k−1 for k-bit sequence numbers (to avoid confusing old and new frames).
  • Stop-and-wait efficiency = 1 ÷ (1 + 2a), where a = propagation delay ÷ transmission time. On long links it is terrible.
  • TCP uses ideas from both: cumulative ACKs plus selective ACKs (SACK).

# A learning switch: it learns which MAC address lives on which port from SOURCE addresses, floods unknown destinations.
table = {}
def frame(src, dst, port):
    table[src] = port
    if dst == "ff:ff:ff:ff:ff:ff": return "broadcast -> flood all ports except %d" % port
    if dst in table: return "forward to port %d" % table[dst]
    return "unknown destination -> flood all ports except %d" % port
steps = [("aa:aa", "ff:ff:ff:ff:ff:ff", 1, "A asks 'who has 10.0.0.2?' (ARP request, broadcast)"),
         ("bb:bb", "aa:aa", 2, "B replies 'I am 10.0.0.2, MAC bb:bb' (ARP reply)"),
         ("aa:aa", "bb:bb", 1, "A sends data to B"),
         ("cc:cc", "aa:aa", 3, "C sends to A")]
for src, dst, port, what in steps:
    print("%-48s port %d: %s" % (what, port, frame(src, dst, port)))

20 Link-State Routing and Dijkstra (OSPF)

Picture: Every town gets a copy of the full road map and computes its own shortest routes.
Fig S5 — The example network used below (link costs on edges).
Router A's routing table from Dijkstra (run for real)
# Link-state routing (OSPF idea): every router knows the whole map and runs Dijkstra's shortest-path algorithm.
import heapq
g = {"A": {"B": 4, "C": 2}, "B": {"A": 4, "C": 1, "D": 5}, "C": {"A": 2, "B": 1, "D": 8, "E": 10}, "D": {"B": 5, "C": 8, "E": 2, "F": 6}, "E": {"C": 10, "D": 2, "F": 2}, "F": {"D": 6, "E": 2}}
def dijkstra(src):
    dist, prev, pq = {src: 0}, {}, [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]: continue
        for v, w in g[u].items():
            if d + w < dist.get(v, 1e9): dist[v] = d + w; prev[v] = u; heapq.heappush(pq, (d + w, v))
    return dist, prev
dist, prev = dijkstra("A")
print("routing table of router A:")
for dst in sorted(g):
    if dst == "A": continue
    path, x = [dst], dst
    while x != "A": x = prev[x]; path.append(x)
    path.reverse(); print("   to %s: cost %2d, next hop %s, path %s" % (dst, dist[dst], path[1], "-".join(path)))

# ----- Output (real run) -----
# routing table of router A:
#    to B: cost  3, next hop C, path A-C-B
#    to C: cost  2, next hop C, path A-C
#    to D: cost  8, next hop C, path A-C-B-D
#    to E: cost 10, next hop C, path A-C-B-D-E
#    to F: cost 12, next hop C, path A-C-B-D-E-F

Even B (directly linked at cost 4) is best reached via C (2 + 1 = 3). Every route from A leaves through C: one next hop for the whole table.

Good to know

  • OSPF floods link-state advertisements, divides big networks into areas, and recomputes quickly after failures.
  • Dijkstra needs non-negative link costs; it runs in O(E log V) with a heap.

21 Distance-Vector Routing and Count to Infinity (RIP)

Picture: Towns only talk to neighbours: 'I can reach the capital in 5 hours'. A neighbour adds its own travel time. Simple, but bad news travels slowly.
Bellman-Ford convergence and the count-to-infinity problem (run for real)
# Distance-vector routing (RIP idea): routers repeatedly tell their neighbours "I can reach X at cost d" (Bellman-Ford).
INF = 16                                                            # RIP treats 16 hops as 'unreachable'
links = {("A", "B"): 1, ("B", "C"): 2, ("A", "D"): 4, ("C", "D"): 1}
nodes = ["A", "B", "C", "D"]
cost = lambda u, v: links.get((u, v), links.get((v, u)))
dist = {u: {v: 0 if u == v else INF for v in nodes} for u in nodes}
for rnd in range(1, 5):
    changed = False
    for u in nodes:
        for v in nodes:
            if cost(u, v) is None: continue
            for dst in nodes:
                if cost(u, v) + dist[v][dst] < dist[u][dst]: dist[u][dst] = cost(u, v) + dist[v][dst]; changed = True
    print("round %d: A's distances %s" % (rnd, dist["A"]))
    if not changed: print("no changes: converged"); break
print("\nThe 'count to infinity' problem: line A - B - C, every link cost 1. The link B-C breaks.")
def after_break(poisoned):
    a_c, b_c, out = 2, INF, []                                       # A still believes 'C is 2 away (via B)'
    for _ in range(8):
        b_c = INF if poisoned else min(INF, 1 + a_c)                  # B hears A's stale route (unless A poisons it, since A's route goes via B)
        a_c = min(INF, 1 + b_c)                                       # A learns from B
        out.append("B=%d A=%d" % (b_c, a_c))
    return out
print("plain distance vector :", ", ".join(after_break(False)), "... counts up to 16")
print("with poisoned reverse :", ", ".join(after_break(True)[:3]), "... unreachable at once")

# ----- Output (real run) -----
# round 1: A's distances {'A': 0, 'B': 1, 'C': 16, 'D': 4}
# round 2: A's distances {'A': 0, 'B': 1, 'C': 3, 'D': 4}
# round 3: A's distances {'A': 0, 'B': 1, 'C': 3, 'D': 4}
# no changes: converged
#
# The 'count to infinity' problem: line A - B - C, every link cost 1. The link B-C breaks.

The table converges in a few rounds. After a link breaks, A and B keep believing each other's stale routes and count up 3, 4, 5 ... until 16 ('infinity' in RIP). Poisoned reverse (advertise 'infinite' back to the neighbour you route through) stops this loop immediately in this simple case.

Good to know

  • Other fixes: split horizon, triggered updates, hold-down timers. Distance vector is simple but slow to converge in large networks.

# DNS messages are small binary packets. Build a real query for 'example.com' type A and decode a hand-made answer (no network needed).
import struct
def build_query(name, qid=0x1234):
    header = struct.pack(">HHHHHH", qid, 0x0100, 1, 0, 0, 0)          # id, flags (recursion desired), 1 question
    q = b"".join(bytes([len(p)]) + p.encode() for p in name.split(".")) + b"\x00" + struct.pack(">HH", 1, 1)   # QTYPE A, QCLASS IN
    return header + q
pkt = build_query("example.com")
print("query (%d bytes): %s" % (len(pkt), pkt.hex(" ")))
print("  name is stored as length-prefixed labels: 07 'example' 03 'com' 00")
answer = pkt[:2] + struct.pack(">H", 0x8180) + struct.pack(">HHHH", 1, 1, 0, 0) + pkt[12:] + \
         struct.pack(">HHHIH", 0xC00C, 1, 1, 3600, 4) + bytes([93, 184, 215, 14])      # pointer to the name, A, IN, TTL 3600, 4 bytes of address (EXAMPLE values)
qid, flags, qd, an, ns, ar = struct.unpack(">HHHHHH", answer[:12])
ttl, rdlen = struct.unpack(">IH", answer[len(pkt) + 6:len(pkt) + 12])
ip = ".".join(str(b) for b in answer[-4:])
print("decoded answer: id=0x%04X response=%s answers=%d ttl=%ds address=%s (hand-made example record)" % (qid, bool(flags & 0x8000), an, ttl, ip))

/* A minimal TCP server in C with the BSD socket API (template; the Python demos above use the same calls). */
int s = socket(AF_INET, SOCK_STREAM, 0);
struct sockaddr_in a = { .sin_family = AF_INET, .sin_port = htons(8080), .sin_addr.s_addr = htonl(INADDR_ANY) };   /* htons: host -> network byte order */

listen(s, 16);                                    /* backlog of pending connections */
for (;;) {

    char buf[1024]; ssize_t n = read(c, buf, sizeof buf);
    write(c, buf, n);                             /* echo */
    close(c);
}

42 Interview Questions (With Answers)

Picture: Grouped by theme, easiest first. Click to reveal.

A. Basics

Q1: OSI vs TCP/IP model?

OSI has 7 layers (teaching model); TCP/IP has 4 (application, transport, internet, link) and is what the Internet uses.

Q2: Hub vs switch vs router?

Hub repeats bits to all ports (L1); switch forwards frames by MAC (L2); router forwards packets between networks by IP (L3).

Q3: Bandwidth vs latency vs throughput?

Capacity of the link; delay for a bit to arrive; actual achieved data rate.

Q4: What happens when you type a URL and press Enter?

DNS resolves the name, TCP (or QUIC) connects, TLS handshakes, HTTP request is sent, server responds, browser renders and fetches more resources; caches and CDNs may answer earlier.

B. Data link

Q5: What is a MAC address?

A 48-bit link-layer address of a network interface, used inside one LAN.

Q6: CSMA/CD vs CSMA/CA?

Collision detection (old wired Ethernet) vs collision avoidance with random backoff and optional RTS/CTS (Wi-Fi).

Q7: Why CRC instead of a simple checksum?

CRC detects burst errors and reorderings a simple sum misses (our word-swap example).

Q8: What is a VLAN?

A logical LAN on shared switches, separated by 802.1Q tags.

C. Network layer

Q9: How many usable hosts in a /26?

2^6 − 2 = 62.

Q10: What is CIDR and longest prefix match?

Classless prefixes of any length; routers pick the most specific matching route.

Q11: What does ARP do?

Finds the MAC address for an IPv4 address on the local network.

Q12: What is NAT and its downsides?

Maps many private addresses to one public address with port translation; breaks end-to-end reachability and complicates peer-to-peer.

Q13: Link state vs distance vector?

Link state: full map + Dijkstra (OSPF), fast convergence. Distance vector: neighbours exchange distances (RIP), simple, slow, count-to-infinity.

Q14: What is BGP?

The path-vector protocol that exchanges routes between autonomous systems, driven by policy.

Q15: IPv4 vs IPv6 key differences?

32 vs 128-bit addresses, fixed 40-byte header without checksum, no broadcast, SLAAC, no router fragmentation.

D. Transport

Q16: TCP vs UDP?

TCP: connection-oriented, reliable, ordered byte stream with flow and congestion control. UDP: connectionless, unreliable datagrams with low overhead.

Q17: Explain the 3-way handshake.

SYN, SYN-ACK, ACK: both sides agree on initial sequence numbers.

Q18: Why does TIME_WAIT exist?

To let delayed packets of the old connection expire and to resend the final ACK if needed.

Q19: Flow control vs congestion control?

Protect the receiver (rwnd) vs protect the network (cwnd).

Q20: Describe slow start and AIMD.

Window doubles per RTT until ssthresh, then +1 per RTT; halves on loss (3 dup ACKs) or resets to 1 on timeout.

Q21: Why is TCP called a byte stream?

Message boundaries are not preserved; three sends can arrive as one receive.

Q22: What problem does QUIC solve?

TCP head-of-line blocking across streams, slow connection set-up, and connection migration; encryption is built in.

E. Application and security

Q23: How does DNS resolution work?

Stub → recursive resolver → root → TLD → authoritative server, with caching by TTL.

Q24: HTTP/1.1 vs HTTP/2 vs HTTP/3?

Text, one request at a time per connection; binary multiplexed streams over TCP; multiplexed streams over QUIC/UDP.

Q25: What does TLS provide?

Encryption, integrity and server (optionally client) authentication via certificates.

Q26: GET vs POST?

GET reads and is safe/idempotent; POST submits data and is neither.

Q27: What is a DDoS attack and how do you mitigate it?

Overwhelming a target with traffic from many sources; CDNs/scrubbing, anycast, rate limiting, SYN cookies.

Q28: How would you debug 'website not loading'?

Check link and IP, gateway, DNS, port reachability, TLS, HTTP status and logs, packet capture if needed.

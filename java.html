Part A — Getting Started with Java

1 What Is Java?

Picture: A universal travel adapter. You write your plug once (the program), and the adapter (the JVM) fits it into any wall socket (Windows, Linux, macOS). That is Java's famous promise: write once, run anywhere.

Java is a general-purpose, object-oriented, statically typed language created at Sun Microsystems (James Gosling and team, first released 1995; now stewarded by Oracle and the OpenJDK community). Source code is compiled to bytecode that runs on the Java Virtual Machine (JVM), which also provides automatic memory management (garbage collection).

StrengthWhat it means
PortableThe same .class files run on any operating system that has a JVM
Safe memoryNo pointer arithmetic, bounds-checked arrays, garbage collector: no manual free; whole classes of C/C++ bugs cannot happen
Huge ecosystemLibraries and frameworks for everything: Spring, Hibernate, Kafka, Hadoop, Android (Kotlin/Java), build tools Maven and Gradle
Fast enoughThe JIT compiler turns hot code into machine code at run time; Java is commonly within a small factor of C++ for server work
Strong toolingIDEs, debuggers, profilers, mature testing (JUnit)
Backward compatibleOld Java code keeps running on new JVMs

Where Java is used

  • Enterprise back ends and web services (banks, insurance, e-commerce); microservices with Spring Boot
  • Big-data tools (Hadoop, Spark, Kafka, Elasticsearch are JVM programs); Android apps (Java or Kotlin)
  • Large systems where teams, long life and stability matter
The smallest Java program (run for real)
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}

// ----- Output (real run: JDK 25, Temurin) -----
// Hello, Java!

Compiled with javac and run on a real JDK 25 (Eclipse Temurin). Everything in Java lives inside a class; main is where the JVM starts.

Good to know

  • Compared with C++: Java trades some raw control (no manual memory, no operator overloading, no multiple inheritance of classes) for safety and portability. Throughout this guide a 'C++ twin' note shows the matching idea in the C++ guide.
  • Java is not JavaScript. They share half a name and nothing else.
How to read this guide: every code block was compiled (with all compiler warnings on) and run on JDK 25; the output shown is real. The Servlet, JSP, JDBC and Spring Boot parts ran for real too (embedded Tomcat, an in-memory H2 database, and a Spring Boot 4.1 application). Timings and memory figures are from this computer.

Good to know

public class Main {
    public static void main(String[] args) {
        System.out.println("Java version  : " + System.getProperty("java.version"));
        System.out.println("Runtime       : " + Runtime.version());
        System.out.println("Class version : " + System.getProperty("java.class.version") + " (52=Java 8, 61=Java 17, 65=Java 21, 69=Java 25)");
        System.out.println("File encoding : " + System.getProperty("native.encoding") + " / default " + java.nio.charset.Charset.defaultCharset());
        System.out.println("CPU cores seen: " + (Runtime.getRuntime().availableProcessors() > 0));
        long mb = Runtime.getRuntime().maxMemory() / (1024 * 1024);
        System.out.println("Max heap known: " + (mb > 0) + "  (the JVM picks it from the machine's memory)");
        // the same source file becomes bytecode: show the name of the loaded class and its loader
        System.out.println("Main loaded by: " + Main.class.getClassLoader().getClass().getSimpleName());
        System.out.println("String loaded by: " + String.class.getClassLoader() + "  (null = bootstrap loader)");
    }
}

// ----- Output (real run: JDK 25, Temurin) -----
// Java version  : 25.0.5
// Runtime       : 25.0.5+8-LTS
// Class version : 69.0 (52=Java 8, 61=Java 17, 65=Java 21, 69=Java 25)

Good to know

  • Warm-up matters: short programs and the first call of a method are slower than the steady state. Always warm up before benchmarking (the benchmark section does).
  • C++ twin: C++ compiles straight to machine code for one platform (see how a C++ program is built); Java adds the bytecode + JVM layer in between, which is why it is portable.

Unlike C++, Java's sizes are the same on every machine (int is always 32 bits). Integer.MAX_VALUE + 1 silently wrapped to the most negative number, while Math.addExact reported the overflow. 0.1 + 0.2 == 0.3 is false, exactly as in C++. Integer division by zero throws; floating-point division gives Infinity or NaN.

Good to know

  • Two groups of types: primitives (8 of them, stored directly, never null) and reference types (objects; the variable holds a reference, can be null).
  • Local variables must be assigned before use (the compiler enforces it); fields get default values (0, false, null).
  • Never compare decimals with ==; use a tolerance, or BigDecimal for money.

public class Main {

import java.util.*;
public class Main {
    public static void main(String[] args) {
        int marks = 82;
        if (marks >= 90) System.out.println("A");
        else if (marks >= 75) System.out.println("B");
        else System.out.println("C");
        String day = "TUE";
        switch (day) {
            case "MON": System.out.println("start of week"); break;
            case "TUE":
            case "WED": System.out.println("midweek (fall-through grouped)"); break;
            default: System.out.println("other");
        }
        int len = switch (day) { case "MON", "TUE" -> 3; case "WEDNESDAY" -> 9; default -> { int z = day.length(); yield z; } };
        System.out.println("switch expression gave " + len);
        for (int i = 1; i <= 5; i++) { if (i == 3) continue; if (i == 5) break; System.out.print(i + " "); }
        System.out.println("<- continue skipped 3, break stopped at 5");
        List<String> names = List.of("Asha", "Ravi", "Meera");
        for (String n : names) System.out.print(n + " ");
        System.out.println("<- enhanced for");
        int k = 10;
        do { System.out.print("do-while runs once even though k=" + k); } while (k < 5);
        System.out.println();
        outer:
        for (int r = 1; r <= 3; r++) {
            for (int c = 1; c <= 3; c++) {
                if (r * c == 4) { System.out.println("labelled break at r=" + r + " c=" + c); break outer; }
            }
        }
        int sum = 0;
        for (int i = 1; i <= 100; i++) sum += i;

17 Sealed Types and Pattern Matching

Picture: A closed club: only listed members can join, so when you handle visitors you know every kind that can arrive.
  • sealed interface Shape permits Circle, Rect, Square {} lists every allowed implementation.
  • switch over a sealed type needs no default: the compiler proves every case is handled, and complains if you add a new shape and forget one.
  • Pattern matching: case Circle c, case Rect(double w, double h) (record deconstruction), guards when, and case null.
Areas of shapes and a describe(Object) function with patterns (run for real)
import java.util.*;
public class Main {
    sealed interface Shape permits Circle, Rect, Square {}
    record Circle(double r) implements Shape {}
    record Rect(double w, double h) implements Shape {}
    record Square(double side) implements Shape {}

    static double area(Shape s) {
        return switch (s) {                       // no default needed: the compiler knows every case
            case Circle c -> Math.PI * c.r() * c.r();
            case Rect(double w, double h) -> w * h;      // record pattern: unpack in place
            case Square sq -> sq.side() * sq.side();
        };
    }
    static String describe(Object o) {
        return switch (o) {
            case null -> "null!";
            case Integer i when i > 100 -> "big int " + i;
            case Integer i -> "small int " + i;
            case String s -> "string of length " + s.length();
            case int[] arr -> "int array of " + arr.length;
            default -> "something else: " + o.getClass().getSimpleName();
        };
    }
    public static void main(String[] args) {
        List<Shape> shapes = List.of(new Circle(2), new Rect(3, 4), new Square(5));
        for (Shape s : shapes) System.out.printf("%s -> area %.2f%n", s, area(s));
        for (Object o : new Object[]{7, 500, "hello", new int[]{1, 2}, 2.5, null}) System.out.println(describe(o));
    }
}

// ----- Output (real run: JDK 25, Temurin) -----
// Circle[r=2.0] -> area 12.57
// Rect[w=3.0, h=4.0] -> area 12.00
// Square[side=5.0] -> area 25.00
// small int 7
// big int 500
// string of length 5
// int array of 2
// something else: Double
// null!

Each shape's area was computed with an exhaustive switch (record pattern unpacked w and h directly). The second switch handled null, big and small integers (with a guard), strings, an int[] and 'anything else'.

  • C++ twin: a sealed hierarchy + pattern switch is Java's answer to std::variant + std::visit (see C++ optional/variant).

public class Main {

        private T value;
        Box(T value) { this.value = value; }

        @Override public String toString() { return "Box(" + value + ")"; }
    }

        final A first; final B second;
        Pair(A a, B b) { first = a; second = b; }
        public String toString() { return "(" + first + ", " + second + ")"; }
    }

        T best = list.get(0);
        for (T x : list) if (x.compareTo(best) > 0) best = x;
        return best;
    }
    static double sum(List<? extends Number> nums) {                // upper bounded wildcard: read-only producer
        double s = 0; for (Number n : nums) s += n.doubleValue(); return s;
    }

        List<String> strings = new ArrayList<>();

23 try-with-resources: Java's RAII

Picture: A hotel key card that closes the room's door for you when you leave, whichever way you leave.

Any class that implements AutoCloseable can be declared in try ( ... ). Java calls close() automatically, in reverse order, even if an exception is thrown. If close() itself fails, that exception is attached as a suppressed exception.

Resources closed in reverse order, also on exceptions (run for real)
import java.io.*;
public class Main {
    static class Res implements AutoCloseable {
        final String name;
        Res(String name) { this.name = name; System.out.println("open  " + name); }
        void use(boolean fail) { System.out.println("use   " + name); if (fail) throw new IllegalStateException("boom in " + name); }
        @Override public void close() { System.out.println("close " + name); }
    }
    public static void main(String[] args) {
        try (Res a = new Res("A"); Res b = new Res("B")) { a.use(false); b.use(false); }
        System.out.println("--- with an exception ---");
        try (Res a = new Res("C"); Res b = new Res("D")) { a.use(false); b.use(true); }
        catch (IllegalStateException e) { System.out.println("caught: " + e.getMessage() + " (resources were still closed, in REVERSE order)"); }
        try (Res bad = new Res("E") { @Override public void close() { throw new IllegalArgumentException("close failed"); } }) { bad.use(true); }
        catch (Exception e) { System.out.println("caught " + e.getMessage() + ", suppressed: " + e.getSuppressed()[0].getMessage()); }
    }
}

// ----- Output (real run: JDK 25, Temurin) -----
// open  A
// open  B
// use   A
// use   B
// close B
// close A
// --- with an exception ---
// open  C
// open  D
// use   C
// use   D
// close D
// close C
// caught: boom in D (resources were still closed, in REVERSE order)
// open  E
// use   E
// caught boom in E, suppressed: close failed

Resources A and B closed as B, A; when an exception occurred in D, both D and C still closed; a failing close() became a suppressed exception.

Good to know

  • Use it for files, streams, JDBC connections, sockets, locks wrappers.
  • C++ twin: RAII, where destructors do this automatically for every object; in Java you must remember to use try-with-resources, because the garbage collector does not close files on time.

24 Interfaces: Default, Static and Private Methods

Since Java 8 an interface may contain default methods (with a body), static methods, and since Java 9 private helper methods. A class can implement many interfaces; if two supply the same default method the class must resolve the clash itself.

        default void warn(String m) { log("WARN: " + m); }

26 Immutable Objects

Picture: A printed photo: you cannot change it. If you want a different picture you print a new one, and nobody who holds the old one is surprised.

Recipe for an immutable class: final class, private final fields, no setters, make defensive copies of mutable inputs and outputs, and return new objects for 'changes'. Examples in the JDK: String, wrappers, LocalDate, BigDecimal, List.of(...), records (if their fields are immutable).

An immutable Money class and a Team that defends itself (run for real)
import java.util.*;
public final class Main {
    static final class Money {
        private final long cents; private final String currency;
        Money(long cents, String currency) { this.cents = cents; this.currency = currency; }
        Money plus(Money o) { return new Money(cents + o.cents, currency); }    // returns a NEW object
        @Override public String toString() { return String.format("%d.%02d %s", cents / 100, cents % 100, currency); }
    }
    static final class Team {
        private final List<String> members;
        Team(List<String> m) { members = List.copyOf(m); }                      // defensive copy
        List<String> members() { return members; }
    }
    public static void main(String[] args) {
        Money a = new Money(1050, "INR"), b = new Money(295, "INR");
        System.out.println(a + " + " + b + " = " + a.plus(b) + "  (a is still " + a + ")");
        List<String> original = new ArrayList<>(List.of("Asha", "Ravi"));
        Team t = new Team(original);
        original.add("Hacker");
        System.out.println("team unaffected by later changes: " + t.members());
        try { t.members().add("x"); } catch (UnsupportedOperationException e) { System.out.println("cannot modify the returned list either"); }
        System.out.println("Immutable = thread-safe, cache-friendly, easy to reason about. Recipe: final class, final fields, no setters, copy mutable inputs/outputs.");
    }
}

29 Concurrency (1): Threads, synchronized and Data Races

Picture: A kitchen with several cooks. They can work at the same time, but if two reach for the same salt pot without a rule, the recipe goes wrong.
  • Create a thread with new Thread(runnable); start() runs it, join() waits for it, interrupt() asks it to stop.
  • synchronized (on a method or a lock object) lets one thread at a time into a critical section; volatile makes a variable's changes visible to other threads.
  • A data race is unsynchronised access where at least one thread writes.
A correct synchronized counter and a deliberately broken unsynchronized one (run for real)
import java.util.*;
public class Main {
    static int unsafe = 0;
    static int safe = 0;
    static final Object lock = new Object();
    public static void main(String[] args) throws Exception {
        Thread t = new Thread(() -> System.out.println("hello from " + Thread.currentThread().getName()), "worker-1");
        t.start(); t.join();
        int threads = 4, per = 50_000;
        List<Thread> ts = new ArrayList<>();
        for (int i = 0; i < threads; i++) {
            Thread x = new Thread(() -> { for (int k = 0; k < per; k++) { unsafe++; synchronized (lock) { safe++; } } });
            ts.add(x); x.start();
        }
        for (Thread x : ts) x.join();
        System.out.println("expected " + threads * per + ", synchronized counter = " + safe);
        System.out.println("unsynchronized counter = " + (unsafe == safe ? "(happened to be right this time)" : "wrong (" + unsafe + "): a data race lost updates") + " <- varies per run");
        Thread daemon = new Thread(() -> { try { Thread.sleep(10_000); } catch (InterruptedException e) { System.out.println("interrupted!"); } });
        daemon.start(); daemon.interrupt(); daemon.join();
        System.out.println("states: " + new Thread(() -> {}).getState() + " -> after join -> " + t.getState());
    }
}

// ----- Output (real run: JDK 25, Temurin) -----
// hello from worker-1
// expected 200000, synchronized counter = 200000
// unsynchronized counter = wrong (199162): a data race lost updates <- varies per run
// interrupted!
// states: NEW -> after join -> TERMINATED

Four threads each added 50,000 times: the synchronized counter was exactly 200,000; the plain counter lost updates (it printed 199,007 in this run: the exact wrong number differs every run, and sometimes it is accidentally right).

Good to know

  • C++ twin: in Java a data race gives a wrong value; in C++ it is undefined behaviour. See C++ threads and mutexes.
  • Do not create raw threads in real applications; use executors (next section).

31 Concurrency (3): Virtual Threads (Java 21+)

Picture: Instead of hiring one waiter per table (expensive), you hire a few waiters who instantly swap between tables whenever one table is just waiting for the kitchen.
  • A virtual thread is a very cheap thread managed by the JVM, not the OS. You can have millions.
  • When it blocks (waiting for the network or database) the JVM parks it and runs another on the same OS thread.
  • Create with Thread.ofVirtual().start(...) or Executors.newVirtualThreadPerTaskExecutor().
  • Best for waiting-heavy code (web requests, JDBC); no benefit for CPU-heavy loops.
10,000 tasks that each sleep 100 ms (run for real)
import java.time.Duration;
import java.util.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;
public class Main {
    public static void main(String[] args) throws Exception {
        Thread vt = Thread.ofVirtual().name("v1").start(() -> System.out.println("virtual? " + Thread.currentThread().isVirtual()));
        vt.join();
        int tasks = 10_000;
        AtomicInteger done = new AtomicInteger();
        long t0 = System.nanoTime();
        try (ExecutorService ex = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < tasks; i++) ex.submit(() -> { Thread.sleep(Duration.ofMillis(100)); done.incrementAndGet(); return null; });
        }
        long ms = (System.nanoTime() - t0) / 1_000_000;
        System.out.println(tasks + " tasks each sleeping 100 ms finished: " + done.get() + " in about " + ms + " ms with virtual threads");
        System.out.println("(with 200 platform threads the same job needs at least " + (tasks / 200 * 100) + " ms: 50 waves of 100 ms)");
        System.out.println("Virtual threads are cheap, JVM-managed threads: ideal for code that WAITS (network, database), not for CPU-heavy loops.");
    }
}

// ----- Output (real run: JDK 25, Temurin) -----
// virtual? true
// 10000 tasks each sleeping 100 ms finished: 10000 in about 175 ms with virtual threads

  • Spring Boot can run request handling on virtual threads with one property (see the Spring Boot part).

33 Annotations and Reflection

Picture: Sticky labels on your classes, and a detective who can read the labels at run time. Frameworks use this a lot: you put @Test or @RestController on something and the framework finds and uses it.
  • An annotation adds metadata: @Override, @Deprecated, @FunctionalInterface, or your own with @interface.
  • Reflection (java.lang.reflect) lets code inspect classes, call methods and read fields at run time, even private ones.
  • JUnit, Spring, Hibernate and Jackson are built on this.
A tiny test framework: find @Test methods and run them (run for real)
import java.lang.annotation.*;
import java.lang.reflect.*;
import java.util.*;
public class Main {
    @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.METHOD) @interface Test { String name() default "unnamed"; }
    static class Calc {
        @Test(name = "adds") public boolean addWorks() { return 2 + 2 == 4; }
        @Test public boolean broken() { return 2 + 2 == 5; }
        public void helper() {}
        private int secret = 42;
    }
    public static void main(String[] args) throws Exception {
        Class<?> c = Calc.class;
        System.out.println("class " + c.getSimpleName() + " has methods: " + Arrays.stream(c.getDeclaredMethods()).map(Method::getName).sorted().toList());
        Object obj = c.getDeclaredConstructor().newInstance();
        Method[] ms = c.getDeclaredMethods();
        Arrays.sort(ms, Comparator.comparing(Method::getName));
        for (Method m : ms) {
            Test t = m.getAnnotation(Test.class);
            if (t != null) System.out.println("running @Test " + t.name() + " -> " + m.invoke(obj));
        }
        Field f = c.getDeclaredField("secret");
        f.setAccessible(true);
        System.out.println("read a private field with reflection: " + f.get(obj));
        System.out.println("Reflection powers frameworks (Spring, Hibernate, JUnit); use it sparingly in your own code.");
    }
}

// ----- Output (real run: JDK 25, Temurin) -----

// running @Test adds -> true
// running @Test unnamed -> false
// read a private field with reflection: 42

The program discovered the methods annotated with @Test, invoked them (adds passed, the other returned false) and read a private field. This is exactly how JUnit finds your tests.

  • Reflection is slower and bypasses compile-time checks: use it for frameworks, not everyday code.

38 Encapsulation: Protecting the Rules of Your Data

  • Prefer meaningful operations (withdraw) to raw setters (setBalance).
  • Validate in constructors and methods; throw IllegalArgumentException/IllegalStateException.

public class Main {
    static class Account {
        private final String owner;
        private double balance;
        private int txCount;
        Account(String owner, double opening) {
            if (opening < 0) throw new IllegalArgumentException("opening balance cannot be negative");
            this.owner = owner; this.balance = opening;
        }
        public void deposit(double amt) {
            if (amt <= 0) throw new IllegalArgumentException("deposit must be positive");
            balance += amt; txCount++;
        }
        public void withdraw(double amt) {
            if (amt <= 0) throw new IllegalArgumentException("withdrawal must be positive");
            if (amt > balance) throw new IllegalStateException("insufficient funds");
            balance -= amt; txCount++;
        }
        public double getBalance() { return balance; }
        public String getOwner() { return owner; }
        public int getTxCount() { return txCount; }
    }
    public static void main(String[] args) {
        Account a = new Account("Asha", 100);
        a.deposit(50); a.withdraw(30);
        System.out.printf("%s balance %.2f after %d transactions%n", a.getOwner(), a.getBalance(), a.getTxCount());
        try { a.withdraw(1000); } catch (IllegalStateException e) { System.out.println("rejected: " + e.getMessage()); }
        try { a.deposit(-5); } catch (IllegalArgumentException e) { System.out.println("rejected: " + e.getMessage()); }
        System.out.printf("balance unchanged by bad requests: %.2f%n", a.getBalance());
        // a.balance = 1_000_000;   // would NOT compile: balance is private
    }
}

  • Contract: if a.equals(b) then a.hashCode() == b.hashCode(); equals must be reflexive, symmetric, transitive, consistent; always override both together.
  • Easiest: use a record (gets both for free), or an IDE/Lombok-generated pair, or Objects.equals/hash.
  • C++ twin: operator== and a std::hash specialisation for use in unordered_map (C++ unordered containers).

45 The hashCode Traps: Mutable Keys and Bad Hashes

Picture: Filing cabinets: the hash is the drawer number. If you change a document's content after filing it, you will look in the wrong drawer and swear it was lost.
A key that was mutated after insertion, and a hashCode that always returns 7 (run for real)
import java.util.*;
public class Main {
    static class BadKey {
        int id; BadKey(int id) { this.id = id; }
        @Override public boolean equals(Object o) { return o instanceof BadKey k && k.id == id; }
        @Override public int hashCode() { return 7; }                       // legal but terrible: everything collides
    }
    static class MutableKey {
        int id; MutableKey(int id) { this.id = id; }
        @Override public boolean equals(Object o) { return o instanceof MutableKey k && k.id == id; }
        @Override public int hashCode() { return Integer.hashCode(id); }
    }
    public static void main(String[] args) {
        Map<MutableKey, String> m = new HashMap<>();
        MutableKey k = new MutableKey(1);
        m.put(k, "value");
        System.out.println("before mutating the key: " + m.get(k));
        k.id = 2;
        System.out.println("after mutating the key : " + m.get(k) + "  (lost! it sits in the wrong bucket) size=" + m.size());
        int n = 5000;
        Map<BadKey, Integer> slow = new HashMap<>();
        long t = System.nanoTime();
        for (int i = 0; i < n; i++) slow.put(new BadKey(i), i);
        long bad = System.nanoTime() - t;
        Map<MutableKey, Integer> fast = new HashMap<>();
        t = System.nanoTime();
        for (int i = 0; i < n; i++) fast.put(new MutableKey(i), i);
        long good = System.nanoTime() - t;
        System.out.printf("inserting %d keys: constant hashCode %.1f ms vs good hashCode %.1f ms (machine dependent)%n", n, bad / 1e6, good / 1e6);
        System.out.println("Rules: never mutate fields used by hashCode while an object is a key; use immutable keys (String, Integer, records).");
    }
}

// ----- Output (real run: JDK 25, Temurin) -----
// before mutating the key: value
// after mutating the key : null  (lost! it sits in the wrong bucket) size=1
// inserting 5000 keys: constant hashCode 113.7 ms vs good hashCode 2.3 ms (machine dependent)
// Rules: never mutate fields used by hashCode while an object is a key; use immutable keys (String, Integer, records).

After the key's field changed, get returned null although the map still had size 1. With a constant hashCode every key landed in the same bucket, so inserting 5,000 keys took far longer than with a good hash (the exact timings vary per machine, but the gap is large).

Good to know

  • Keys should be immutable (Strings, Integers, records).
  • Since Java 8, a long collision chain in HashMap becomes a tree for keys that are Comparable, so the worst case is O(log n) rather than O(n): but it is still much slower than good hashing.

46 Composition, Aggregation and Dependency Injection

Picture: A car owns its engine (they live and die together: composition). A team uses players who exist without the team (aggregation).
Fig S8 — Composition (filled diamond) vs aggregation (hollow diamond) vs a plain association.
Owned parts, borrowed parts and an injected dependency (run for real)
import java.util.*;
public class Main {
    static class Engine {
        Engine() { System.out.println("  Engine built"); }
        void start() { System.out.println("  engine running"); }
    }
    static class Car {                                   // composition: the car creates and owns its engine
        private final Engine engine = new Engine();
        private final String name;
        Car(String name) { this.name = name; System.out.println("  Car " + name + " built"); }
        void drive() { engine.start(); System.out.println("  " + name + " is moving"); }
    }
    static class Player { final String name; Player(String n) { name = n; } }
    static class Team {                                  // aggregation: players exist without the team
        private final List<Player> players = new ArrayList<>();
        void add(Player p) { players.add(p); }
        String names() { return players.stream().map(p -> p.name).toList().toString(); }
    }
    interface Notifier { void send(String msg); }
    static class Service {                               // dependency injection: the part is given from outside
        private final Notifier notifier;
        Service(Notifier notifier) { this.notifier = notifier; }
        void run() { notifier.send("service finished"); }
    }
    public static void main(String[] args) {
        System.out.println("composition:");
        new Car("Zephyr").drive();
        System.out.println("aggregation:");
        Player a = new Player("Asha"), r = new Player("Ravi");
        Team t = new Team(); t.add(a); t.add(r);
        t = null;                                        // team gone, players still alive
        System.out.println("  players still exist: " + a.name + ", " + r.name);
        System.out.println("dependency injection:");
        new Service(m -> System.out.println("  [console] " + m)).run();
        new Service(m -> System.out.println("  [fake in a test] " + m)).run();
        System.out.println("Prefer composition over inheritance: it is more flexible and keeps classes independent.");
    }
}

// ----- Output (real run: JDK 25, Temurin) -----

//   Engine built
//   Car Zephyr built
//   engine running
//   Zephyr is moving
// aggregation:
//   players still exist: Asha, Ravi
// dependency injection:
//   [console] service finished
//   [fake in a test] service finished
// Prefer composition over inheritance: it is more flexible and keeps classes independent.

48 Copying Objects: Shallow vs Deep

Picture: Photocopying a folder: a shallow copy copies only the folder cover (the new cover still points at the same papers); a deep copy duplicates every paper.
Shallow copy shares inner objects, deep copy does not (run for real)
import java.util.*;
public class Main {
    static class Address { String city; Address(String c) { city = c; } }
    static class Person {
        String name; Address address; List<String> tags = new ArrayList<>();
        Person(String n, String city) { name = n; address = new Address(city); }
        Person shallowCopy() { Person p = new Person(name, address.city); p.address = this.address; p.tags = this.tags; return p; }
        Person deepCopy() { Person p = new Person(name, address.city); p.tags = new ArrayList<>(tags); return p; }
    }
    public static void main(String[] args) {
        Person a = new Person("Asha", "Pune"); a.tags.add("admin");
        Person shallow = a.shallowCopy(), deep = a.deepCopy();
        a.address.city = "Delhi"; a.tags.add("tester");
        System.out.println("original  : " + a.address.city + " " + a.tags);
        System.out.println("shallow   : " + shallow.address.city + " " + shallow.tags + "  (shares the inner objects!)");
        System.out.println("deep copy : " + deep.address.city + " " + deep.tags + "  (independent)");
        int[] arr = {1, 2, 3}; int[] c = arr.clone(); c[0] = 99;
        System.out.println("array clone is independent for primitives: " + arr[0]);
        Person[] people = {a}; Person[] cl = people.clone(); cl[0].name = "Changed";
        System.out.println("array clone of objects is shallow: " + a.name);
        System.out.println("Prefer copy constructors or copy factory methods to Object.clone().");
    }
}

// ----- Output (real run: JDK 25, Temurin) -----
// original  : Delhi [admin, tester]
// shallow   : Delhi [admin, tester]  (shares the inner objects!)
// deep copy : Pune [admin]  (independent)
// array clone is independent for primitives: 1
// array clone of objects is shallow: Changed
// Prefer copy constructors or copy factory methods to Object.clone().

After changing the original's city and tags, the shallow copy changed too (shared inner objects) but the deep copy stayed independent.

  • Prefer copy constructors or copy factory methods over Object.clone() (which is shallow by default and awkward).

import java.util.*;
public class Main {
    static abstract class Account {
        private static final Map<String, Integer> seq = new HashMap<>();
        protected final String id; protected final String owner; protected double balance;
        Account(String prefix, String owner, double opening) { this.id = prefix + "-" + seq.merge(prefix, 1, Integer::sum); this.owner = owner; this.balance = opening; }
        void deposit(double a) { if (a <= 0) throw new IllegalArgumentException("deposit must be positive"); balance += a; }
        void withdraw(double a) { if (a > available()) throw new IllegalStateException("overdraft limit exceeded in " + id); balance -= a; }
        abstract double available();
        void monthEnd() {}
        abstract String type();
        public String toString() { return String.format("%-4s %-8s %-9s %9.2f", id, type(), owner, balance); }
    }
    static class Savings extends Account {
        private final double rate;
        Savings(String o, double open, double rate) { super("S", o, open); this.rate = rate; }
        double available() { return balance; }
        @Override void monthEnd() { balance += balance * rate / 12; }
        String type() { return "Savings"; }
    }
    static class Current extends Account {
        private final double overdraft;
        Current(String o, double open, double od) { super("C", o, open); overdraft = od; }
        double available() { return balance + overdraft; }
        String type() { return "Current"; }
    }
    static class Bank {
        private final Map<String, Account> accounts = new LinkedHashMap<>();
        Account open(Account a) { accounts.put(a.id, a); return a; }
        Account find(String id) { Account a = accounts.get(id); if (a == null) throw new NoSuchElementException("no account " + id); return a; }
        void transfer(String from, String to, double amt) { Account f = find(from), t = find(to); f.withdraw(amt); t.deposit(amt); }
        void monthEnd() { accounts.values().forEach(Account::monthEnd); }
        void print(String title) { System.out.println(title); accounts.values().forEach(a -> System.out.println("  " + a)); }
    }
    public static void main(String[] args) {
        Bank bank = new Bank();
        bank.open(new Current("Ravi", 200, 500)); bank.open(new Savings("Asha", 1000, 0.06));
        bank.print("opening balances:");
        String[][] ops = {{"C-1", "S-1", "300"}, {"C-1", "S-1", "600"}, {"S-1", "X-9", "10"}, {"S-1", "C-1", "100"}};
        for (String[] op : ops) {
            try { bank.transfer(op[0], op[1], Double.parseDouble(op[2])); System.out.println("transferred " + op[2] + " " + op[0] + " -> " + op[1]); }
            catch (RuntimeException e) { System.out.println("error: " + e.getMessage()); }
        }
        bank.monthEnd();
        bank.print("after transfers and month-end interest:");
    }
}

            window.addLast(i);
            if (window.peekFirst() <= i - 3) window.pollFirst();
            if (i >= 2) maxes.add(a[window.peekFirst()]);
        }
        System.out.println("sliding window max (k=3): " + maxes);
        Map<String, List<String>> groups = Stream.of("eat", "tea", "tan", "ate", "nat", "bat").collect(Collectors.groupingBy(w -> { char[] c = w.toCharArray(); Arrays.sort(c); return new String(c); }, TreeMap::new, Collectors.toList()));
        System.out.println("group anagrams: " + groups.values());
        System.out.println("intersection of two lists: " + new TreeSet<>(List.of(1, 2, 3, 4)).stream().filter(new HashSet<>(List.of(3, 4, 5))::contains).toList());

A transfer that commits, one that rolls back, a batch insert, and an SQL-injection demonstration (run for real)
// libs
import java.sql.*;
import java.util.*;
public class Main {
    static int balance(Connection c, int id) throws SQLException {
        try (PreparedStatement ps = c.prepareStatement("SELECT balance FROM account WHERE id = ?")) { ps.setInt(1, id); try (ResultSet rs = ps.executeQuery()) { rs.next(); return rs.getInt(1); } }
    }
    static void transfer(Connection c, int from, int to, int amt) throws SQLException {
        c.setAutoCommit(false);                                      // start a transaction
        try (PreparedStatement debit = c.prepareStatement("UPDATE account SET balance = balance - ? WHERE id = ?");
             PreparedStatement credit = c.prepareStatement("UPDATE account SET balance = balance + ? WHERE id = ?")) {
            debit.setInt(1, amt); debit.setInt(2, from); debit.executeUpdate();
            if (balance(c, from) < 0) throw new SQLException("insufficient funds in account " + from);
            credit.setInt(1, amt); credit.setInt(2, to); credit.executeUpdate();
            c.commit();
            System.out.println("COMMIT transfer " + amt + " from " + from + " to " + to);
        } catch (SQLException e) {
            c.rollback();
            System.out.println("ROLLBACK: " + e.getMessage());
        } finally { c.setAutoCommit(true); }
    }
    public static void main(String[] args) throws SQLException {
        try (Connection c = DriverManager.getConnection("jdbc:h2:mem:bank;DB_CLOSE_DELAY=-1")) {
            try (Statement st = c.createStatement()) {
                st.execute("CREATE TABLE account(id INT PRIMARY KEY, owner VARCHAR(30), balance INT)");
                st.execute("INSERT INTO account VALUES (1,'Asha',1000),(2,'Ravi',200)");
            }
            transfer(c, 1, 2, 300);
            transfer(c, 2, 1, 5000);
            System.out.println("balances: Asha=" + balance(c, 1) + " Ravi=" + balance(c, 2) + " (total still 1200: all or nothing)");
            try (PreparedStatement ps = c.prepareStatement("INSERT INTO account VALUES (?,?,?)")) {
                for (int i = 10; i < 15; i++) { ps.setInt(1, i); ps.setString(2, "user" + i); ps.setInt(3, i * 10); ps.addBatch(); }
                int[] counts = ps.executeBatch();
                System.out.println("batch inserted " + counts.length + " rows in one round trip");
            }
            // SQL injection: the dangerous way vs the safe way
            String evil = "x' OR '1'='1";
            try (Statement st = c.createStatement(); ResultSet rs = st.executeQuery("SELECT COUNT(*) FROM account WHERE owner = '" + evil + "'")) {
                rs.next(); System.out.println("string concatenation with input  " + evil + "  matches " + rs.getInt(1) + " rows (every row: INJECTION!)");
            }
            try (PreparedStatement ps = c.prepareStatement("SELECT COUNT(*) FROM account WHERE owner = ?")) {
                ps.setString(1, evil);
                try (ResultSet rs = ps.executeQuery()) { rs.next(); System.out.println("PreparedStatement with the same input matches " + rs.getInt(1) + " rows (treated as plain text: SAFE)"); }
            }
        }
    }
}

// ROLLBACK: insufficient funds in account 2
// balances: Asha=700 Ravi=500 (total still 1200: all or nothing)

Good to know

  • Pattern: setAutoCommit(false) → work → commit(); in catch → rollback(); in finally → setAutoCommit(true) / close.
  • Batches (addBatch / executeBatch) cut network round trips for bulk inserts.
  • Isolation levels (READ_COMMITTED, REPEATABLE_READ, SERIALIZABLE) trade safety for speed. Frameworks (Spring @Transactional) manage all this for you.
Security: SQL injection is one of the most common web vulnerabilities. Parameterised queries (PreparedStatement, JPA named parameters) are the fix; escaping by hand is not.

77 The DAO Pattern and a Connection Pool

Picture: A library desk: you ask the librarian (DAO) for 'the book about Java'; you never walk into the stacks and read shelf labels yourself. And a pool is a rack of reusable library cards, because making a new card (a database connection) for every visit is slow.
A StudentDao interface, a JDBC implementation, a tiny connection pool and 12 concurrent inserts through 3 connections (run for real)
// libs
import java.sql.*;
import java.util.*;
import java.util.concurrent.*;
public class Main {
    record Student(int id, String name, String city, int marks) {}
    interface StudentDao { Student save(Student s); Optional<Student> findById(int id); List<Student> findByCity(String city); int count(); }

    static class SimplePool implements AutoCloseable {                    // a toy connection pool: real apps use HikariCP
        private final BlockingQueue<Connection> idle = new ArrayBlockingQueue<>(3);
        SimplePool(String url, int n) throws SQLException { for (int i = 0; i < n; i++) idle.add(DriverManager.getConnection(url)); }
        Connection borrow() throws InterruptedException { return idle.take(); }
        void giveBack(Connection c) { idle.add(c); }
        public void close() throws SQLException { for (Connection c : idle) c.close(); }
    }
    static class JdbcStudentDao implements StudentDao {
        private final SimplePool pool;
        JdbcStudentDao(SimplePool pool) { this.pool = pool; }
        public Student save(Student s) {
            return withConnection(c -> {
                try (PreparedStatement ps = c.prepareStatement("INSERT INTO student(name, city, marks) VALUES (?,?,?)", Statement.RETURN_GENERATED_KEYS)) {
                    ps.setString(1, s.name()); ps.setString(2, s.city()); ps.setInt(3, s.marks()); ps.executeUpdate();
                    try (ResultSet k = ps.getGeneratedKeys()) { k.next(); return new Student(k.getInt(1), s.name(), s.city(), s.marks()); }
                }
            });
        }
        public Optional<Student> findById(int id) {
            return withConnection(c -> { try (PreparedStatement ps = c.prepareStatement("SELECT * FROM student WHERE id = ?")) { ps.setInt(1, id); try (ResultSet rs = ps.executeQuery()) { return rs.next() ? Optional.of(map(rs)) : Optional.empty(); } } });
        }
        public List<Student> findByCity(String city) {
            return withConnection(c -> { try (PreparedStatement ps = c.prepareStatement("SELECT * FROM student WHERE city = ? ORDER BY id")) { ps.setString(1, city); try (ResultSet rs = ps.executeQuery()) { List<Student> l = new ArrayList<>(); while (rs.next()) l.add(map(rs)); return l; } } });
        }
        public int count() { return withConnection(c -> { try (Statement st = c.createStatement(); ResultSet rs = st.executeQuery("SELECT COUNT(*) FROM student")) { rs.next(); return rs.getInt(1); } }); }
        private Student map(ResultSet rs) throws SQLException { return new Student(rs.getInt("id"), rs.getString("name"), rs.getString("city"), rs.getInt("marks")); }
        interface Work<T> { T run(Connection c) throws SQLException; }
        private <T> T withConnection(Work<T> w) {
            Connection c = null;
            try { c = pool.borrow(); return w.run(c); }
            catch (SQLException | InterruptedException e) { throw new IllegalStateException(e); }
            finally { if (c != null) pool.giveBack(c); }
        }
    }
    public static void main(String[] args) throws Exception {
        String url = "jdbc:h2:mem:dao;DB_CLOSE_DELAY=-1";
        try (SimplePool pool = new SimplePool(url, 3)) {
            Connection setup = pool.borrow();
            try (Statement st = setup.createStatement()) { st.execute("CREATE TABLE student(id INT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(50), city VARCHAR(30), marks INT)"); }
            pool.giveBack(setup);
            StudentDao dao = new JdbcStudentDao(pool);
            dao.save(new Student(0, "Asha", "Pune", 91)); dao.save(new Student(0, "Ravi", "Delhi", 78)); Student m = dao.save(new Student(0, "Meera", "Pune", 85));
            System.out.println("saved " + m + ", count=" + dao.count());
            System.out.println("findById(2) = " + dao.findById(2).map(Student::name).orElse("-") + ", findById(99) present? " + dao.findById(99).isPresent());
            System.out.println("findByCity(Pune) = " + dao.findByCity("Pune").stream().map(Student::name).toList());
            ExecutorService ex = Executors.newFixedThreadPool(6);
            List<Future<Student>> fs = new ArrayList<>();
            for (int i = 0; i < 12; i++) { final int n = i; fs.add(ex.submit(() -> dao.save(new Student(0, "temp" + n, "Goa", n)))); }
            for (Future<Student> f : fs) f.get();
            ex.shutdown();
            System.out.println("12 concurrent inserts through a 3-connection pool; count now " + dao.count());
        }
        System.out.println("The DAO hides SQL behind an interface: callers use Java objects (Student), tests can swap in a fake.");
    }
}

The program writes two JSP files, starts embedded Tomcat with the JSP engine (Jasper), requests a plain JSP with scriptlets/EL, and a servlet that forwards to a JSP that loops with JSTL.

// libs
import jakarta.servlet.*;
import jakarta.servlet.http.*;
import org.apache.catalina.Context;
import org.apache.catalina.startup.Tomcat;
import java.io.*;

import java.net.http.*;

import java.util.*;
import java.util.logging.Handler;
import java.util.logging.Level;
import java.util.logging.Logger;

public class Main {
    public static class Student {   // a JavaBean: private fields + getters, which is what EL (${s.name}) calls
        private final String name; private final int marks;
        public Student(String name, int marks) { this.name = name; this.marks = marks; }
        public String getName() { return name; } public int getMarks() { return marks; }

    public static class ListController extends HttpServlet {                // the C of MVC: gets data, then forwards to the view
        private static final long serialVersionUID = 1L;
        @Override protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
            List<Student> students = List.of(new Student("Asha", 91), new Student("Ravi", 78), new Student("Meera", 62));
            req.setAttribute("students", students);                          // the M (model) handed to the view
            req.setAttribute("title", "Class <A>");
            req.getRequestDispatcher("/students.jsp").forward(req, resp);
        }
    }
    public static void main(String[] args) throws Exception {
        Logger.getLogger("").setLevel(Level.SEVERE);
        for (Handler h : Logger.getLogger("").getHandlers()) h.setLevel(Level.SEVERE);

            <%-- a JSP comment: not sent to the browser --%>
            <%! int twice(int x) { return x * 2; } %>
            <html><body>
            <h1>Hello <%= request.getParameter("name") == null ? "guest" : request.getParameter("name") %></h1>
            <% int total = 0; for (int i = 1; i <= 3; i++) { total += i; } %>
            <p>scriptlet total: <%= total %>, declaration twice(21): <%= twice(21) %></p>
            <p>EL: ${param.name} and ${1 + 2} and ${empty param.zzz}</p>
            </body></html>

            <%@ page contentType="text/html;charset=UTF-8" %>

            <html><body>
            <h1><c:out value="${title}"/></h1>

            <c:forEach var="s" items="${students}">
              <tr class="${s.marks >= 75 ? 'pass' : 'fail'}"><td>${s.name}</td><td>${s.marks}</td><td>${s.grade}</td></tr>

            """);
        Tomcat tomcat = new Tomcat();
        tomcat.setBaseDir(base.toString());
        tomcat.setPort(0); tomcat.getConnector();

        } catch (IOException | RuntimeException e) { System.out.println("(generated sources not kept: " + e.getClass().getSimpleName() + ")"); }
        tomcat.stop(); tomcat.destroy();
    }
}

Student.java: a JPA entity with Bean Validation (this file is real project source)
package demo.school;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;

@Entity
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank(message = "name must not be blank")
    private String name;

    private String city;

    @Min(value = 0, message = "marks must be at least 0")
    @Max(value = 100, message = "marks must be at most 100")
    private int marks;

    protected Student() { }                       // JPA needs a no-argument constructor

    public Student(String name, String city, int marks) {
        this.name = name;
        this.city = city;
        this.marks = marks;
    }

    public Long getId() { return id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public String getCity() { return city; }
    public void setCity(String city) { this.city = city; }
    public int getMarks() { return marks; }
    public void setMarks(int marks) { this.marks = marks; }
}

@Entity maps the class to a table; @Id @GeneratedValue makes the database create ids; @NotBlank, @Min, @Max are Bean Validation rules checked at the API edge. JPA needs a no-argument constructor (kept protected).

Good to know

  • Derived query methods: findByCityOrderByNameAsc(String city) becomes select ... where city = ? order by name. Keywords: And, Or, Between, Like, In, GreaterThan, OrderBy, Top3.

89 Service and Controller: Business Logic and REST

Picture: The service is the manager who applies the school's rules; the controller is the receptionist who talks HTTP and JSON to the outside world.

StudentService.java (real source)
package demo.school;

import java.util.List;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.web.server.ResponseStatusException;

@Service
public class StudentService {

    private final StudentRepository repo;

    public StudentService(StudentRepository repo) {
        this.repo = repo;
    }

    public List<Student> list(String city) {
        return city == null ? repo.findAll() : repo.findByCityOrderByNameAsc(city);
    }

    public Student get(Long id) {
        return repo.findById(id).orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "student " + id + " not found"));
    }

    @Transactional
    public Student create(Student s) {
        return repo.save(new Student(s.getName(), s.getCity(), s.getMarks()));
    }

    @Transactional
    public Student update(Long id, Student in) {
        Student s = get(id);
        s.setName(in.getName());
        s.setCity(in.getCity());
        s.setMarks(in.getMarks());
        return s;                                  // changes are saved automatically at commit (dirty checking)
    }

    @Transactional
    public void delete(Long id) {
        repo.delete(get(id));
    }

    public long count() {
        return repo.count();
    }

    public double average() {
        Double avg = repo.averageMarks();
        return avg == null ? 0 : Math.round(avg * 100.0) / 100.0;
    }
}

Note update: it just changes the managed entity's fields; JPA's dirty checking saves the changes when the transaction commits. A missing student becomes a ResponseStatusException with status 404.

Good to know

  • @Transactional on a method: Spring starts a transaction, commits on normal return, rolls back on unchecked exceptions. It works through a proxy, so calling a transactional method from the same class bypasses it (a classic pitfall).

package demo.school;

import java.util.stream.Collectors;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class ApiErrors {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ProblemDetail invalid(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .map(f -> f.getField() + ": " + f.getDefaultMessage())
                .sorted().collect(Collectors.joining("; "));
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.BAD_REQUEST, msg);
        pd.setTitle("Validation failed");
        return pd;
    }
}

@RestControllerAdvice applies to every controller. ProblemDetail is Spring's implementation of the standard RFC 9457 'problem details' JSON format (application/problem+json).

package demo.school;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.core.userdetails.User;
import org.springframework.security.crypto.factory.PasswordEncoderFactories;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.provisioning.InMemoryUserDetailsManager;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {
    @Bean
    SecurityFilterChain chain(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())                        // fine for a stateless token/basic API; keep CSRF ON for browser forms
            .authorizeHttpRequests(a -> a
                .requestMatchers("/actuator/health").permitAll()
                .requestMatchers(org.springframework.http.HttpMethod.GET, "/api/**").hasAnyRole("USER", "ADMIN")
                .anyRequest().hasRole("ADMIN"))
            .httpBasic(Customizer.withDefaults())
            .build();
    }
    @Bean PasswordEncoder encoder() { return PasswordEncoderFactories.createDelegatingPasswordEncoder(); }
    @Bean InMemoryUserDetailsManager users(PasswordEncoder enc) {
        return new InMemoryUserDetailsManager(
            User.withUsername("asha").password(enc.encode("change-me")).roles("ADMIN").build());
    }
}

97 Project: Word Frequency Statistics with Streams

Picture: Counting how often each word appears in a story, like tallying votes.

Reads text, lower-cases it, splits words, counts them with groupingBy/counting, sorts by frequency then alphabetically, and draws a small histogram. The same task in C++ is in the C++ guide.

Counting words in a short text (run for real)
import java.util.*;
import java.util.stream.*;
public class Main {
    public static void main(String[] args) {
        String text = """
            It was the best of times, it was the worst of times, it was the age of wisdom,
            it was the age of foolishness, it was the epoch of belief.
            """;
        List<String> words = Arrays.stream(text.toLowerCase().split("[^a-z]+")).filter(w -> !w.isBlank()).toList();
        Map<String, Long> freq = words.stream().collect(Collectors.groupingBy(w -> w, Collectors.counting()));
        System.out.println("total words: " + words.size() + ", distinct: " + freq.size() + ", longest: " + words.stream().max(Comparator.comparingInt(String::length)).get());
        System.out.println("top words:");
        freq.entrySet().stream()
            .sorted(Map.Entry.<String, Long>comparingByValue().reversed().thenComparing(Map.Entry.comparingByKey()))
            .limit(5)
            .forEach(e -> System.out.printf("  %-8s %s %d%n", e.getKey(), "#".repeat(e.getValue().intValue()), e.getValue()));
        Map<Integer, Long> byLen = words.stream().collect(Collectors.groupingBy(String::length, TreeMap::new, Collectors.counting()));
        System.out.println("words by length: " + byLen);
    }
}

// ----- Output (real run: JDK 25, Temurin) -----
// total words: 30, distinct: 12, longest: foolishness
// top words:
//   it       ##### 5
//   of       ##### 5
//   the      ##### 5
//   was      ##### 5
//   age      ## 2
// words by length: {2=10, 3=12, 4=1, 5=4, 6=2, 11=1}

30 words, 12 distinct; 'it', 'of', 'the' and 'was' lead with 5 each (ties are broken alphabetically).

100 FAQ

Picture: Questions beginners ask most.
Q: Is Java still worth learning in 2026?

Yes. It runs a large share of enterprise back ends, Android code (with Kotlin), big-data tools and finance systems; the language keeps modernising (records, pattern matching, virtual threads).

Q: Which Java version should I install?

A current LTS: Java 21 or 25. Everything on this page compiles on Java 25.

Q: Java or C++ first?

Java is gentler (garbage collector, no pointers, clear errors). Learning C++ afterwards teaches what the JVM hides; the two guides are written to be read side by side.

Q: Do I need to learn servlets and JSP before Spring Boot?

You can start with Spring Boot, but servlets explain what Spring MVC does under the hood (requests, sessions, filters). A quick pass through the servlet section is time well spent.

Q: Spring Boot or Jakarta EE?

Most new projects choose Spring Boot; Jakarta EE is chosen for vendor-neutral standards. Skills transfer (both use JPA, Bean Validation, CDI-style injection).

Q: Why does my code say javax.servlet not found?

Jakarta EE 9+ renamed the packages to jakarta.*. Use jakarta imports with Tomcat 10+/Spring Boot 3+/4; old javax code needs migration.

Q: Why use ArrayList and not Vector or Stack?

Vector and Stack are old, synchronised and slower. Use ArrayList and ArrayDeque; use concurrent collections for threads.

Q: Is Java slow?

After JIT warm-up it is fast, usually within a small factor of C++ on server workloads. Start-up time and memory use are the costs; native images and tuning help.

101 Interview Questions (With Answers)

Picture: A practice interview, grouped from easy to hard.

1. Java basics

Q1: JDK vs JRE vs JVM?

JVM runs bytecode; JRE = JVM + libraries; JDK = JRE + developer tools (javac etc.).

Q2: Why is Java platform independent?

Source compiles to bytecode, which any JVM runs; the JVM hides OS differences.

Q3: Primitive vs wrapper types?

Primitives are raw values (never null); wrappers are objects needed for collections and null. Autoboxing converts automatically; unboxing null throws NPE.

Q4: Is Java pass by value or by reference?

Always by value; for objects the value is a copy of the reference, so the object can be changed but the caller's variable cannot be re-pointed.

Q5: == vs equals()?

== compares primitives by value and references by identity; equals compares logical content (if overridden).

Q6: Why is String immutable? What is the string pool?

Immutability gives safety, caching of hash codes, thread-safety and pool sharing. Literals with equal text share one pooled object.

Q7: String vs StringBuilder vs StringBuffer?

String immutable; StringBuilder mutable and fast (not thread-safe); StringBuffer mutable and synchronised (legacy).

Q8: What are var, records and sealed classes?

var infers local types; records are immutable data classes; sealed classes restrict permitted subclasses so switches can be exhaustive.

2. OOP

Q9: Four pillars of OOP?

Encapsulation, abstraction, inheritance, polymorphism (see the OOP part).

Q10: Abstract class vs interface?

Abstract class: state, constructors, one parent only; interface: contract with default/static methods, many per class. Use interfaces for roles, abstract classes for shared state/code.

Q11: Overloading vs overriding?

Overloading: same name, different parameters, resolved at compile time. Overriding: subclass redefines a method with the same signature, resolved at run time.

Q12: Why does Java not support multiple inheritance of classes?

To avoid the diamond problem and complexity; interfaces (with default methods) give multiple inheritance of behaviour; a class that inherits clashing defaults must override.

Q13: What is the contract between equals and hashCode?

Equal objects must have equal hash codes; equals must be reflexive, symmetric, transitive, consistent. Break it and HashMap/HashSet misbehave.

Q14: What does static mean? final?

static: belongs to the class. final: variable assigned once, method not overridable, class not extendable.

Q15: What happens in what order when an object is created?

Class loading and static init (once), parent constructor chain, field initialisers and instance blocks, constructor body.

Q16: Composition vs inheritance?

Inheritance = is-a, tight coupling; composition = has-a, flexible. Prefer composition.

Q17: Shallow vs deep copy?

Shallow copies references to inner objects; deep copies them too (see the copy demo).

Q18: How is polymorphism implemented in the JVM?

Virtual method tables; invokevirtual picks the method from the object's real class. (Similar to the C++ vtable.)

Q19: How do you make a class immutable?

final class, private final fields, no setters, defensive copies, return new objects.

Q20: Java vs C++ OOP differences?

See the side-by-side table: references vs value objects, GC vs RAII, single class inheritance, virtual-by-default, no operator overloading, no header files.

3. Exceptions and memory

Q21: Checked vs unchecked exceptions?

Checked (Exception subclasses) must be handled/declared; unchecked (RuntimeException, Error) need not.

Q22: What does try-with-resources do?

Closes AutoCloseable resources automatically in reverse order, even on exceptions; failures in close are suppressed exceptions.

Q23: How does garbage collection work? Can you force it?

The GC frees objects unreachable from GC roots; generational collectors (G1 default, ZGC) collect young objects often. System.gc() is only a hint.

Q24: What causes memory leaks in Java?

Unneeded references kept alive: static collections, unremoved listeners, caches without eviction, ThreadLocals.

Q25: StackOverflowError vs OutOfMemoryError?

Stack overflow: too-deep recursion exhausts a thread's stack. OOM: heap (or metaspace) exhausted.

4. Collections and generics (with C++ STL comparisons)

Q26: ArrayList vs LinkedList? Which C++ containers are they?

ArrayList ~ std::vector (array, O(1) index); LinkedList ~ std::list (doubly linked, O(1) insert at a node). ArrayList wins in practice.

Q27: HashMap vs TreeMap vs LinkedHashMap? C++ twins?

HashMap ~ unordered_map (O(1)); TreeMap ~ map (sorted, O(log n)); LinkedHashMap has no direct twin (insertion/access order).

Q28: How does HashMap work internally?

An array of buckets; hashCode picks a bucket; collisions chain (treeify when long); resizes at 75% load; keys need equals+hashCode.

Q29: HashMap vs ConcurrentHashMap vs Hashtable?

HashMap is not thread-safe; Hashtable locks everything (legacy); ConcurrentHashMap uses fine-grained locking/CAS with atomic compute/merge.

Q30: What is a fail-fast iterator?

It throws ConcurrentModificationException if the collection is structurally changed during iteration (C++ would be undefined behaviour).

Q31: Comparable vs Comparator?

Comparable: the class's natural order (compareTo); Comparator: an external, replaceable ordering.

Q32: PriorityQueue differences from C++ priority_queue?

Java's is a min-heap by default, C++'s a max-heap; iteration order is not sorted in either.

Q33: What is type erasure?

Generics are checked at compile time and erased in bytecode; so no new T(), no primitives as type arguments, no instanceof List<String>.

Q34: What are PECS wildcards?

Producer Extends, Consumer Super: List<? extends T> to read, List<? super T> to write.

Q35: List.of vs Arrays.asList vs Collections.unmodifiableList?

List.of is immutable (no nulls); Arrays.asList is fixed-size but writable-through to the array; unmodifiableList is a read-only view of a mutable list.

Q36: Stream vs C++ ranges?

Both are lazy pipelines; a Java stream is single-use; ranges views can be re-iterated.

5. Concurrency

Q37: Thread vs Runnable vs Callable?

Thread is the worker; Runnable the task without result; Callable returns a result and can throw.

Q38: synchronized vs volatile vs atomic?

synchronized: mutual exclusion + visibility; volatile: visibility only; atomics: lock-free single-variable updates.

Q39: What are virtual threads?

Lightweight JVM-scheduled threads (Java 21+) that make blocking code scalable; one per task, no pooling.

Q40: What is a deadlock? How to avoid it?

Threads waiting for each other's locks forever. Acquire locks in a consistent order, use timeouts (tryLock), minimise lock scope.

Q41: What is the Java Memory Model's happens-before?

Rules guaranteeing when one thread's writes are visible to another (locks, volatile, thread start/join).

6. JDBC, Servlets, JSP and J2EE

Q42: Statement vs PreparedStatement?

PreparedStatement uses placeholders, prevents SQL injection and can be precompiled and reused.

Q43: How do you handle transactions in JDBC?

setAutoCommit(false), run statements, commit(), rollback() on failure.

Q44: Why use a connection pool?

Opening connections is slow; pools (HikariCP) reuse them and cap load.

Q45: Describe the servlet lifecycle.

init once, service/doGet/doPost per request (one instance, many threads), destroy once.

Q46: Forward vs redirect?

Forward happens inside the server, same request, URL unchanged; redirect sends a 302 so the browser makes a new request and the URL changes.

Q47: How do sessions work?

The container creates a session object and sends a JSESSIONID cookie; the browser returns it with each request.

Q48: Filter vs servlet vs listener?

Filter wraps requests/responses (cross-cutting), servlet produces the response, listener reacts to lifecycle events.

Q49: What is JSP and how does it relate to servlets?

A JSP is translated into a servlet class and compiled on first use; EL and JSTL avoid Java code in pages.

Q50: J2EE vs Java EE vs Jakarta EE?

Same platform renamed: J2EE (to 2005), Java EE (2006–2017), Jakarta EE (from 2018; jakarta.* packages since version 9).

Q51: JPA vs Hibernate vs Spring Data JPA?

JPA is the standard, Hibernate an implementation, Spring Data JPA removes repository boilerplate on top of them.

Q52: What is the N+1 select problem?

One query for parents plus one per child. Fix with join fetch, entity graphs or batch fetching.

7. Spring and Spring Boot

Q53: What is IoC and DI?

The container creates and wires objects (IoC); dependencies are supplied from outside, preferably through constructors (DI).

Q54: What does @SpringBootApplication do?

Combines @Configuration, @EnableAutoConfiguration and @ComponentScan.

Q55: How does auto-configuration work?

Conditional configuration classes (@ConditionalOnClass, @ConditionalOnMissingBean) activate according to the classpath and properties.

Q56: Bean scopes?

singleton (default), prototype, request, session, application.

Q57: @Component vs @Service vs @Repository vs @Controller?

All stereotypes registering beans; the others add meaning (and @Repository translates persistence exceptions).

Q58: How does @Transactional work, and what is the self-invocation pitfall?

A proxy wraps the bean and begins/commits transactions; calling a transactional method from inside the same class bypasses the proxy.

Q59: How do you validate request bodies and return errors?

@Valid + Bean Validation annotations, handled by @RestControllerAdvice returning ProblemDetail (as in the project).

Q60: How do you test a Boot app?

@SpringBootTest with MockMvc, or slices such as @WebMvcTest/@DataJpaTest; Mockito for unit tests.

Q61: How do you configure different environments?

Profiles and external config (env vars, config server); never commit secrets.

Q62: Explain a layered architecture and why.

Controller (HTTP) → Service (rules, transactions) → Repository (data): separation of concerns, easier tests and change.

8. Coding questions to practise

Q63: Reverse a string / check a palindrome / count words.

StringBuilder.reverse, two pointers, split + groupingBy (see the word-statistics project).

Q64: Implement an LRU cache.

LinkedHashMap with accessOrder and removeEldestEntry (8 lines), or HashMap + doubly linked list.

Q65: Producer-consumer.

BlockingQueue with a producer thread and consumer loop (see the concurrent collections demo).

Q66: Write a thread-safe singleton.

An enum singleton, or a holder class; avoid double-checked locking unless the field is volatile.

103 Quick Quiz

Picture: Check yourself: click a question to reveal the answer.
1. What does new String("hi") == "hi" give, and why?

false: new creates a separate object; the literal is the pooled one. equals would be true.

2. Which C++ container is ArrayList? HashMap? TreeMap? PriorityQueue?

vector, unordered_map, map, priority_queue (but Java's is a min-heap by default).

3. Why did map.get(key) return null after the key object was changed?

Its hashCode changed, so the lookup went to a different bucket than where the entry was stored: never mutate keys.

4. What status code does a servlet send for a method it did not implement?

405 Method Not Allowed (as the demo showed for GET /students).

It treats input as data, not SQL: the demo showed the concatenated query matching every row while the prepared one matched none.

6. What does @SpringBootApplication stand for?

@Configuration + @EnableAutoConfiguration + @ComponentScan.

7. 10,000 tasks each sleeping 100 ms: why did virtual threads finish in about 0.2 s?

They all slept at the same time on a few carrier threads; a fixed pool of 200 platform threads would need 50 sequential rounds (5 s).

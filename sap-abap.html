2 What Is ABAP?

Picture: The house language of a big family business. Outsiders speak English, but inside the family every recipe, rule and shopping list is written in the family language. ABAP is SAP's house language: Advanced Business Application Programming.
FeatureWhat it means for you
Built for business dataDatabase access (ABAP SQL) is part of the language, not a library
Runs inside the SAP serverYou do not install ABAP on your laptop; programs live in the SAP system's repository
Strongly typed, compiled to byte codeTypes come from the ABAP Dictionary, so a 'customer number' has the same type everywhere
Multi-paradigmOld procedural style (reports, FORMs, function modules) and object-oriented ABAP Objects
Backward compatibleCode from the 1990s often still runs; you will read old and new styles side by side
Two language versions todayStandard ABAP (everything) and ABAP for Cloud Development (a restricted, upgrade-safe subset)

Good to know

  • Keywords are not case-sensitive (WRITE = write); every statement ends with a full stop .
  • ABAP looks like English sentences: SELECT ... FROM ... WHERE ... INTO TABLE ..., LOOP AT ... ENDLOOP.
  • Who uses it: SAP's own developers, customer IT teams and consultancies. The demand is large because many big companies run on SAP (as widely reported; exact counts change).

7 Classic ABAP vs ABAP Cloud (and 'Clean Core')

Picture: Renting a flat with a contract. In the old days you could knock down walls (modify SAP code); every renovation of the building (upgrade) then broke your changes. Now the landlord says: use the official hooks and sockets (released APIs and extension points) and your furniture survives every renovation. That is clean core.
Classic ABAP (Standard ABAP)ABAP Cloud (ABAP for Cloud Development)

LanguageEverything, including old statements (WRITE, screens, CALL TRANSACTION)Restricted subset: no classic screens/lists, no direct access to SAP tables
SAP objects you may useAny table, function module, classOnly released APIs (C1 contract), e.g. released CDS views and classes

UpgradesYour code may break on upgradeDesigned to be upgrade-safe

Good to know

  • Each object has a language version (in ADT: Properties). The compiler and ATC enforce the rules.
  • SAP describes extensibility tiers for on-premise/private cloud (as reported, 2023-2025): tier 1 = ABAP Cloud, tier 2 = wrappers around not-yet-released objects, tier 3 = classic code. Newer SAP material talks about clean-core 'levels' A-D; check the current wording before using it in an interview.
  • You still need classic ABAP: most existing company code is classic, and migrations need people who read both.

9 Your First Program (Classic and Cloud)

Picture: Writing your name on the first page of a new notebook. Two notebooks exist: the classic one (a REPORT that prints a list) and the cloud one (a class that writes to the console).
Classic report (ABAP template, not run)
REPORT zhello_world.                      " every classic program starts with REPORT (or PROGRAM)

DATA lv_name TYPE string VALUE `World`.   " a variable of type string

START-OF-SELECTION.                       " the event where the main work starts
  WRITE / |Hello, { lv_name }!|.          " string template with an embedded expression
  WRITE / 'Today is', sy-datum.           " sy-datum = system field with today's date
* Output (classic list screen):
*   Hello, World!
*   Today is 19.11.2026          (shown in the user's date format)
ABAP Cloud console class (ABAP template, not run)
" ABAP Cloud: no REPORT, no WRITE. A global class with the interface if_oo_adt_classrun,
" run it in ADT (Eclipse or VS Code) with F9; the text appears in the Console view.
CLASS zcl_hello_cloud DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    INTERFACES if_oo_adt_classrun.
ENDCLASS.

CLASS zcl_hello_cloud IMPLEMENTATION.
  METHOD if_oo_adt_classrun~main.
    DATA(lv_name) = `ABAP Cloud`.                       " inline declaration: the type is taken from the value
    out->write( |Hello, { lv_name }!| ).
    out->write( |Today: { cl_abap_context_info=>get_system_date( ) DATE = ISO }| ).
  ENDMETHOD.
ENDCLASS.

Good to know

  • Create the object: ADT → File → New → ABAP Program (classic) or ABAP Class (cloud); choose a package ($TMP to start) and a transport request if asked.
  • Activate (Ctrl+F3) before running: an inactive version exists only for you; activation compiles it and makes it visible to everyone.
  • Run: F8 (report) or F9 (console class).
  • String literals: 'text' (quotes) = type c, trailing spaces ignored; `text` (backquotes) = type string; |...{ expr }...| = string template.

12 Structures: One Row with Named Fields

Picture: A form at the doctor's: name, age, city, blood group, all on one sheet. A structure is that sheet; each box on it is a component.
Structures (ABAP template, not run)
TYPES: BEGIN OF ty_student,
         id    TYPE i,
         name  TYPE string,
         city  TYPE string,
         marks TYPE p LENGTH 5 DECIMALS 1,
       END OF ty_student.

DATA ls_student TYPE ty_student.          " one structure (one 'row')
ls_student-id    = 1.                     " component selector is the dash: structure-field
ls_student-name  = `Asha`.
ls_student-city  = `Pune`.
ls_student-marks = '91.5'.

DATA(ls_copy) = VALUE ty_student( id = 2 name = `Ravi` city = `Delhi` marks = '78.0' ).
CLEAR ls_student.                         " every field back to its initial value
MOVE-CORRESPONDING ls_copy TO ls_student. " copy fields with the same names
ls_student = CORRESPONDING #( ls_copy ).  " the same, as an expression

Good to know

  • Access a field with the dash: ls_student-name. For objects you use the arrow lo_obj->attr, for static members zcl=>attr.
  • CORRESPONDING #( ) copies fields by name; use MAPPING when names differ.
  • Nested structures and 'deep' structures (with tables inside) are allowed.

Working with internal tables (ABAP template, not run)
TYPES ty_students TYPE STANDARD TABLE OF ty_student WITH EMPTY KEY.          " like a list
DATA  lt_sorted   TYPE SORTED TABLE OF ty_student WITH UNIQUE KEY id.         " kept sorted by id
DATA  lt_hashed   TYPE HASHED TABLE OF ty_student WITH UNIQUE KEY id.         " like a dictionary

DATA(lt_students) = VALUE ty_students(
  ( id = 1 name = `Asha` city = `Pune`  marks = '91.5' )
  ( id = 2 name = `Ravi` city = `Delhi` marks = '78.0' )
  ( id = 3 name = `Meera` city = `Pune` marks = '85.0' ) ).

APPEND VALUE #( id = 4 name = `John` city = `Goa` marks = '66.0' ) TO lt_students.
INSERT VALUE #( id = 0 name = `Zara` city = `Goa` marks = '70.0' ) INTO lt_students INDEX 1.

" Read one line
READ TABLE lt_students INTO DATA(ls_one) WITH KEY name = `Ravi`.   " sets sy-subrc (0 = found)
IF sy-subrc = 0.
  WRITE / ls_one-city.
ENDIF.
DATA(ls_two) = lt_students[ id = 3 ].                              " table expression (raises CX_SY_ITAB_LINE_NOT_FOUND if missing)
DATA(ls_safe) = VALUE #( lt_students[ id = 99 ] OPTIONAL ).       " no exception: initial line instead
IF line_exists( lt_students[ city = `Goa` ] ).
  WRITE / 'Someone lives in Goa'.
ENDIF.
DATA(lv_lines) = lines( lt_students ).

" Loop
LOOP AT lt_students ASSIGNING FIELD-SYMBOL(<ls_s>) WHERE city = `Pune`.  " change in place, no copy
  <ls_s>-marks = <ls_s>-marks + 1.
ENDLOOP.

" Change, delete, sort
MODIFY lt_students FROM VALUE #( id = 2 name = `Ravi` city = `Mumbai` marks = '80.0' ) TRANSPORTING city marks WHERE id = 2.
DELETE lt_students WHERE marks < 70.
SORT lt_students BY city ASCENDING marks DESCENDING.
DELETE ADJACENT DUPLICATES FROM lt_students COMPARING city.

" Fast reads on a standard table
SORT lt_students BY id.
READ TABLE lt_students INTO ls_one WITH KEY id = 3 BINARY SEARCH.  " only correct if sorted by id!

Good to know

  • Keys: WITH EMPTY KEY, WITH DEFAULT KEY (all character fields: avoid), WITH UNIQUE/NON-UNIQUE KEY ..., plus secondary keys (WITH NON-UNIQUE SORTED KEY by_city COMPONENTS city).
  • LOOP AT ... ASSIGNING FIELD-SYMBOL(<x>) changes rows in place without copying; INTO makes a copy.
  • Header lines (DATA itab TYPE ... WITH HEADER LINE, itab[]) are obsolete: you will see them in old code only.

14 Which Table Kind Is Fast? (Measured Simulation)

Picture: Finding a name in a phone book. Reading every line from the top (standard table) is slow. Opening in the middle and halving (sorted, binary search) is quick. Knowing the exact page because the name tells you where it is (hashed) is quickest.

This Python program imitates the three ABAP lookup strategies on 200,000 rows. The absolute times are Python's, on one laptop; the ratios show the same idea ABAP has.

Standard vs sorted vs hashed lookups (simulation in Python, not ABAP: run for real)
# Simulation of ABAP internal-table lookups (READ TABLE) in Python.
# STANDARD table + READ ... WITH KEY      -> linear scan          (like a list search)
# SORTED table  (or BINARY SEARCH)        -> binary search        (like bisect)
# HASHED table  + WITH TABLE KEY          -> hash lookup          (like a dict)
import bisect, random, time
random.seed(7)
N, LOOKUPS = 200_000, 1_000
ids = random.sample(range(10_000_000), N)            # customer numbers
standard = [(cid, f"Customer {cid}") for cid in ids]  # insertion order, unsorted
sorted_tab = sorted(standard)                          # SORTED TABLE ... WITH UNIQUE KEY id
sorted_keys = [r[0] for r in sorted_tab]
hashed = dict(standard)                                # HASHED TABLE ... WITH UNIQUE KEY id
wanted = random.sample(ids, LOOKUPS)

def linear(k):
    for row in standard:
        if row[0] == k:
            return row
def binary(k):
    i = bisect.bisect_left(sorted_keys, k)
    return sorted_tab[i]
def hashed_read(k):
    return (k, hashed[k])

for name, f in [("STANDARD  (linear scan)", linear), ("SORTED    (binary search)", binary), ("HASHED    (hash key)", hashed_read)]:
    t = time.perf_counter()
    for k in wanted:
        assert f(k)[0] == k
    ms = (time.perf_counter() - t) * 1000
    print(f"{name}: {LOOKUPS} lookups in {N} rows took {ms:10.2f} ms")
print("comparisons per lookup (worst case): linear", N, "| binary", N.bit_length(), "| hash ~1")

# ----- Output (real run) -----
# STANDARD  (linear scan): 1000 lookups in 200000 rows took    6864.85 ms
# SORTED    (binary search): 1000 lookups in 200000 rows took       1.51 ms
# HASHED    (hash key): 1000 lookups in 200000 rows took       0.69 ms
# comparisons per lookup (worst case): linear 200000 | binary 18 | hash ~1
Fig S3 — 1,000 lookups in 200,000 rows (simulation in Python, real run, one laptop; linear scale, so the sorted and hashed bars are almost invisible)

Good to know

  • Linear search grows with the table size (O(n)); binary search with log n (18 steps for 200,000 rows); hash stays about 1 step.
  • In real ABAP the classic performance bug is READ TABLE ... WITH KEY on a big standard table inside a LOOP: n × n steps. Use a sorted/hashed table or a secondary key.
  • For small tables (say under a few hundred rows) the kind hardly matters: choose what reads clearly.

17 Numbers and Money: Why Packed Decimals

Picture: A shopkeeper's cash box counts exact paise; a scientist's calculator shows 0.9999999. Money must be counted like the cash box. ABAP's packed type p stores digits exactly in decimal.
Packed decimal vs float (simulation in Python, not ABAP: run for real)
# Simulation of ABAP type P (packed decimal) vs type F (binary float) using Python's decimal module.
# ABAP: DATA amount TYPE p LENGTH 8 DECIMALS 2.  -> exact decimal, up to 15 digits, 2 after the point
from decimal import Decimal, ROUND_HALF_UP
f = 0.0
p = Decimal("0.00")
for _ in range(10):
    f += 0.10                     # type f (float)
    p += Decimal("0.10")          # type p (packed)
print("ten times 0.10 as float :", repr(f))
print("ten times 0.10 as packed:", p)
print("float == 1.00 ?", f == 1.0, "| packed == 1.00 ?", p == Decimal("1.00"))
# Commercial rounding: ABAP rounds half away from zero when a result is moved into p DECIMALS 2
for net in ["10.005", "2.675", "19.995"]:
    print(f"round {net:>7} -> packed {Decimal(net).quantize(Decimal('0.01'), ROUND_HALF_UP)}"
          f" | Python float round() -> {round(float(net), 2)}")
# 19% VAT on three lines: round per line vs round the total (a classic invoice difference)
lines = [Decimal("0.07"), Decimal("0.07"), Decimal("0.07")]
per_line = sum((x * Decimal("0.19")).quantize(Decimal("0.01"), ROUND_HALF_UP) for x in lines)
on_total = (sum(lines) * Decimal("0.19")).quantize(Decimal("0.01"), ROUND_HALF_UP)
print("VAT rounded per line:", per_line, "| VAT rounded on total:", on_total)
print("max value of p LENGTH 8 DECIMALS 2:", Decimal("9" * 13 + "." + "99"))

# ----- Output (real run) -----
# ten times 0.10 as float : 0.9999999999999999
# ten times 0.10 as packed: 1.00
# float == 1.00 ? False | packed == 1.00 ? True
# round  10.005 -> packed 10.01 | Python float round() -> 10.01
# round   2.675 -> packed 2.68 | Python float round() -> 2.67

Good to know

  • TYPE p LENGTH 8 DECIMALS 2: 8 bytes = 15 digits, 2 of them after the point.
  • When a result is moved into a p field with fewer decimals, ABAP rounds commercially (half away from zero). Python's round() on floats can surprise you (2.675 → 2.67, because 2.675 is not exact in binary).
  • Rounding per line vs on the total can give a different VAT amount (0.03 vs 0.04 above). Business rules decide which is right, not the programmer.
  • Amounts in DDIC have type CURR plus a currency key (CUKY); quantities have QUAN plus a unit (UNIT). Some currencies (JPY) have 0 decimals: always format with the currency.

# Simulation (real SQLite) of ABAP's FOR ALL ENTRIES IN itab semantics and its two classic traps.
import sqlite3
db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE orders(order_no INTEGER PRIMARY KEY, customer INTEGER, net REAL)")
db.executemany("INSERT INTO orders VALUES(?,?,?)",
               [(1, 100, 50), (2, 100, 50), (3, 200, 70), (4, 300, 20), (5, 400, 90)])

def for_all_entries(driver, fields):
    """ABAP: SELECT <fields> FROM orders FOR ALL ENTRIES IN driver WHERE customer = driver-customer."""
    if not driver:                                   # empty driver table: the WHERE condition is IGNORED
        rows = db.execute(f"SELECT {fields} FROM orders").fetchall()
    else:
        ids = ",".join(str(c) for c in driver)
        rows = db.execute(f"SELECT {fields} FROM orders WHERE customer IN ({ids})").fetchall()
    return sorted(set(rows))                         # FAE always removes duplicate result rows

print("driver [100, 200], select order_no, net :", for_all_entries([100, 200], "order_no, net"))
print("driver [100, 200], select customer, net :", for_all_entries([100, 200], "customer, net"),
      "<- order 1 and 2 collapsed into one row!")
print("driver [] (empty!)                      :", len(for_all_entries([], "order_no, net")), "rows = the WHOLE table")
print("Fix 1: IF driver IS NOT INITIAL before the SELECT.  Fix 2: always select the full key.")

# ----- Output (real run) -----
# driver [100, 200], select order_no, net : [(1, 50.0), (2, 50.0), (3, 70.0)]
# driver [100, 200], select customer, net : [(100, 50.0), (200, 70.0)] <- order 1 and 2 collapsed into one row!
# driver [] (empty!)                      : 5 rows = the WHOLE table

Good to know

  • Trap 1: empty driver table → the WHERE condition is ignored → all rows. Always guard with IF lt_driver IS NOT INITIAL.

32 SELECT Inside a LOOP: The Most Common Performance Bug

Picture: Going to the shop once for every egg you need, instead of once with a list. Each trip (database round trip) costs time even if the egg is small.
Nested SELECT vs FOR ALL ENTRIES vs JOIN (assumed 0.3 ms per round trip) (simulation in Python, not ABAP: run for real)
# Simulation of 'SELECT SINGLE inside LOOP' vs one JOIN vs FOR ALL ENTRIES.
# Real SQLite, plus an ASSUMED 0.3 ms network round trip per database call (the app server and DB are
# usually on different machines). The point is the number of round trips.
import sqlite3, time, random
random.seed(1)
ROUND_TRIP = 0.0003
db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE kna1(kunnr INTEGER PRIMARY KEY, name1 TEXT)")
db.execute("CREATE TABLE vbak(vbeln INTEGER PRIMARY KEY, kunnr INTEGER)")
db.executemany("INSERT INTO kna1 VALUES(?,?)", [(k, f"Customer {k}") for k in range(1, 2001)])
db.executemany("INSERT INTO vbak VALUES(?,?)", [(v, random.randint(1, 2000)) for v in range(1, 1001)])
calls = 0
def q(sql, args=()):
    global calls
    calls += 1
    time.sleep(ROUND_TRIP)
    return db.execute(sql, args).fetchall()

def nested():
    out = []
    for vbeln, kunnr in q("SELECT vbeln, kunnr FROM vbak"):
        out.append((vbeln, q("SELECT name1 FROM kna1 WHERE kunnr = ?", (kunnr,))[0][0]))   # SELECT SINGLE in LOOP
    return out
def join():
    return q("SELECT v.vbeln, k.name1 FROM vbak v JOIN kna1 k ON k.kunnr = v.kunnr")
def fae():
    orders = q("SELECT vbeln, kunnr FROM vbak")
    keys = sorted({k for _, k in orders})
    names = dict(q(f"SELECT kunnr, name1 FROM kna1 WHERE kunnr IN ({','.join(map(str, keys))})"))
    return [(v, names[k]) for v, k in orders]

ref = None
for name, f in [("SELECT SINGLE inside LOOP", nested), ("FOR ALL ENTRIES (2 SELECTs)", fae), ("one JOIN", join)]:
    calls = 0
    t = time.perf_counter()
    res = sorted(f())
    ms = (time.perf_counter() - t) * 1000
    ref = ref or res
    assert res == ref
    print(f"{name:<28}: {calls:5d} database calls, {ms:8.1f} ms")

# ----- Output (real run) -----
# SELECT SINGLE inside LOOP   :  1001 database calls,    762.1 ms
# FOR ALL ENTRIES (2 SELECTs) :     2 database calls,      8.8 ms
# one JOIN                    :     1 database calls,      4.4 ms

Good to know

  • 1,001 calls vs 2 vs 1: the number of round trips decides, not how clever each SELECT is.
  • Find it in real systems with the SQL trace ST05 (look for 'identical selects') or the ATC check for SELECT in loops.
  • The 0.3 ms per call is an assumption for illustration; real latency depends on the network and the database load.

# Simulation of SAP table buffering on several application servers.
# Each app server keeps its own buffer; a change on server A is told to the others by a periodic
# synchronisation (rdisp/bufreftime, often around 60 s), so B can read stale data for a while.
class AppServer:
    def __init__(self, name): self.name, self.buffer, self.hits, self.db_reads = name, {}, 0, 0
    def read(self, db, key):
        if key in self.buffer: self.hits += 1; return self.buffer[key]
        self.db_reads += 1; self.buffer[key] = db[key]; return db[key]

# Simulation of the SAP LUW with the update task:
#   CALL FUNCTION 'Z_SAVE_ORDER' IN UPDATE TASK ...   -> only REGISTERED (queued)
#   COMMIT WORK                                       -> the update work process runs all registered calls together
#   ROLLBACK WORK                                     -> the queue is thrown away
class SapLuw:
    def __init__(self, db): self.db, self.queue = db, []
    def call_in_update_task(self, fm, *args): self.queue.append((fm, args)); print(f"  registered {fm}{args}")
    def commit_work(self):
        snapshot = dict(self.db)
        try:
            for fm, args in self.queue:
                fm_impl[fm](self.db, *args)
            print("  COMMIT WORK: all", len(self.queue), "updates written together")
        except Exception as e:
            self.db.clear(); self.db.update(snapshot)          # update task fails -> whole LUW rolled back
            print("  update task error:", e, "-> NOTHING written (all or nothing)")
        self.queue.clear()
    def rollback_work(self): print("  ROLLBACK WORK: discarded", len(self.queue), "registered updates"); self.queue.clear()

def save_order(db, no, amt): db[f"order {no}"] = amt
def post_stock(db, item, qty):
    if qty > 10: raise ValueError(f"stock too low for {item}")
    db[f"stock {item}"] = db.get(f"stock {item}", 10) - qty
fm_impl = {"Z_SAVE_ORDER": save_order, "Z_POST_STOCK": post_stock}

db = {}
print("LUW 1:"); l = SapLuw(db); l.call_in_update_task("Z_SAVE_ORDER", 1, 500); l.call_in_update_task("Z_POST_STOCK", "PEN", 3)
print("  database before COMMIT:", db); l.commit_work(); print("  database after COMMIT :", db)
print("LUW 2:"); l.call_in_update_task("Z_SAVE_ORDER", 2, 900); l.call_in_update_task("Z_POST_STOCK", "PEN", 50); l.commit_work(); print("  database:", db)

Exclusive and shared locks (simulation in Python, not ABAP: run for real)
# Simulation of SAP lock objects (the enqueue server's lock table).
# ENQUEUE_EZ_ORDER locks a key; another user who asks for the same key gets sy-subrc = 1 (FOREIGN_LOCK).
# Mode E (exclusive) blocks everyone else; mode S (shared) allows other S locks but no E lock.
locks = {}   # key -> list of (user, mode)
def enqueue(user, key, mode="E"):
    held = [(u, m) for u, m in locks.get(key, []) if u != user]
    if held and (mode == "E" or any(m == "E" for _, m in held)):
        return f"sy-subrc = 1 FOREIGN_LOCK: {key} is locked by {held[0][0]} (mode {held[0][1]})"
    locks.setdefault(key, []).append((user, mode)); return f"sy-subrc = 0 locked {key} for {user} (mode {mode})"
def dequeue(user, key):
    locks[key] = [(u, m) for u, m in locks.get(key, []) if u != user]; return f"{user} released {key}"
print(enqueue("ASHA", "ORDER 4711"))
print(enqueue("RAVI", "ORDER 4711"))             # Ravi must wait or show a message
print(enqueue("RAVI", "ORDER 4712"))             # different key: no conflict
print(dequeue("ASHA", "ORDER 4711"))
print(enqueue("RAVI", "ORDER 4711"))
print(enqueue("MEERA", "MATERIAL PEN", "S")); print(enqueue("JOHN", "MATERIAL PEN", "S")); print(enqueue("ASHA", "MATERIAL PEN", "E"))
print("Note: locks are logical (SAP-level), separate from database row locks; they are released at")
print("DEQUEUE, at the end of the program, or (with _SCOPE = 2) by the update task after COMMIT WORK.")

# Simulation of a RAP managed business object 'Travel' with draft:
# determination (set status, compute total), validation (dates), action acceptTravel, and the save sequence.
from datetime import date
class TravelBO:
    def __init__(self): self.active, self.draft, self.next_id = {}, {}, 1
    def create(self, **f):                                     # MODIFY ENTITIES ... CREATE (draft)
        tid = self.next_id; self.next_id += 1
        self.draft[tid] = dict(f, status="O", total=0); self.determine_total(tid)
        print(f"  CREATE draft {tid}: status O (open) set by determination"); return tid
    def update(self, tid, **f): self.draft[tid].update(f); self.determine_total(tid)
    def determine_total(self, tid):                            # determination on modify
        t = self.draft[tid]; t["total"] = t.get("booking_fee", 0) + sum(t.get("flights", []))
    def validate_dates(self, tid):                             # validation on save
        t = self.draft[tid]
        if t["end"] < t["begin"]: return f"END DATE {t['end']} BEFORE BEGIN {t['begin']}"
        if t["begin"] < date(2026, 11, 19): return "BEGIN DATE IN THE PAST"
    def accept(self, tid):                                     # action acceptTravel result [1] $self
        self.draft[tid]["status"] = "A"; print(f"  ACTION acceptTravel on {tid}: status A")
    def activate(self, tid):                                   # draft -> save sequence
        err = self.validate_dates(tid)
        if err: print(f"  SAVE {tid} rejected: failed/reported = '{err}' (draft kept, user can fix)"); return
        self.active[tid] = self.draft.pop(tid); a = self.active[tid]; print(f"  SAVE {tid}: finalize -> check_before_save -> save: ACTIVE  begin {a['begin']} end {a['end']} status {a['status']} total {a['total']}")

71 Step 5: Reading the Data Fast

Picture: Shopping with one list instead of running to the shop for every item: one SELECT with joins for orders, then one grouped SELECT each for deliveries and invoices.
get_data( ): joins, grouped FOR ALL ENTRIES, hashed lookups (ABAP template, not run)
METHOD get_data.
  " 1) Orders + customer + item totals in ONE statement (no SELECT inside a LOOP)
  SELECT FROM vbak AS k
    INNER JOIN vbap AS p ON p~vbeln = k~vbeln
    INNER JOIN kna1 AS c ON c~kunnr = k~kunnr
    FIELDS k~vkorg, k~vbeln, k~auart, k~kunnr, c~name1, k~erdat, k~vdatu, k~waerk,
           SUM( p~kwmeng ) AS ordered,
           SUM( p~netwr )  AS netwr
    WHERE k~vkorg IN @s_vkorg
      AND k~kunnr IN @s_kunnr
      AND k~erdat IN @s_erdat
      AND k~auart IN @s_auart
    GROUP BY k~vkorg, k~vbeln, k~auart, k~kunnr, c~name1, k~erdat, k~vdatu, k~waerk
    INTO CORRESPONDING FIELDS OF TABLE @mt_out.

  IF mt_out IS INITIAL.                         " guard BEFORE using FOR ALL ENTRIES
    MESSAGE s002(zsd_mon) DISPLAY LIKE 'W'.       " 'No orders found'
    RETURN.
  ENDIF.

  " 2) Delivered quantities: delivery items refer to the order (VGBEL = order number)
  SELECT FROM lips FIELDS vgbel, SUM( lfimg ) AS delivered
    FOR ALL ENTRIES IN @mt_out WHERE vgbel = @mt_out-vbeln
    GROUP BY vgbel
    INTO TABLE @DATA(lt_dlv).

  " 3) Billed quantities: billing items refer to the order (AUBEL)
  SELECT FROM vbrp FIELDS aubel, SUM( fkimg ) AS billed
    FOR ALL ENTRIES IN @mt_out WHERE aubel = @mt_out-vbeln
    GROUP BY aubel
    INTO TABLE @DATA(lt_bil).

  " 4) Put them into the output lines with fast hashed lookups
  DATA lt_dlv_h TYPE HASHED TABLE OF ty_qty WITH UNIQUE KEY doc.
  DATA lt_bil_h TYPE HASHED TABLE OF ty_qty WITH UNIQUE KEY doc.
  lt_dlv_h = VALUE #( FOR d IN lt_dlv ( doc = d-vgbel qty = d-delivered ) ).
  lt_bil_h = VALUE #( FOR b IN lt_bil ( doc = b-aubel qty = b-billed ) ).
  LOOP AT mt_out ASSIGNING FIELD-SYMBOL(<ls_out>).
    <ls_out>-delivered = VALUE #( lt_dlv_h[ doc = <ls_out>-vbeln ]-qty OPTIONAL ).
    <ls_out>-billed    = VALUE #( lt_bil_h[ doc = <ls_out>-vbeln ]-qty OPTIONAL ).
  ENDLOOP.
ENDMETHOD.
" Note (hedged): in S/4HANA the order already carries status fields in VBAK/VBAP (the old status
" tables VBUK/VBUP were merged into them), and the document flow is in VBFA. Many real monitors read
" those status fields or a released CDS view instead of summing LIPS/VBRP. Check your system.

Good to know

  • Only 3 database calls, whatever the number of orders: no SELECT inside the LOOP (see the measured simulation).
  • The empty-table guard before FOR ALL ENTRIES prevents the 'read the whole table' trap (see here).
  • Totals are computed by the database (SUM ... GROUP BY): code pushdown.
  • Hashed tables make the final matching O(1) per order.

lcl_status: A/B/C status and the traffic light (ABAP template, not run)
" The business rules live in their own small class, so they can be unit-tested without a database
CLASS lcl_status DEFINITION FINAL.
  PUBLIC SECTION.
    CLASS-METHODS doc_status IMPORTING iv_done TYPE p iv_total TYPE p
                             RETURNING VALUE(rv_status) TYPE char1.
    CLASS-METHODS traffic_light IMPORTING iv_dlv_stat TYPE char1 iv_bil_stat TYPE char1
                                          iv_due TYPE d iv_today TYPE d iv_warn_days TYPE i
                                EXPORTING ev_light TYPE char1 ev_note TYPE char30 ev_days_late TYPE i.
ENDCLASS.

CLASS lcl_status IMPLEMENTATION.
  METHOD doc_status.
    rv_status = COND #( WHEN iv_done = 0       THEN 'A'      " not yet processed
                        WHEN iv_done >= iv_total THEN 'C'    " completely processed
                        ELSE 'B' ).                          " partly processed
  ENDMETHOD.

  METHOD traffic_light.
    DATA(lv_days_left) = CONV i( iv_due - iv_today ).
    ev_days_late = COND #( WHEN lv_days_left < 0 THEN - lv_days_left ELSE 0 ).
    IF iv_dlv_stat <> 'C' AND lv_days_left < 0.
      ev_light = '1'. ev_note = |LATE { ev_days_late } d|.            " red
    ELSEIF iv_dlv_stat <> 'C' AND lv_days_left <= iv_warn_days.
      ev_light = '2'. ev_note = |due in { lv_days_left } d|.          " yellow
    ELSEIF iv_dlv_stat = 'C' AND iv_bil_stat <> 'C'.
      ev_light = '2'. ev_note = 'not billed'.                          " yellow
    ELSE.
      ev_light = '3'. ev_note = 'OK'.                                  " green
    ENDIF.
  ENDMETHOD.
ENDCLASS.

81 Interview Questions and Answers (Easy → Hard)

Picture: A mock interview: start with names of things, end with 'why' and 'what would you do'.

Basics

QuestionShort answer
What is ABAP and where does it run?SAP's business programming language; it runs on the ABAP application server of an SAP system, not on the client.
Difference between type c and string?c has a fixed length (padded with spaces); string grows and keeps trailing spaces.
Why type p for money?Exact decimal arithmetic with commercial rounding; float cannot represent 0.10 exactly.
What is sy-subrc?Return code of the last statement; 0 means success.
Client-specific vs cross-client?Client-specific tables have MANDT/CLIENT as first key; ABAP code and cross-client customizing are shared by all clients.

Internal tables and SQL

QuestionShort answer
Standard vs sorted vs hashed table?Linear / binary / hash access; hashed needs a unique full key; sorted keeps order.
What is BINARY SEARCH and its trap?Binary search on a standard table; wrong results if the table is not sorted by the same key.
Two traps of FOR ALL ENTRIES?Empty driver selects everything; duplicates are removed (select the full key).
How do you find SELECT in a loop?ST05 SQL trace (identical selects), SAT, ATC performance checks.
What is code pushdown?Moving data-intensive logic into the database (SQL, CDS, AMDP), important on SAP HANA.

Objects, transactions, architecture

QuestionShort answer
Static vs instance method?Static belongs to the class (=>), instance to an object (->).
CX_STATIC_CHECK vs CX_DYNAMIC_CHECK vs CX_NO_CHECK?Must be declared/handled / checked at runtime only / never declared.
What is the SAP LUW? Why the update task?A business transaction across several dialog steps; updates are registered and executed together at COMMIT WORK, all or nothing.
How do SAP locks work?Logical locks in the enqueue server's lock table (ENQUEUE/DEQUEUE), respected by cooperating programs; see SM12.
BAPI vs direct table update?BAPI runs SAP's checks and follow-up logic; direct updates of standard tables are forbidden.

Modern ABAP

QuestionShort answer
What is a CDS association?A declared relationship; turned into a join only when a consumer uses its path.
Managed vs unmanaged RAP?Framework saves vs your own save code (for existing logic).
Determination vs validation?Determination computes values; validation checks and can reject the save.
What is clean core?Extending SAP only through released APIs and extension points so upgrades do not break custom code.
Classic ABAP vs ABAP Cloud?Full language vs restricted, upgrade-safe subset using released APIs, ADT only, Fiori UIs.
How would you migrate a custom report to S/4HANA?Run ATC S/4HANA readiness checks, fix simplification-item findings (changed tables like MATDOC/ACDOCA, field lengths like 40-char material number), retest, then consider rewriting with CDS/ABAP Cloud.

1. Which table kind gives constant-time reads by a unique key?

HASHED.

2. What happens with FOR ALL ENTRIES IN an empty table?

The WHERE condition is ignored: all rows are read.

Packed decimal (p) / DDIC CURR with a currency key.

4. What does COMMIT WORK do with functions called IN UPDATE TASK?

Runs them together in the update work process, as one all-or-nothing unit.

5. Which transaction shows short dumps?

ST22.

6. In RAP, which element checks data and can reject the save?

A validation.

7. Which statement makes a handler react to an event?

SET HANDLER.

8. What is the value of a date variable before assignment?

'00000000' (initial), not NULL.

9. Why should you not update SAP standard tables directly?

You skip SAP's checks, change documents and follow-up postings; use BAPIs / released APIs.

10. What does 'clean core' mean?

Extend SAP only via released APIs and extension points so upgrades are safe.
